测试数据准备

代号准备内容
SA超级管理员账号
O1 / O2O1：平台根组织（各业务都开通）；O2：只开通门店经营 STORE_MGMT，不开通商城 MALL_MGMT
X / YX =「门店经营管理」commerce.store.manage（STORE_MGMT）；Y =「商城上架管理」commerce.mall.manage（MALL_MGMT）
B1 / B2B1：一个按钮原子，测试时在关联管理里让它同时属于 X 和 Y；B2：只属于 X 的按钮原子
R1 / RX / RYR1：全局岗位，按用例要求勾能力；RX：只勾 X；RY：只勾 Y
U1 / U2 / U3 / U4U1：在 O1、O2 都有岗位的非超管；U2：只在 O2 的非超管；U3：用于离线场景；U4：某仓库的作业成员（资源岗位）
  • 用非超管账号验证权限。超级管理员不受任何权限限制，用它测不出漏配。
  • 「立即生效」指对方不重新登录，下一次点击或刷新即按新权限。
  • 日志在 system-core：重建看 权限包定向重建完成，按钮被拦看 SUPPRESSED_BY_CAPABILITY，组织边界看 SUPPRESSED_BY_ORG_BOUNDARY。
  • 组织能力开关暂无页面，用接口 POST /system-core/v1/org-capability/toggle（参数 orgId、capabilityCode、enabled）。
  • 标记的执行结果只保存在你自己的浏览器里，不会同步给其他人；最终结果请登记到禅道。
