## 1. 需求描述

### 1.1 RBT-移动端 · 门店端

本能力是**丰银宝门店端中的一个菜单**，不是独立 App。仅当门店已在 RBT「门店管理」完成准入（且启用）后，该门店账号登录丰银宝门店端时才可见、可进入本菜单；未准入或已禁用的门店不展示该菜单。

原型页面：`RBT/rbt_h5_store.html`（原型以手机框演示丰银宝内该菜单页）。

进入菜单后，门店账号可查看本店需求、发布需求；发布流程为选择商品包 → 勾选商品 → 选择结算方案 → 发布。需求数据与 B 端「需求单管理」共用，额度与「门店管理」联动。

### 1.2 逻辑说明

#### 1.2.1 进入与切换门店

* 入口：丰银宝门店端 → 本菜单（菜单名以产品最终命名为准；原型侧栏演示为「门店端」）
* **可见条件**：当前登录门店已在 RBT 准入且状态为启用；未准入、未启用则丰银宝门店端不出现该菜单
* 进入后即使用当前丰银宝登录门店身份，先进入门店首页；无需再做独立 RBT 登录
* 原型为方便验收：打开页可恢复本会话已选门店，或进入「选择门店」在多个已准入启用门店间切换；正式环境以丰银宝当前登录门店为准，不另设选店页
* 账号口径与丰银宝门店端一致（联系人 / 法人等）；禁用门店不可进入本菜单
* 演示默认密码等仅为原型约定，正式以丰银宝账号体系为准

#### 1.2.2 首页

进入门店后默认「首页」，样式对齐丰银宝门店首页：顶栏为门店头像和名称，其下为「扫码核销」「售后」，白卡片「基础工具」内为四列图标菜单（门店会员码、直播推广、客户订单、收货、进货、门店钱包、经营中心、库存查询、售后、商户进件、RBT）。除「RBT」外仅展示、不可点击。点击「RBT」进入该店需求列表，列表可返回首页。

#### 1.2.3 需求列表

只展示**需求门店为当前门店**的需求，不限状态。与当前门店无关的需求不出现。

每条卡片展示：

* 需求单号
* 状态
* 商品包（名称 + 编码）
* 商品（名称×数量，多个用顿号）
* 商品金额、服务费、总金额
* 结算周期、结算方式
* 结算比例：仅初审维护后出现；发布时不写、卡片不展示
* 创建时间
* 「取消」：仅「待审核」可取消，且仅需求门店可取消；待审核之后不展示取消入口
* 「去签署」：状态为「待签署」时展示。需求门店确认销售合同。采购合同由贸易商与冷丰供应链签署，需求门店不能代签

列表底部固定「发布需求」。

空列表文案：暂无需求。

#### 1.2.4 需求状态

主链路：

待审核 → 待接单 → 待确认签约 → 待签署 → 待复核 → 支付中 → 已完成

旁路：

* 已作废：门店在待审核取消，或平台在支付中之前作废
* 已驳回：B 端驳回（门店端只读展示）

说明：

* 进行中（占用额度未释放）：待审核、待接单、待确认签约、待签署、待复核、支付中
* 可取消：仅待审核。待审核之后没有取消入口
* 「待接单」由贸易商接单后进入「待确认签约」；确认签约后才进入「待签署」并生成合同
* 待签署及之后可关联合同（见 B 端需求单详情）；门店端列表不展示合同
* 历史状态迁移（演示兼容）：已发布/待报价 → 待审核；已报价 → 待接单；待还款 → 支付中；已取消 → 已作废

#### 1.2.5 发布需求 · 前置条件

点击「发布需求」或进入结算后点击「发布」前，须满足：

* 当前门店**可用额度 > 0**，否则提示「可用额度不足，无法发布需求」
* 不限制「同时仅一条有效需求」：只要可用额度足够，可继续发布

可用额度口径与门店管理一致：

* 可用额度 = 门店总额度 − 已占用（已成交不扣减可用）

#### 1.2.6 选择商品包

* 只展示已关联当前登录门店、且**启用**的商品包。关联关系在商品包上多选维护，按门店编码匹配
* 未关联当前门店，或已禁用的商品包不出现
* 无数据时：暂无本门店的商品包
* 点选一个商品包进入勾选商品页

#### 1.2.7 勾选商品

**商品**

* 展示商品包内 SKU：图片、名称、条码、单位、规格、单价
* 支持全选 / 单选；勾选后可改数量，数量范围 1～999
* 底部汇总：已选几种、共几件、需求金额（= 各勾选商品 售价×数量 之和，未乘结算系数）
* 汇总下方直接是「下一步」

**下一步校验**

* 未选商品 → 「请勾选商品」
* 商品包未关联任何启用中的产品配置 → 「商品未关联产品配置」
* 所选商品售价合计不落在任一适用产品的货款区间内 → 「售价不在产品配置的货款区间内」
* 通过后进入「结算」页

#### 1.2.8 结算

页面标题为「结算」。仅展示同时满足以下条件的产品配置（启用中）：

1. 适用商品包包含当前商品包（按名称或编码匹配）
2. 商品售价合计落在该产品货款区间内

在匹配结果内，用户依次选择：

* **结算周期**：当前原型可选「日结」；有多个周期时按配置出现
* **结算方式**：比例付

本页不展示结算比例。发布成功后也不写入结算比例，结算比例只在初审通过时按本单维护。

**金额展示**

页面自上而下先展示金额，再选结算周期、结算方式。

* **商品金额**：所选商品售价合计，保留两位小数。样式弱化
* **服务费**：总金额 − 商品金额，保留两位小数。样式弱化
* **总金额**：商品金额 × 门店结算系数，保留两位小数。门店结算系数取产品配置，无效时按 1。样式突出，金额用主色大字
* 写入需求单的商品金额、服务费、总金额；占用额度和可用额度校验使用总金额

点「发布」时再校验：

* 须已选结算周期、结算方式
* 总金额须 ≤ 当前门店可用额度，否则「总金额须小于等于可用额度」

发布成功：

* 生成需求单号（`XQ` + 五位序号）
* 初始状态：待审核
* 写入商品包、SKU（编码/名称/售价/数量）、商品金额、服务费、总金额、产品编码/名称、结算周期/方式、创建人/创建时间/更新人/更新时间。不写结算比例
* **占用额度**：只给需求门店的「已占用」增加本单总金额
* **同步审核中心**：在「审核中心 → RBT审核 → 需求单审核」新增一条「待审核」记录，供 B 端通过 / 驳回
* 返回需求列表，提示「需求已发布」

#### 1.2.9 取消需求

* 仅待审核可取消
* 取消后状态为「已作废」，并**释放**本单对需求门店的已占用额度
* 待审核之后没有取消入口；若触发取消则提示「当前状态不允许取消」

#### 1.2.10 额度与 B 端联动（门店端视角）

| 动作 | 已占用 | 已成交 | 可用额度 |
| --- | --- | --- | --- |
| 发布需求成功 | 仅需求门店 +总金额 | 不变 | 随已占用减少 |
| 门店取消 / 平台作废 / B 端驳回 / 需求完成 | 对应门店 −总金额（若曾占用） | 完成不因释放而减少已成交 | 随已占用增加 |
| B 端复核通过进入支付中 | 不变 | 仅需求门店 +总金额 | 不变（已成交不扣可用） |

门店端自身不操作复核、驳回、完成；这些在 B 端需求单管理或后续流程中发生，列表状态与额度会随共享数据更新。

#### 1.2.11 数据范围

* 商品包：与 B 端商品包配置同源；无缓存时用演示商品包
* 产品配置：与 B 端产品配置同源；无缓存时用演示分期，并按适用商品包过滤
* 需求：与 B 端需求单管理同源；门店端列表只展示需求门店为当前门店的单据
* 门店与额度：与 B 端门店管理同源

## 2. 界面说明

* 整体为手机框（约 393×851），主色 `#ff7019`
* 顶栏：门店名称 + 当前步骤文案（需求列表 / 选择商品包 / 勾选商品 / 结算）
* 列表页底栏固定「发布需求」；其他步骤隐藏该底栏，用页面内主按钮「下一步」「发布」
* 操作反馈用页面内 Toast

## 3. 非目标

* 门店端不提供审核、接单、复核、支付完成；待签署时需求门店只签署销售合同
* 门店端需求列表不另做合同预览；合同正文在签署页和 B 端需求单详情
* 贸易商端见《贸易商端移动端PRD》
