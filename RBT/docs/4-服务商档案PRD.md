## 1. 需求描述

服务商不在 RBT 侧栏维护，改由业务伙伴下的商家主体准入，并在商家列表中用服务商档案承接。交互对齐贸易商档案：先在所有主体建商家，再在档案里补资料、查询和进件。

贸易商档案只保存贸易商，并通过「绑定服务商」引用本档的服务商名称。贸易商规则见《贸易商档案PRD》。

### 1.1 入口

顶部进入「业务伙伴」。

* 商家主体 / 所有主体：新增按钮最下方增加「新增服务商商家」，排在「新增贸易商商家」之后。
* 商家列表：增加「服务商档案」，排在「贸易商档案」之后。

原型页面：

* 所有主体：`MDM/mdm_party_all.html`
* 服务商档案：`MDM/mdm_archive_provider.html`

本期不包含：

* RBT 侧栏单独的服务商管理菜单。
* 服务商新增、编辑、详情基础信息中的营业执照、经营许可证、牌照类型、业务范围上传和展示。服务商类型在本档维护，不再叫牌照类型。

## 2. 所有主体

列表是门店、供应商、仓库、贸易商、服务商的合并列表。查询条件不变：商家名称、商家状态。商家类型包含「服务商」。

### 2.1 新增服务商商家

点击「新增服务商商家」，打开「添加服务商商家」。字段与新增贸易商商家相同，主体类型不可编辑，固定显示「服务商」。需要短信验证码，不收集登录账号，不选择绑定 BD。

字段：

* 主体名称：必填
* 主体类型：必填，不可编辑，固定显示「服务商」
* 联系人：必填
* 手机号码：必填，11 位，旁有「获取验证码」
* 验证码：必填，6 位数字

保存校验不通过时停留在弹窗，并提示对应文案：请输入主体名称、请输入联系人、请输入手机号码、请输入11位手机号码、请输入6位数字验证码。

保存成功后：

* 所有主体新增一行。商家 ID 前缀 `PRV`，商家类型为「服务商」，绑定 BD、登录账号展示「—」，状态为「开启」，最后操作人为当前用户。手机号按前 3 后 4 脱敏。
* 同步写入一条服务商档案，并提示「已写入服务商档案，正在跳转…」，随后打开服务商档案。
* 这条档案另行生成服务商 ID，前缀也是 `PRV`，如 `PRV20190001`，与所有主体那一行的商家 ID 不是同一个字段。服务商名称、主体名称取主体名称；主体类型为「服务商」；联系人、手机号取本表单；简称未填时取名称前 6 个字；服务商类型先空着，在服务商档案中补；进件状态为「未进件」；服务商状态为「正常」；地址、详细地址为空时展示「—」。创建人、更新人为当前用户。

列表中服务商的禁用确认文案为「确定禁用此服务商吗？」。开启、禁用规则与其他商家相同。

仍留在贸易商档案、主体类型为「服务商」的旧数据，打开贸易商档案时迁入本档。同名已存在则不重复写入。示例包含「冷丰」（商业保理公司）和「宁波海丰商业保理有限公司」（持牌金融机构）。

## 3. 服务商档案

面包屑：业务伙伴 / 资源中心 / 服务商档案。页面结构对齐贸易商档案。没有「绑定服务商」。

### 3.1 查询

条件按以下顺序。可只填一部分。文本为包含匹配；下拉为精确匹配。

* 主体名称
* 服务商类型：全部、商业保理公司、融资租赁公司、持牌金融机构、地方金融组织
* 联系人姓名
* 联系人手机号：可按展示的脱敏号码匹配，也可只输入其中连续数字
* 服务商名称
* 进件状态：全部、未进件、进件中、进件成功、进件失败
* 服务商状态：全部、正常、冻结

「查询」按当前条件刷新。「重置」清空以上条件并恢复全部记录。

### 3.2 列表

列顺序：

* 服务商 ID
* 主体名称
* 主体类型：固定为服务商
* 服务商名称：可点击，当前页打开详情，地址不变
* 服务商简称
* 服务商地址
* 服务商详细地址
* 服务商类型
* 联系人姓名
* 手机号码
* 进件状态
* 服务商状态：正常、冻结
* 创建人
* 创建时间
* 更新人
* 更新时间
* 操作：编辑、去进件

主体名称、服务商名称、简称、地址、详细地址过长时左对齐并省略，悬停可看全文。空值展示「—」。分页默认每页 10 条，与其他档案列表一致。

查询区按钮：重置、查询、「+ 新增服务商」。

本档的服务商名称会提供给贸易商档案的「绑定服务商」。贸易商新增时只能选这里已有的名称。

### 3.3 新增、编辑

新增标题为「新增服务商」，编辑标题为「编辑服务商」。样式对齐贸易商档案的宽表单。不出现营业执照、经营许可证，也没有「绑定服务商」。地址下方有地图定位示意，不单独落库。

字段：

* 主体名称：必填，从已有服务商档案的主体名称中选择。编辑时若当前主体不在选项里，补进下拉并选中
* 主体类型：必填，不可编辑，固定显示「服务商」
* 服务商名称：必填
* 服务商简称：可不填。档案页直接新增且简称空着时，保存后取名称前 6 个字
* 服务商类型：必填。枚举为商业保理公司、融资租赁公司、持牌金融机构、地方金融组织
* 服务商地址：必填，省 / 市 / 区
* 详细地址：必填，最多 200 字
* 手机号码：必填，带「获取验证码」。已脱敏号码（含 `*`）保存时不再校验 11 位；未脱敏时必须是 11 位
* 验证码：必填，6 位数字
* 联系人姓名：必填
* 服务商状态：必填，正常、冻结，默认正常

必填未填时提示对应字段：请选择主体名称、请输入服务商名称、请选择服务商类型、请输入服务商地址、请输入详细地址、请输入手机号码、请输入验证码、请输入联系人姓名。手机号、验证码格式不对时分别提示「请输入11位手机号码」「请输入6位数字验证码」。

保存成功后关闭弹窗并刷新列表。新增写入的进件状态为「未进件」。编辑更新联系人、地址、服务商类型、状态等已改字段，并刷新更新人、更新时间；不改写进件状态。档案页直接新增只写服务商档案，不回写所有主体。

### 3.4 详情

点击服务商名称打开「服务商详情」。页头展示简称，没有简称时用服务商名称；标签带出服务商状态和进件状态。页签为「基础信息」「进件信息」。

基础信息：

* 服务商 ID、主体名称、主体类型、服务商名称、服务商简称
* 服务商地址、服务商详细地址、服务商类型
* 联系人姓名、手机号码
* 进件状态、服务商状态
* 创建人、创建时间、更新人、更新时间

基础信息不展示营业执照、经营许可证、牌照类型、业务范围、绑定服务商。

进件信息对齐贸易商档案：展示已保存的进件资料、进件记录，以及「去进件」「绑定商户号」。未绑定商户号时，商户号按 `HF-` 加服务商 ID 展示。无论是否已有商户号，都可以再次去进件或绑定商户号。进件审核仍在审核中心，本页只发起和保存。审核链路为门店 → BD → 财务 → 汇付。

### 3.5 去进件

列表操作「去进件」与详情进件信息里的「去进件」打开同一套「服务商进件」。同一服务商共用一条进件记录。

带入：服务商简称，无简称时用服务商名称；详细地址；手机号码。

提交后列表和详情的进件状态改为「进件中」。删除或清空进件记录后回到「未进件」。进件结果为成功或失败时，列表标签与档案中的进件状态一起更新。

## 4. 服务商端登录

服务商使用丰银宝贸易商端的同一套登录，不是另一套 App。正式环境使用丰银宝当前登录主体。原型页面 `RBT/rbt_h5_trader.html` 的放行规则与正式一致。

验证码登录和密码登录都要先通过原有账号审核校验，再按服务商档案的「服务商状态」判断：

* 手机号不存在：「该手机号不存在」
* 账号待审核：「账号审核中，暂不可登录」
* 账号未通过审核：「账号未通过审核，无法登录」
* 贸易商档案和服务商档案都对不上：「未在贸易商或服务商档案中，无法登录」
* 状态为「正常」：可以获取验证码并登录
* 状态为「冻结」：提示「该服务商已冻结，无法登录」，不发验证码，不进入端内
* 状态不是「正常」也不是「冻结」：「服务商状态非正常，无法登录」

账号与档案按服务商名称对应，也认主体名称。手机号按前 3 位和后 4 位对应（档案中的号码是脱敏的）。

服务商登录后可以进入首页，但需求大厅两个页签都没有数据，也不能接单。待接单、已接单的空列表仍分别是「暂无待接单需求」「暂无已接单需求」。已登录后若档案被改为非正常，再次打开页面时退出登录。

贸易商状态为正常时才能接单，见《贸易商档案PRD》和《贸易商接单流程PRD》。需求上的服务商在接单时写入，见《整体业务流程图》。
