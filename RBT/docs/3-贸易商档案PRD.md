## 1. 需求描述

贸易商不在 RBT「贸易商管理」中维护，改由业务伙伴下的商家主体准入，并在商家列表中用贸易商档案承接。交互对齐现有供应商：先在所有主体建商家，再在档案里补资料、查询和进件。

服务商单独建档，见《服务商档案PRD》。贸易商只绑定服务商名称，不在本档维护服务商类型。

### 1.1 入口

顶部进入「业务伙伴」。

* 商家主体 / 所有主体：新增按钮最下方增加「新增贸易商商家」，排在「新增仓库商家」之后、「新增服务商商家」之前。
* 商家列表：增加「贸易商档案」，排在「仓库档案」之后、「服务商档案」之前。

原型页面：

* 所有主体：`MDM/mdm_party_all.html`
* 贸易商档案：`MDM/mdm_archive_trader.html`

本期不包含：

* RBT 侧栏「贸易商管理」及其待入驻、已入驻、审核、额度。该菜单和页面已去掉。
* 贸易商新增、编辑、详情基础信息中的营业执照、经营许可证上传和展示。

## 2. 所有主体

列表是门店、供应商、仓库、贸易商、服务商的合并列表。查询条件不变：商家名称、商家状态。商家类型包含「贸易商」。

### 2.1 新增贸易商商家

点击「新增贸易商商家」，打开「添加贸易商商家」。表单对齐新增供应商商家：需要短信验证码，不收集登录账号，不选择绑定 BD。

字段：

* 主体名称：必填
* 主体类型：必填，不可编辑，固定显示「贸易商」
* 联系人：必填
* 手机号码：必填，11 位，旁有「获取验证码」
* 验证码：必填，6 位数字

保存校验不通过时停留在弹窗，并提示对应文案：请输入主体名称、请输入联系人、请输入手机号码、请输入11位手机号码、请输入6位数字验证码。

保存成功后：

* 所有主体新增一行。商家 ID 前缀 `TRD`，商家类型为「贸易商」，绑定 BD、登录账号展示「—」，状态为「开启」，最后操作人为当前用户。手机号按前 3 后 4 脱敏。
* 同步写入一条贸易商档案，并提示「已写入贸易商档案，正在跳转…」，随后打开贸易商档案。
* 这条档案另行生成贸易商 ID，前缀也是 `TRD`，如 `TRD20190001`，与所有主体那一行的商家 ID 不是同一个字段。贸易商名称、主体名称取主体名称；主体类型为「贸易商」；联系人、手机号取本表单；简称未填时取名称前 6 个字；绑定服务商默认「冷丰」；进件状态为「未进件」；贸易商状态为「正常」；地址、详细地址为空时展示「—」。创建人、更新人为当前用户。

列表中贸易商的禁用确认文案为「确定禁用此贸易商吗？」。开启、禁用规则与其他商家相同。

仍留在贸易商档案、主体类型却是「服务商」的旧数据，打开贸易商档案时迁到服务商档案。服务商档案里已有同名记录则不重复写入。

## 3. 贸易商档案

面包屑：业务伙伴 / 资源中心 / 贸易商档案。

### 3.1 查询

条件按以下顺序。可只填一部分。文本为包含匹配；下拉为精确匹配。

* 主体名称
* 主体类型：全部、贸易商
* 绑定服务商：按名称包含匹配
* 联系人姓名
* 联系人手机号：可按展示的脱敏号码匹配，也可只输入其中连续数字
* 贸易商名称
* 进件状态：全部、未进件、进件中、进件成功、进件失败
* 贸易商状态：全部、正常、冻结

「查询」按当前条件刷新。「重置」清空以上条件并恢复全部记录。

### 3.2 列表

列顺序：

* 贸易商 ID
* 主体名称
* 主体类型：固定为贸易商
* 贸易商名称：可点击，当前页打开详情，地址不变
* 贸易商简称
* 贸易商地址
* 贸易商详细地址
* 绑定服务商：展示已绑定的服务商名称。没有时按「冷丰」
* 联系人姓名
* 手机号码
* 进件状态
* 贸易商状态：正常、冻结
* 创建人
* 创建时间
* 更新人
* 更新时间
* 操作：编辑、去进件

主体名称、贸易商名称、简称、地址、详细地址过长时左对齐并省略，悬停可看全文。空值展示「—」。分页默认每页 10 条，与其他档案列表一致。

查询区按钮：重置、查询、「+ 新增贸易商」。

### 3.3 新增、编辑

新增标题为「新增贸易商」，编辑标题为「编辑贸易商」。样式对齐供应商档案的宽表单。不出现营业执照、经营许可证。地址下方有地图定位示意，不单独落库。

字段：

* 主体名称：必填，从已有贸易商档案的主体名称中选择。编辑时若当前主体不在选项里，补进下拉并选中
* 主体类型：必填，不可编辑，固定显示「贸易商」
* 贸易商名称：必填
* 贸易商简称：可不填。档案页直接新增且简称空着时，保存后取名称前 6 个字
* 绑定服务商：必填。新增时若服务商档案里有「冷丰」则默认选中，可改。下拉只含服务商档案中的服务商名称，同名只出现一次
* 贸易商地址：必填，省 / 市 / 区
* 详细地址：必填，最多 200 字
* 手机号码：必填，带「获取验证码」。已脱敏号码（含 `*`）保存时不再校验 11 位；未脱敏时必须是 11 位
* 验证码：必填，6 位数字
* 联系人姓名：必填
* 贸易商状态：必填，正常、冻结，默认正常

必填未填时提示对应字段：请选择主体名称、请输入贸易商名称、请选择绑定服务商、请输入贸易商地址、请输入详细地址、请输入手机号码、请输入验证码、请输入联系人姓名。手机号、验证码格式不对时分别提示「请输入11位手机号码」「请输入6位数字验证码」。

保存成功后关闭弹窗并刷新列表。新增写入的进件状态为「未进件」。编辑更新联系人、地址、绑定服务商、状态等已改字段，并刷新更新人、更新时间；不改写进件状态。档案页直接新增只写贸易商档案，不回写所有主体。

### 3.4 详情

点击贸易商名称打开「贸易商详情」。页头展示简称，没有简称时用贸易商名称；标签带出贸易商状态和进件状态。页签为「基础信息」「进件信息」。

基础信息：

* 贸易商 ID、主体名称、主体类型、贸易商名称、贸易商简称
* 贸易商地址、贸易商详细地址、绑定服务商
* 联系人姓名、手机号码
* 进件状态、贸易商状态
* 创建人、创建时间、更新人、更新时间

基础信息不展示营业执照、经营许可证，也不展示牌照类型、业务范围。

进件信息对齐供应商档案：展示已保存的进件资料、进件记录，以及「去进件」「绑定商户号」。未绑定商户号时，商户号按 `HF-` 加贸易商 ID 展示。无论是否已有商户号，都可以再次去进件或绑定商户号。进件审核仍在审核中心，本页只发起和保存。审核链路为门店 → BD → 财务 → 汇付。

### 3.5 去进件

列表操作「去进件」与详情进件信息里的「去进件」打开同一套「贸易商进件」。同一贸易商共用一条进件记录。

带入：贸易商简称，无简称时用贸易商名称；详细地址；手机号码。

提交后列表和详情的进件状态改为「进件中」。删除或清空进件记录后回到「未进件」。进件结果为成功或失败时，列表标签与档案中的进件状态一起更新。

## 4. 贸易商端登录

贸易商端是丰银宝贸易商端中的一个模块，不是独立 App。正式环境使用丰银宝当前登录贸易商。原型页面 `RBT/rbt_h5_trader.html` 用下面的登录做验收，放行规则与正式一致。

验证码登录和密码登录都要先通过原有账号审核校验，再按贸易商档案的「贸易商状态」判断：

* 手机号不存在：「该手机号不存在」
* 账号待审核：「账号审核中，暂不可登录」
* 账号未通过审核：「账号未通过审核，无法登录」
* 贸易商档案和服务商档案都对不上：「未在贸易商或服务商档案中，无法登录」
* 状态为「正常」：可以获取验证码并登录
* 状态为「冻结」：提示「该贸易商已冻结，无法登录」，不发验证码，不进入端内
* 状态不是「正常」也不是「冻结」：「贸易商状态非正常，无法登录」

可登录账号列表只展示档案状态为正常、且账号审核已通过的贸易商。已登录后若档案被改为非正常，再次打开页面时退出登录。

账号与档案按贸易商名称对应，也认主体名称。手机号按前 3 位和后 4 位对应（档案中的号码是脱敏的）。名称和手机号都能对上时用这一条；只有一条档案的手机号能对上时也用这一条。

状态为「正常」的贸易商登录后，可看全部待接单和自己已接单的需求。接单时，把本档「绑定服务商」写入该需求单。接单、确认签约见《贸易商接单流程PRD》。服务商账号的登录和不能接单，见《服务商档案PRD》。
