## 1. 需求描述

### 1.1 审核中心新增 RBT审核

顶部导航「审核中心」下，侧栏新增一级菜单「RBT审核」，其下二级菜单「需求单审核」。

原型页面：`MDM/mdm_audit_rbt_demand.html`

与「需求单管理」（RBT 模块）共用需求数据：门店端发布成功后，需求单管理出现「待审核」单据，同时本页新增一条初审记录。贸易商支付完成后需求直接进入门店付款中，本页不再生成复核。

### 1.2 逻辑说明

#### 1.2.1 产生审核记录

* 触发：门店端发布需求成功
* 效果：
  * RBT「需求单管理」新增状态为「待审核」的需求单
  * 审核中心「需求单审核」新增一条「初审」、状态为「待审核」的审核单
  * 需求单管理里「初审自动审核」为「是」（默认）时，这条初审立刻由系统审核通过，需求变为「待接单」，审核人记「系统」。为「否」时停在待审核，等人工审核
* 历史已有需求单在进入本页时按状态补齐初审记录（演示同步）。历史上的复核记录不再展示

#### 1.2.1a 需求单管理快捷入口

* RBT「需求单管理」操作列固定显示「审核」，仅「待审核」可点，其余状态置灰
* 点击后跳转本页，并按该行需求单号自动带入查询条件；审核状态不默认带值

#### 1.2.2 查询

* 需求单号（可兼匹配审核单号）
* 门店（名称或编码，包含匹配）
* 审核状态：全部 / 待审核 / 审核通过 / 审核驳回

支持查询、重置；分页默认每页 20 条。

#### 1.2.3 列表字段

* 审核单号
* 需求单号
* 门店（名称 + 编码）
* 商品包
* 商品金额、服务费、总金额
* 提交人
* 提交时间
* 审核状态
* 审核人
* 审核时间
* 操作：详情；待审核时另有「审核」

#### 1.2.4 审核操作

**审核**

* 仅「待审核」可操作。点击「审核」打开关联需求单详情，底部为「审核通过」「审核驳回」
* 「详情」仍只打开需求单详情，没有这两个按钮
* 驳回原因填在详情底部，点「审核驳回」时必填。未填提示「驳回原因必填」，不驳回

**通过（初审）**

* 不再选择服务商，也不再按本单填写各渠道结算比例
* 各渠道结算比例在发布需求时已按产品配置记到需求单。点「审核通过」只改状态，不重写这份比例
* 确认后：该审核单 → 审核通过；关联需求单状态 → **待接单**
* 待接单到门店付款中，需求单管理可再改这份比例，不改需求状态
* 不释放占用额度

**驳回**

* 仅「待审核」可操作。在需求单详情底部填写驳回原因后点「审核驳回」
* 须填写驳回原因
* 确认后：当前这条审核单 → 审核驳回；关联需求单状态 → **已驳回**
* 释放该需求对需求门店的已占用额度

**详情**

* 打开关联需求单详情（与需求单管理详情一致）
* 需求单详情「保证金缴纳凭证」展示该需求门店在准入里的缴纳状态和凭证。选「否」或还没配置时不展示文件

#### 1.2.5 状态联动

| 来源 | 审核单状态 |
| --- | --- |
| 门店刚发布 / 需求仍为待审核 | 待审核 |
| 初审通过 / 需求已进入待接单及之后。渠道比例在发布时已经记到需求单 | 审核通过 |
| 本页驳回 / 需求为已驳回 | 审核驳回 |
| 门店取消（仅待审核） | 审核驳回，意见「需求已作废」 |
| 平台作废需求，初审仍待审核 | 审核驳回，意见「需求已作废」 |
| 平台作废需求，初审已经审核通过 | 保持审核通过 |

## 2. 菜单结构

审核中心侧栏（自上而下）：

* 审核中心：入驻审核、进件审核
* 营销审核：优惠券、现金红包、派发红包
* **RBT审核：需求单审核**
