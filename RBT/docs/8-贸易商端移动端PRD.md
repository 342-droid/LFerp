## 1. 需求描述

### 1.1 RBT-移动端 · 贸易商端

本能力是**丰银宝贸易商端中的一个模块**，不是独立 App，也不是丰银宝门店端里的菜单。仅当贸易商档案状态为「正常」时，该贸易商登录丰银宝贸易商端后才可见、可进入；冻结或档案中不存在的贸易商不展示该模块。

原型页面：`RBT/rbt_h5_trader.html`（原型以手机框演示丰银宝贸易商端内该模块）。

进入模块后，贸易商可在需求大厅接单、签署合同。身份来自贸易商档案。需求数据与 B 端「需求单管理」、门店端发布共用。贸易商不改门店额度。

登录是否放行以《贸易商档案PRD》第 4 节为准。正式环境使用丰银宝当前登录贸易商，不另做一套账号。

### 1.2 逻辑说明

#### 1.2.1 进入

* 入口：丰银宝贸易商端 → 本模块（模块名以产品最终命名为准；进入后首页菜单为「需求大厅」）
* **可见条件**：当前登录贸易商在贸易商档案中的状态为「正常」；冻结、未建档或不为正常时，丰银宝贸易商端不出现该模块
* 进入后使用丰银宝当前登录贸易商，先到首页
* 原型为方便验收，页内另有验证码登录和密码登录，通过后进入同一首页。正式环境不保留这套独立登录

原型登录规则（与正式放行一致）：

* 支持「验证码登录」「密码登录」，可切换
* 手机号须为 11 位。验证码须先获取再填写；60 秒内不可重复获取
* 先校验账号审核状态，再校验贸易商档案状态：
  * 手机号不存在：「该手机号不存在」
  * 账号待审核：「账号审核中，暂不可登录」
  * 账号未通过审核：「账号未通过审核，无法登录」
  * 档案中没有对应贸易商：「未在贸易商档案中，无法登录」
  * 档案状态为冻结：「该贸易商已冻结，无法登录」，不发验证码
  * 档案状态不是「正常」：「贸易商状态非正常，无法登录」
  * 档案状态为「正常」：可以获取验证码或使用密码登录
* 账号与档案按贸易商名称对应；手机号按前 3 位和后 4 位对应（档案号码脱敏）
* 密码错误：「密码错误」。验证码未获取、为空、错误时分别提示「请先获取验证码」「请输入验证码」「验证码错误」
* 登录成功进入首页。已进入后若档案变为非正常，再次打开页面时退出并提示原因
* 原型在登录区列出当前可登录账号，点击填入手机号。演示验证码、默认密码仅为原型约定，正式以贸易商账号体系为准

登录后的贸易商名称取执照名称，接单、已接单过滤、合同签署都用这个名称。

#### 1.2.2 首页

进入模块后默认首页。顶栏为贸易商名称（头像取名称首字），右侧铃铛、齿轮仅展示，不可点击。

其下白卡片「基础工具」，当前只有一个菜单「需求大厅」，点击进入需求大厅。

没有扫码核销、售后，也没有底部入口栏。首页不显示橙色原型顶栏。

#### 1.2.3 需求大厅

从首页进入时默认「待接单」页签。两个页签可切换，每个页签上的数字是该页签自己的条数，没有数据时也显示 0。

谁能看见需求：发布需求的门店只看自己发布的需求；主体类型为「贸易商」的账号看全部待接单，以及自己已接单的需求。主体类型为「服务商」的账号登录后，两个页签都没有数据，空列表仍用「暂无待接单需求」「暂无已接单需求」。

**待接单**

* 只对主体类型为「贸易商」的账号展示状态为「待接单」且尚未写入接单贸易商的需求
* 按创建时间从新到旧
* 空列表：「暂无待接单需求」
* 每条有「接单」

**已接单**

* 只对主体类型为「贸易商」的账号展示接单贸易商名称等于当前登录贸易商的需求，不限之后变成什么状态
* 其他贸易商接走的需求不出现
* 按接单时间从新到旧
* 空列表：「暂无已接单需求」
* 展示接单后的需求状态和接单时间
* 「待确认签约」显示「确认签约」和「撤回接单」
* 状态为「待签署」时显示「去签署」
* 状态为「待付款」时显示「在线支付」和「线下支付」

卡片字段：

* 需求单号、状态
* 门店（需求门店名称）
* 商品包（名称 + 编码）
* 商品（名称×数量，多个用顿号）
* 商品金额：所选商品售价合计
* 总金额：等于该需求单的贸易商应收，即商品金额 × 产品配置的贸易商结算系数
* 服务费：总金额 − 商品金额
* 有结算周期时：结算周期、结算方式；结算比例仅在初审已维护时展示
* 创建时间
* 已接单页签另展示接单时间

从大厅返回回到首页。

#### 1.2.4 接单

* 仅主体类型为「贸易商」、且需求为「待接单」、还没有接单贸易商时可接。主体类型为「服务商」不能接单，提示「服务商不能接单」
* 点击后确认：「确认接单「需求单号」？一笔需求单只能由一个贸易商接单。」取消则不接
* 确认成功：需求状态变为「待确认签约」，写入接单贸易商名称、手机号、接单时间，不生成合同；提示「接单成功」
* 待确认签约点「确认签约」：状态变为「待签署」，生成销售合同和采购合同，之后才可去签署
* 待确认签约点「撤回接单」：清空接单贸易商，需求变为「待重新确认」。此时不回到「待接单」，其他贸易商不能接。需平台在需求单管理重新发布后，才回到「待接单」并可再接；平台也可作废
* 该单从全部可接贸易商的「待接单」消失，只出现在接单贸易商的「已接单」。服务商两边都看不到
* 已被别人接走，或状态已不是待接单：提示「该需求单已被接单」，不覆盖原接单贸易商
* 需求单不存在：「需求单不存在」

一笔需求只允许一个贸易商接单。

#### 1.2.5 合同签署

已接单且状态为「待签署」时，点击「去签署」进入合同签署页，可返回已接单列表。

页面先展示需求摘要：需求单号、需求门店（名称 + 编码）、商品金额、服务费、总金额、结算周期、结算方式、结算比例。

其下两份合同都能查看，贸易商确认与自己有关的两份：

| 合同 | 双方 | 贸易商 |
| --- | --- | --- |
| 销售合同 | 需求门店、接单贸易商 | 确认自己这一方 |
| 采购合同 | 接单贸易商、冷丰供应链 | 确认自己这一方。冷丰供应链不在本端签署 |

* 一份协议上，自己尚未签署且需求仍为「待签署」时，该份显示「确认签署」
* 签署成功且还有其他方未签：「签署成功」。自己已签完、别人未签完时，页上提示「你已签署，待其他方完成签署。」
* 重复签署：「你已签署」
* 销售合同和采购合同的各方都签完后，需求状态变为「待付款」，提示「各方已完成签署，请选择支付方式」。签署页和已接单都可支付
* 「在线支付」直接完成（当前为模拟支付），需求变为「待复核」，提示「支付完成，需求进入待复核」
* 「线下支付」弹出「请进行线下打款，相关信息请联系平台处理」。点「确认」后需求变为「待复核」；点「取消」仍为「待付款」
* 当前不能签：「当前不能签署」
* 各方都完成后，提示「各方已完成签署，需求状态为……」

贸易商不代需求门店或冷丰供应链签署。

#### 1.2.6 需求状态（贸易商端能看到的变化）

主链路：

待审核 → 待接单 → 待确认签约 → 待签署 → 待付款 → 待复核 → 还款中 → 已完成

旁路：待重新确认（撤回接单后，待平台重新发布或作废）、已作废、已驳回。

贸易商端只操作接单和签署：

| 动作 | 需求状态 | 谁能在大厅看到 |
| --- | --- | --- |
| 初审通过 | 待接单 | 主体类型为贸易商的账号可见；服务商不可见 |
| 本贸易商接单 | 待确认签约 | 只在该贸易商的已接单，可确认签约或撤回 |
| 确认签约 | 待签署 | 已接单，显示去签署 |
| 撤回接单 | 待重新确认 | 从已接单消失，也不进待接单。平台重新发布后才回到待接单 |
| 其他贸易商已接 | 待确认签约及之后 | 当前贸易商两边都看不到 |
| 各方签署完成 | 待付款 | 接单贸易商的已接单，可选在线支付或线下支付 |
| 在线支付 / 确认线下支付 | 待复核 | 接单贸易商的已接单，无支付按钮 |
| 复核通过 | 还款中 | 接单贸易商的已接单，只读 |
| 门店取消（仅待审核）或平台作废 | 已作废 | 从待接单消失；若已接则留在该贸易商已接单，无操作按钮 |

贸易商不能审核、驳回、作废、复核，也不能把需求改成还款中或已完成。确认签约前可以撤回自己的接单。这些在门店端或 B 端发生后，已接单列表随共享数据更新。

#### 1.2.7 数据范围

* 需求：与 B 端需求单管理、门店端同源
* 贸易商身份：与贸易商档案同源；名称用于接单和已接单过滤。主体类型为服务商时需求大厅无数据，且不能接单。主体类型为贸易商时看全部待接单和自己已接单的需求。门店只看自己发布的需求
* 合同：与需求单上的销售合同、采购合同同源

## 2. 界面说明

* 手机框约 393×851，主色 `#ff7019`
* 首页隐藏橙色顶栏，使用贸易商名称顶栏
* 需求大厅、合同签署使用橙色顶栏，标题分别为「需求大厅」「合同签署」
* 页签数字为橙色圆角；当前页签上的数字为白底
* 操作反馈用页面内 Toast

## 3. 非目标

* 不提供底部入口栏。资产台账、我的、修改密码、退出登录无入口，本版不作为正式功能
* 首页铃铛、齿轮不可点击
* 不发布需求，不查看担保额度，不上传担保金凭证
* 不代冷丰供应链签署采购合同
* 审核、复核、驳回、取消在审核中心、需求单管理或门店端完成
