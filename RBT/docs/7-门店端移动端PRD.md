## 1. 需求描述

### 1.1 RBT-移动端 · 门店端

本能力是**丰银宝门店端中的一个菜单**，不是独立 App。仅当门店已在 RBT「门店管理」完成准入（且启用）后，该门店账号登录丰银宝门店端时才可见、可进入本菜单；未准入或已禁用的门店不展示该菜单。

原型页面：`RBT/rbt_h5_store.html`（原型以手机框演示丰银宝内该菜单页）。

进入菜单后，门店账号可查看本店需求、发布需求；发布流程为选择商品包 → 勾选商品 → 选择结算方案 → 发布。需求数据与 B 端「需求单管理」共用，额度与「门店管理」联动。

### 1.2 逻辑说明

#### 1.2.1 进入与切换门店

* 入口：丰银宝门店端 → 本菜单（菜单名以产品最终命名为准；原型侧栏演示为「门店端」）
* **可见条件**：当前登录门店已在 RBT 准入且状态为启用；未准入、未启用则丰银宝门店端不出现该菜单
* 进入后即使用当前丰银宝登录门店身份，先进入门店首页；无需再做独立 RBT 登录
* 原型为方便验收：打开页可恢复本会话已选门店，或进入「选择门店」在多个已准入启用门店间切换；正式环境以丰银宝当前登录门店为准，不另设选店页
* 账号口径与丰银宝门店端一致（联系人 / 法人等）；禁用门店不可进入本菜单
* 演示默认密码等仅为原型约定，正式以丰银宝账号体系为准

#### 1.2.2 首页

进入门店后默认「首页」，样式对齐丰银宝门店首页：顶栏为门店头像和名称，其下为「扫码核销」「售后」，白卡片「基础工具」内为四列图标菜单（门店会员码、直播推广、客户订单、收货、进货、门店钱包、经营中心、库存查询、售后、商户进件、RBT）。除「RBT」外仅展示、不可点击。点击「RBT」进入该店需求列表，列表可返回首页。

#### 1.2.3 需求列表

只展示**需求门店为当前门店**的需求，不限状态。与当前门店无关的需求不出现。

页头为白底「需求列表」，左侧返回首页。

每条卡片自上而下：

* 第一行：商品包名称；右侧状态。进行中为橙色浅底标签，已作废、已驳回为灰色，已完成为绿色
* 第二行：需求单号 · 商品包编码
* 商品金额单独一行，左侧「商品金额」，右侧橙色大字。不展示总金额、服务费
* 灰底两格：结算周期、结算方式
* 商品：名称×数量，多个用顿号
* 结算比例：发布成功后按该需求匹配的产品配置写入，卡片即可看到，按渠道写成「POS 完成 8.00%；直播 完成 8.00%」。POS 配了二级渠道时写在括号里，如「POS 完成 10.00%（堂食 8.00%，外卖 12.00%）」。非比例付改为展示结算期数
* 底部左侧创建时间；右侧「取消需求」仅「待审核」且为需求门店时出现。待审核之后不展示取消入口
* 「去签署」：状态为「待签署」时出现在底部右侧。需求门店确认销售合同。采购合同由贸易商与冷丰供应链签署，需求门店不能代签

列表底部固定「发布需求」。

空列表文案：暂无需求。

#### 1.2.4 需求状态

主链路：

待审核 → 待接单 → 待确认签约 → 待签署 → 待付款 → 门店付款中 → 已完成

旁路：

* 已作废：门店在待审核取消，或平台在门店付款中之前作废
* 已驳回：B 端驳回（门店端只读展示）

说明：

* 进行中（占用额度未释放）：待审核、待接单、待确认签约、待重新确认、待签署、待付款、门店付款中
* 可取消：仅待审核。待审核之后没有取消入口
* 「待接单」由贸易商接单后进入「待确认签约」；确认签约后才进入「待签署」并生成合同
* 贸易商撤回接单后为「待重新确认」，门店列表只展示状态，不能取消。平台重新发布后回到「待接单」，作废后为「已作废」
* 待签署及之后可关联合同（见 B 端需求单详情）；门店端列表不展示合同
* 历史状态迁移（演示兼容）：已发布/待报价 → 待审核；已报价 → 待接单；待还款、支付中 → 门店付款中；待支付 → 待付款；已取消 → 已作废

#### 1.2.5 发布需求 · 前置条件

点击「发布需求」或在确认发布页点击「确认发布」前，须满足：

* 当前门店**可用额度 > 0**，否则提示「可用额度不足，无法发布需求」
* 当前门店未结束的需求条数达到准入配置的**需求次数**后，不能再发布，提示「需求次数已达上限，无法发布需求」。未结束不含已作废、已驳回、已完成。需求次数在门店准入维护，默认 1，可修改

可用额度口径与门店管理一致：

* 可用额度 = 门店总额度 − 已占用（已成交不扣减可用）

#### 1.2.6 选择商品包

* 只展示已关联当前登录门店、且**启用**的商品包。关联关系在商品包上多选维护，按门店编码匹配
* 未关联当前门店，或已禁用的商品包不出现
* 无数据时：暂无本门店的商品包
* 点选一个商品包进入勾选商品页

#### 1.2.7 选择商品

**商品**

* 页头白底「选择商品」，左侧返回商品包
* 顶部卡片：商品包名称、商品包编码 · 商品个数
* 每个商品一张卡片：圆形勾选、图片、名称、商品条码、规格（1 + 单位 + 规格，如「1箱 4kg」）、售价。售价为单价，橙色大字
* 数量步进器始终展示。未勾选时数量显示 1，点「+」即按 1 勾选；已勾选后可改到 1～999，减到 0 取消勾选
* 底部固定栏：全选、已选几种共几件、商品金额、「下一步」。商品金额 = 已勾选商品 售价×数量 之和，未乘结算系数，不展示服务费和总金额

**下一步校验**

* 未选商品 → 「请勾选商品」
* 商品包未关联任何启用中的产品配置 → 「商品未关联产品配置」
* 所选商品售价合计不落在任一适用产品的货款区间内 → 「售价不在产品配置的货款区间内」
* 通过后进入「结算」页

#### 1.2.8 确认发布信息

页面标题为「确认发布信息」。进入本页前已选定商品包和商品。仅展示同时满足以下条件的产品配置（启用中）：

1. 适用商品包包含当前商品包（按名称或编码匹配）
2. 商品售价合计落在该产品货款区间内

页面自上而下：

* 商品包卡片：名称、编码 · 商品个数
* 商品金额：所选商品售价合计，橙色大字。不展示服务费、总金额
* 结算周期、结算状态：只有一个可选项时直接展示文案；有多个时仍可点选。结算状态即结算方式
* 非比例付且配置了期数时，另展示结算期数

本页不展示结算比例、服务费和总金额。写入需求单时仍计算服务费和总金额：总金额 = 商品金额 × 门店结算系数，服务费 = 总金额 − 商品金额；门店结算系数取产品配置，无效时按 1。发布成功时，把所匹配产品配置的各渠道结算比例直接记到需求单，不等初审。初审自动审核为「是」时，发布成功后需求直接进入待接单；为「否」时停在待审核。产品上已维护渠道比例就用那份；还没单独维护时，用该产品默认比例补 POS、直播、商城三个渠道。产品上取不到比例时提示「请先在产品配置中维护各渠道结算比例」，不发布。占用额度和可用额度校验仍使用商品金额。

点「确认发布」时再校验：

* 须已选结算周期、结算方式
* 商品金额须 ≤ 当前门店可用额度，否则「商品金额须小于等于可用额度」

发布成功：

* 生成需求单号（`XQ` + 五位序号）
* 初始状态：待审核
* 写入商品包、SKU（编码/名称/售价/数量）、商品金额、服务费、总金额、产品编码/名称、结算周期/方式、创建人/创建时间/更新人/更新时间。不写结算比例
* **占用额度**：只给需求门店的「已占用」增加本单商品金额
* **同步审核中心**：在「审核中心 → RBT审核 → 需求单审核」新增一条「待审核」记录，供 B 端通过 / 驳回
* 返回需求列表，提示「需求已发布」

#### 1.2.9 取消需求

* 仅待审核可取消
* 取消后状态为「已作废」，并**释放**本单对需求门店的已占用额度
* 待审核之后没有取消入口；若触发取消则提示「当前状态不允许取消」

#### 1.2.10 额度与 B 端联动（门店端视角）

| 动作 | 已占用 | 已成交 | 可用额度 |
| --- | --- | --- | --- |
| 发布需求成功 | 仅需求门店 +商品金额 | 不变 | 随已占用减少 |
| 门店取消 / 平台作废 / B 端驳回 / 需求完成 | 对应门店 −商品金额（若曾占用） | 完成不因释放而减少已成交 | 随已占用增加 |
| B 端复核通过进入门店付款中 | 不变 | 仅需求门店 +总金额 | 不变（已成交不扣可用） |

门店端自身不操作复核、驳回、完成；这些在 B 端需求单管理或后续流程中发生，列表状态与额度会随共享数据更新。

#### 1.2.11 数据范围

* 商品包：与 B 端商品包配置同源；无缓存时用演示商品包
* 产品配置：与 B 端产品配置同源；无缓存时用演示分期，并按适用商品包过滤
* 需求：与 B 端需求单管理同源；门店端列表只展示需求门店为当前门店的单据
* 门店与额度：与 B 端门店管理同源

## 2. 界面说明

* 整体为手机框（约 393×851），主色 `#ff7019`
* 顶栏：需求列表、选择商品为白底标题；其余步骤为门店名称
* 列表页底栏固定「发布需求」；选择商品页底栏为全选、商品金额和「下一步」；确认发布页底栏为「确认发布」
* 操作反馈用页面内 Toast

## 3. 非目标

* 门店端不提供审核、接单、复核、支付完成；待签署时需求门店只签署销售合同
* 门店端需求列表不另做合同预览；合同正文在签署页和 B 端需求单详情
* 贸易商端见《贸易商端移动端PRD》
