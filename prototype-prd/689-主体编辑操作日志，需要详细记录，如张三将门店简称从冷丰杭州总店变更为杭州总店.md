# 【689】操作日志

商家主体和供应商档案的「操作日志」为列表级入口，打开后按当前业务模块查询。其他页面沿用原入口和查询对象，共用日志抽屉。

## 查询与展示

1. 抽屉提供「操作类型」「操作结果」及「查询」「重置」。两个条件可组合，查询与重置均回到第一页。
2. 日志默认按操作时间倒序，每页默认 20 条。列表列为操作时间、操作内容、操作人、业务编号、结果及「查看详情」。
3. 点击「查看详情」在列表上方打开居中弹窗。顶部展示结果标签和操作类型，基础信息包括操作时间、操作人、业务编号与操作结果。
   - 新增展示新增明细，未记录的变更前值显示「—」；编辑展示实际变更字段和前后值，例如「门店简称：冷丰杭州总店 → 杭州总店」；启停等操作展示状态变更。
   - 一次操作的全部变更项显示在同一详情中，标题标注数量，变更前用红色、变更后用绿色。失败记录显示已记录的失败原因，缺失时显示「未记录」。
   - 技术信息默认折叠，有数据时展示后台动作标识、来源服务、请求方式、接口路径、客户端 IP、处理耗时、TraceID 及脱敏后的结构化请求参数。
4. 结果支持成功和失败。失败且未生成业务编号时展示「—」。既有记录缺少操作人、结果或前后值时，按已知数据展示，不推测补值。
5. 模块级入口只查询所属模块。原有单对象入口继续按该对象查询。关闭详情后保留列表的筛选和页码。

## 业务对象与操作类型

| 模块 | 本地原型入口 | 查询或记录的操作 |
| --- | --- | --- |
| 商家主体 | 业务伙伴 → 所有主体 → 操作日志 | 门店、供应商、仓库商家统一使用新增、启用、禁用商家主体；新增记录主体类型 |
| 门店档案 | 业务伙伴 → 门店档案 → 操作日志 | 新增、编辑、启用、禁用、设置系统默认门店、调整营业时间 |
| 供应商档案 | 业务伙伴 → 供应商档案 → 操作日志 | 编辑供应商，记录名称、简称及入库仓库的变化 |
| 仓库档案 | 业务伙伴 → 仓库档案 → 操作日志 | 编辑仓库名称、启用、停用 |
| 积分 | 积分规则、积分抵现、消费送积分 | 查询对应规则既有保存、启停等记录 |
| 优惠券 | 优惠券列表、优惠券审核 | 查询对应优惠券既有新增、编辑、启停和审核等记录 |
| 营销 | 营销模板、秒杀活动、红包模板 | 查询对应模板或活动的既有记录，操作类型按各业务日志中的实际动作展示 |
| 审核 | 红包模板审核、手动红包审核 | 使用审核简表查询对应记录，展示动作、操作人、说明和结果 |
| 订单 | 零售、代采、直播订单详情 | 保留详情时间线，新增共用查询入口。使用订单已有日志、业务编号和已记录的核销人 |
| 结算 | 通用配置、结算策略 | 查询各自已有的配置或策略变更记录 |
| 选品库 | 商品 → 选品库 → 操作日志 | 新增、修改、商品上架、商品下架、审核及删除等，按商品编码关联 |
| 商品类目 | 商品 → 商品类目 → 操作日志 | 与商城类目共用「商品分类」日志。当前本页原型只有查询入口，暂无独立保存表单 |
| 商城类目 | 商城商品 → 商城类目 → 操作日志 | 新增分类、修改分类、删除分类。上下架在修改分类详情中展示状态前后值，按类目 ID 关联 |

## 营销日志样式

营销模板、优惠券、秒杀及红包等使用单对象日志抽屉，标题为「操作日志 · 对象名称」。列表按时间倒序，展示操作时间、操作内容、操作人、方法、结果、查看详情。方法展示实际请求方式与接口路径。详情顶部展示结果、动作和已记录的 TraceID，基础表展示查询对象、客户端 IP、来源服务和耗时，变更表下直接展示脱敏请求参数。

例如「自动领取福袋」的创建模板、启用模板、禁用模板分别可显示已记录的 POST /marketing-core/v1/activity/create、POST /marketing-core/v1/activity/activate、POST /marketing-core/v1/activity/pause。禁用模板的状态为「启用 → 禁用」，请求参数展示模板 ID。没有请求信息的历史日志对应单元格显示「—」。

分页默认 20 条，可选 20、50、100、200 条/页，支持页码、上一页、下一页和「前往」跳页。空列表显示「暂无数据」，总数仍显示 0 条。详情统一使用「变更明细（共 X 个字段）」及「字段 / 变更前 / 变更后」。实际启用模板记录可为「草稿 → 启用」，以日志保存的状态为准。

## 商品日志详情

商品主档与商品分类使用紧凑的详情弹窗。基础信息为两行四列，技术信息在分隔线下方展开，箭头位于右侧。没有字段差异时在变更明细区居中展示「无字段级变更」。有实际差异时显示前后值。新增商品、修改商品的演示记录可查看结构化请求示例；历史记录按自身已有的技术字段展示。

## 原型验收数据

打开日志时，对页面已定义及已有记录中的操作类型检查结果覆盖情况。常规日志缺少「成功」或「失败」时补齐该组合，审核简表补齐「通过」或「驳回」。演示行标记「演示」，操作人为「演示用户」，常规日志可以按类型及结果筛选并查看详情。成功样例展示业务前后值或摘要，失败样例展示原因。真实记录排在演示行之前；演示数据在打开时生成，仅用于预览。

## 记录口径

- 新增的主数据原型记录包含业务对象、编号、发生时间、操作类型、操作人、结果及已知的变更字段。已登录操作人的正式身份由服务端记录。本地原型使用页面当前用户信息。
- 本地原型在成功执行时新增记录。取消、无字段变化的保存以及仅查看不产生编辑日志。既有模块产生的失败记录照常查询。
- 主体资料编辑、进件及更多档案字段按各业务保存操作记录。业务变更与审计事件应同时落库，并保留业务失败原因。
- 密码、验证码等敏感字段不写入新增日志。

## 验收

- 从所有主体、门店档案、供应商档案、仓库档案列表均能打开对应日志，且各模块记录相互隔离。
- 门店简称变更保存后，详情可见操作人和前后值。多字段同一次保存只生成一条日志。
- 用任一存在成功及失败记录的既有模块组合查询操作类型与结果，点击重置后恢复全部记录。
- 历史日志仅有摘要时仍可查看摘要，缺失字段按「—」或空态显示。
- 记录超过 20 条时可翻页。查看详情再返回时，列表仍保留原筛选和页码。
