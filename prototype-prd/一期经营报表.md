# 一期经营报表

| 项目 | 内容 |
|---|---|
| 适用端 | 门店 APP、BD APP、平台 PC、供应商 APP |
| 文档状态 | 重写稿，供需求评审与研发验收使用 |
| 更新日期 | 2026-11-20 |
| 编写依据 | 当前原型页面、实际交互及配套取数逻辑；字段名称按页面展示 |

## 1. 需求目标与角色范围

店长查看本店零售、进货、佣金及购买客户情况；BD 查看当前负责门店经营和归本人的佣金；平台查看整体经营及门店比较；供应商查看自身交易、供货、退款、货款结算与履约售后。

| 角色 | 数据范围 | 主要入口与内容 |
|---|---|---|
| 店长 | 当前进入门店 | 门店数据中心：总览、经营数据、运营数据、佣金明细 |
| BD | 当前负责门店的经营数据；系统归本人名下的佣金 | BD 数据中心：门店数据、佣金数据；单店零售与代采 |
| 平台 | 账号获授权的平台经营范围 | PC 数据中心：经营总览、零售经营、代采经营、门店经营比较、单店详情 |
| 供应商 | 当前供应商自身业务 | 数据中心：经营总览、商品表现、订单退款、履约与售后、货款结算 |

数据权限同时作用于汇总、趋势、排行、明细及订单下钻。页面传入的门店编号或供应商编号不能代替权限校验。

## 2. 公共统计规则

### 2.1 日期与对比

统计日期使用北京时间，页面显示所选日期范围及数据更新时间。

| 日期选项 | 统计范围 | 对比范围 |
|---|---|---|
| 今日 | 当日零点至数据更新时间 | 昨日相同时段 |
| 昨日 | 昨天完整自然日 | 前一天完整自然日 |
| 近7天 | 截至昨日连续7个完整自然日 | 紧邻之前的7个完整自然日 |
| 近30天 | 截至昨日连续30个完整自然日 | 紧邻之前的30个完整自然日 |
| 自定义 | 用户选择的起止日期，包含首尾日；结束日期不晚于今日 | 紧邻之前的等长日期范围 |

同一模块切换日期或筛选后，更新对应内容。下钻和返回保留该入口实际支持的日期及筛选；已有业务列表的筛选范围见各端订单入口说明。

对比差额＝本期值－对比期值；增长率＝差额÷对比期值。对比期为0或无法计算时不展示有效增长率。总览、BD 页按增加／减少展示变化；部分经营页和平台表格使用正负差额及百分比。具体展示沿用各页面。

### 2.2 纳入统计的交易

- 以支付成功认定购买行为，计入实际货币支付；积分抵扣金额不计入货币支付金额。
- 正常付费销售即使低价，也计入成交、订单数、购买人数及首购识别。
- 免费赠品、纯积分兑换、零元营销、积分加现金补差订单与正常付费销售分开处理，不并入本 PRD 的正常销售及购买统计。
- 仅匹配门店名称、商品名称中的“测试”或“test”，英文不区分大小写。测试门店整单排除；正常门店中的测试商品行排除，关联退款、成本及所得同步排除。
- 平台代采混合订单优先使用系统已有运费分摊；无分摊时，按保留商品实付占原商品实付的比例计算保留运费份额，运费退款与运费平台所得按相同范围处理。
- 剔除后仍有符合范围的付费销售商品，主订单计1笔；商品全部被剔除，主订单不计入。

### 2.3 订单、客户及门店去重

| 对象 | 统计键与汇总规则 |
|---|---|
| 支付订单 | 主订单 ID；子单、包裹不额外增加支付订单数 |
| 零售支付人数 | 消费者唯一身份；跨商城、直播或多店汇总时重新去重 |
| 代采支付门店数 | 采购门店编号；同店不同采购账号、操作人不重复计算 |
| 门店覆盖 | 门店编号集合；零售、代采覆盖分别计算，并集及交集用集合运算 |

零售主订单始终绑定一家门店。平台订单数按主订单 ID 重新去重，不直接累加各店订单数。金额按订单及商品行的实际归属汇总；同一笔交易不能因多标签分组重复计入平台总额。

### 2.4 两种统计时间

| 视角 | 取数方式 | 使用场景 |
|---|---|---|
| 支付订单归属 | 先圈定本期支付成功订单，再关联这些订单截至数据更新时间的退款、成本及结算结果 | 同批订单经营表现、商品交易毛利、关联佣金与平台所得 |
| 发生日期 | 本期支付按支付成功时间，本期退款按退款完成时间，结算所得按对应结算单创建时间分别统计 | 当期交易、退款及结算发生情况 |

当期净成交额＝本期支付金额－本期成功退款金额，仅用于发生日期视角。同批退款后净成交额＝该支付批订单的支付金额－关联成功退款金额，两者需明确区分。

退款以完成结果为准；部分退款及历史订单本期完成退款均按相应视角纳入。线下退款完成时间取上传凭证成功时间。

结算所得按系统中对应收款角色的结算记录取数，以结算单创建时间作为结算统计时间，不等待提现。成本或结算尚未形成时显示“—”，确认结果为0时显示0。部分结果缺失时结合页面提示识别已形成结果与未形成部分。

## 3. 店长端

### 3.1 页面结构与通用交互

门店数据中心顶层为“总览／佣金明细”。总览中的业务区提供进入“经营数据”“运营数据”的对应入口。

| 页面 | 横向模块 |
|---|---|
| 经营数据 | 平台零售、进货、佣金 |
| 运营数据 | 购买客户、购买频次、来源表现 |

页面只展示当前进入门店的数据，数据页顶部不重复展示门店名称。沿用门店 APP 已有导航、字体、数字和卡片样式，佣金明细保留原有 UI。

日期快捷项直接展示。模块以横向 Tab 切换；统计时间及订单来源使用紧凑下拉筛选。顶部采用不透明背景，不出现正文透出、叠字及隐藏导航残留的空白占位。

### 3.2 总览

| 区域 | 展示内容 | 下钻 |
|---|---|---|
| 平台零售 | 主指标“平台零售支付成交额”；退款金额、退款后净成交额、佣金；各项适用的对比信息 | 查看经营数据进入平台零售模块；佣金进入相同口径明细 |
| 渠道构成 | 商城、直播的支付成交额及占比，使用紧凑占比条 | 固定展示两项，无额外视角切换 |
| 成交趋势 | 支付成交额、净成交额、支付人数切换 | 查看对应时间点数据 |
| 代采进货 | 进货支付总额、进货订单数 | 查看进货数据，进入进货模块并保留日期 |
| 客户概况 | 支付人数、首购客户数、老客户数、本期购买2次及以上人数 | 查看运营数据 |

总览零售指标使用支付订单归属视角，关联截至数据更新时间的结果。进货支付金额与零售成交分开展示。

### 3.3 经营数据：平台零售

平台零售模块提供两个下拉筛选：支付订单归属／发生日期、全部来源／商城／直播。进货与佣金模块不展示这两个下拉。

| 指标 | 定义 |
|---|---|
| 平台零售成交额（元） | 本店符合统计范围的零售支付成功订单实际货币支付合计；当前为商品实付。总览主指标名称为“平台零售支付成交额” |
| 支付订单数（单） | 符合范围的支付成功主订单去重数 |
| 支付人数 | 符合范围的支付消费者去重数 |
| 客单价 | 支付成交额÷支付主订单数；分母为0显示“—” |
| 商品退款（元） | 对应统计时间视角的成功商品退款金额 |
| 退款后实付（元） | 当前视角支付金额减成功商品退款金额；总览使用“退款后净成交额”名称 |

客单价不使用支付减退款作分子；周期客单价用周期金额除以周期订单数，不平均每日客单价。趋势与当前来源、日期、统计时间保持一致。

趋势图标题为“成交额趋势”，展示支付成交额随时间变化，可切换查看数据表。切换发生日期视角后，退款指标按退款完成日期统计，支付趋势仍按支付成功时间统计。

“最近订单”最多展示当前范围内最近5笔订单，按支付成功时间倒序；不足5笔按实际展示。发生日期视角的候选范围包含本期支付或本期完成退款的订单。汇总及趋势不受5笔预览限制。

订单摘要沿用“工作台 → 客户订单”的字段与样式，展示商品摘要、支付时间、订单号、实付金额及订单状态。履约状态与退款／售后状态分别展示，不以“部分退款”替代履约状态。状态取系统记录，不展示独立占位“—”；确实缺失时使用明确提示。

“查看全部订单”和最近订单摘要进入已有“工作台 → 客户订单”（页面标题“门店订单”），默认选择“全部”状态。目标页提供订单搜索、订单状态及自提／快递筛选；当前入口不传递报表日期和商城／直播来源，列表按该业务页自身范围展示。返回入口带回原报表页面及其筛选。

最近订单摘要链接虽携带订单编号，当前历史列表未按该编号自动定位或打开详情；本文不将其写为已支持的直接详情下钻。

### 3.4 经营数据：进货

| 指标 | 定义 |
|---|---|
| 进货商品款 | 本期支付成功进货订单商品实付合计，不含运费 |
| 运费 | 对应进货订单实际支付运费 |
| 进货支付总额 | 进货商品款＋运费 |
| 进货订单数 | 纳入统计的支付成功主订单去重数 |
| 商品退款／运费退款 | 根据退款完成记录分别展示 |
| 本期最近进货日 | 所选周期内有效支付订单的最近支付日期 |
| 本期进货天数 | 周期内有有效进货支付的自然日去重数 |
| 平均进货间隔 | （本期最近进货日－本期最早进货日）÷（本期进货天数－1），单位天；不足2个进货日显示“—” |
| 最近一次进货 | 全部可查询历史中最近有效进货支付日期，标明“全部历史” |

进货趋势展示支付总额变化。商品退款、运费退款按本期退款完成日期统计，与本期支付统计分别取时间。进货是门店采购支出，与零售销售金额分开。

“最近进货订单”最多展示当前范围内最近5笔，按支付成功时间倒序。摘要沿用已有进货订单的字段和样式，包含商品摘要、支付时间、订单状态及支付总额；商品款、运费可进入原订单详情查看。

“查看全部进货订单”及预览摘要均进入已有“进货 → 进货订单列表”。当前只携带报表返回地址，不按报表日期过滤，也不直接打开特定进货订单；列表及订单详情沿用该业务页已有能力。

### 3.5 经营数据：佣金与佣金明细

佣金取系统结算记录中收款角色为当前门店的份额，不包含店长个人以 BD 或主播身份获得的所得。佣金与平台零售支付成交额分别展示。

经营数据的佣金模块按本期支付订单关联佣金，展示“佣金合计、待结算佣金、已结算佣金”，以及“商城佣金／直播佣金”拆分、佣金趋势。点击“结算明细”进入按支付时间的佣金明细，并携带日期。

佣金明细保留以下已有内容：

| 区域 | 页面内容 |
|---|---|
| 统计维度 | 按支付时间／按结算时间；页面分别标识预估佣金或结算口径 |
| 账户区 | 可提现账户余额、显示／隐藏余额、去提现入口 |
| 期间汇总 | 所选期间佣金及订单数；今日、昨日、近7天、近30天分时段摘要 |
| 筛选区 | 日期、搜索、全部／待发货／待自提待收货／已完成等订单状态 |
| 订单明细 | 按日期分组，包含订单编号及复制、联系人及电话、商品、实付金额、退款金额、佣金、结算状态、支付时间、结算单创建时间及备注 |

从某个佣金指标进入明细时，携带该指标的日期及统计时间；不能受历史筛选缓存影响自动换成另一时间口径。异常、取消及未形成的结算结果不能混入正常佣金合计。

### 3.6 运营数据

购买行为以本店正常付费销售订单支付成功为准；支付后退款不抹除已发生的购买行为。消费者更换绑定门店时，不迁移其他门店的购买历史。

| 指标 | 定义 |
|---|---|
| 支付人数 | 本期在本店有符合范围支付订单的消费者去重数 |
| 首购客户数 | 期初从未在本店购买，本期首次在本店支付购买的消费者数 |
| 老客户数 | 期初已经在本店购买，本期再次支付购买的消费者数 |
| 老客户占比 | 老客户数÷支付人数；分母为0显示“—” |
| 本期购买2次及以上人数 | 本期在本店支付成功主订单数不少于2的消费者数 |
| 多次购买占比 | 本期购买2次及以上人数÷支付人数 |
| 人均购买次数 | 本期支付主订单数÷本期支付人数 |

首购客户与老客户互斥，相加等于支付人数。本期首次购买后再次购买的客户仍归首购客户，同时可计入本期购买2次及以上人数；后者不能与首购、老客相加。

购买客户模块展示客户指标及人数趋势；购买频次模块展示重复购买人数、占比、人均购买次数及频次分布；来源表现分别展示商城、直播的支付成交额、支付主订单数、支付人数和客单价。

同一消费者跨商城与直播购买时，在各来源分别计入，在合计中重新去重。来源按照订单记录，不重新归因。

## 4. BD 端

### 4.1 页面与权限

BD 数据中心顶层为“门店数据／佣金数据”。

“门店数据”下有“业务分析／零售经营／平台进货”：
- 业务分析：零售／代采切换，展示汇总指标、趋势及门店排行。零售可按成交额、订单数、支付人数、佣金排序；代采可按商品金额、进货总额、订单数、佣金排序。
- 零售经营：展示当前负责门店数，按零售成交额展示门店卡片。卡片含订单数、支付人数、客单价、零售佣金及全部历史最近成交日。
- 平台进货：展示本期有进货的负责门店，按商品金额排序。卡片含订单数、进货天数、代采佣金及全部历史最近进货日。

门店卡片或排行可进入单店页。“佣金数据”直接展示佣金分析，分析中提供佣金明细入口。

| 场景 | 经营数据 | 佣金 |
|---|---|---|
| 当前负责门店 | 可查看该门店经营历史 | 只计归当前 BD 本人的佣金 |
| 门店交接给其他 BD 后 | 原 BD 不再查看该门店经营数据 | 保留归原 BD 本人的历史佣金及必要对账摘要 |
| 新 BD 接手门店 | 可查看当前负责门店的经营历史 | 不因此取得前任 BD 的佣金数据 |

历史佣金下钻不能开放已交接门店完整经营页面。门店列表、单店详情、返回入口和明细链接须使用同一门店身份；无权限或门店无法识别时明确提示，不能静默回退到默认门店。

### 4.2 门店业务数据

零售、代采使用各自指标，不合并为一个门店营业额。

| 业务 | 单店主要指标 |
|---|---|
| 零售 | 零售佣金、支付成交额、支付主订单数、支付人数、零售客单价、有成交天数、本期最近成交日、全部历史最近成交日及趋势 |
| 代采 | 代采佣金、商品支付金额、进货支付总额、支付主订单数、进货天数、平均进货间隔、全部历史最近进货日及趋势 |

“零售佣金”“代采佣金”均指当前 BD 本人的对应佣金，取系统中归本人的结算记录。单店页点击佣金，可进入带门店、业务及日期条件的本人佣金明细。

门店经营金额与个人佣金分别按各自数据范围统计，不能为了只看本人佣金而遗漏当前负责门店的其他有效交易。

### 4.3 佣金数据

进入“佣金数据”直接显示佣金分析，包含本人零售与代采佣金、已交接门店归本人所有的历史佣金。

分析展示佣金合计、待结算佣金、已结算佣金、门店佣金贡献、佣金来源及趋势。来源拆分为商城、直播、代采。分析页提供按支付时间／按结算时间筛选，结算时间对应结算单创建时间。

“查看佣金明细”进入已有明细页，携带适用的日期、时间口径、来源、门店及结算状态条件。明细页提供时间口径、佣金来源、结算状态筛选；来源包括全部来源、零售合计、商城、直播、代采，状态包括全部状态、待结算、结算中、已结算、结算失败、已取消。明细展示关联门店、订单、佣金金额及结算状态，并可点击查看对账摘要。异常记录可在明细查询，但不混入正常佣金合计。

## 5. 平台 PC

### 5.1 页面与筛选

PC 顶部“数据中心”对应左侧“经营总览、零售经营、代采经营、门店经营比较”；单店详情从对应门店进入。导航选中状态在刷新和下钻后保持正确。

经营总览、零售经营、代采经营支持公共日期、支付订单归属／发生日期，以及事业线、品牌、合作类型筛选；门店经营比较固定支付订单归属视角，支持日期与门店档案筛选；单店详情固定支付订单归属，只提供日期选择。事业线、品牌按门店档案筛选，上级条件改变后处理失效的下级选项。

### 5.2 经营总览与业务线

| 页面 | 主要内容 |
|---|---|
| 经营总览 | 支付归属视角主卡为平台支付成交额（商品／运费分列）、商品交易毛利与毛利率、平台分配所得、支付主订单数、成交门店覆盖；订单卡附零售人数及代采门店数。发生日期视角按页面展示当期支付、退款、净成交及平台所得。另有门店 TOP10、支付成交额趋势与业务线构成 |
| 零售经营 | 零售支付成交额、支付主订单数、支付人数、零售客单价、商品交易毛利及毛利率、零售商品分配所得；支付趋势与商城货架／直播来源构成 |
| 代采经营 | 代采支付成交额、商品支付金额、运费支付金额、支付主订单数、支付门店数、代采进货客单价、商品交易毛利及毛利率、平台分配所得；商品支付趋势、支付构成及平台所得构成 |
| 单店详情 | 零售经营、代采进货、平台分配所得三个区块，固定按支付订单归属。零售含成交额、主订单数、人数、客单价、毛利、有支付天数及最近支付；代采含商品金额、主订单数、进货客单价、毛利、有进货天数、最近进货及相邻进货间隔；所得按三项及合计展示 |

| 指标 | 定义 |
|---|---|
| 代采支付成交额 | 代采商品支付金额＋运费支付金额 |
| 平台支付成交额 | 零售支付成交额＋代采支付成交额 |
| 代采进货客单价 | 代采商品支付金额÷代采支付主订单数；不含运费，分母为0显示“—”；展示于平台代采经营及单店详情 |
| 商品净实付 | 支付订单归属视角下，扣除关联成功商品退款后的商品实付，不含运费 |
| 商品交易毛利 | 同批商品净实付－对应剩余采购成本 |
| 商品交易毛利率 | 商品交易毛利÷同批商品净实付；分母为0显示“—” |
| 平台分配所得 | 系统结算记录中归平台的商品及运费份额，分项展示 |
| 任一业务成交门店数 | 有零售支付成交门店与有代采支付成交门店的并集 |
| 两者均有门店数 | 同一统计范围内零售与代采成交门店的交集 |

采购成本使用交易对应快照，不随当前采购价回溯变化。剩余采购成本根据售后结论及实际成本调整记录确定，不能直接按退款金额比例推减。运费退款不冲减商品采购成本。毛利允许负值，不套用分佣侧负毛利归0规则。

平台分配所得按零售商品、代采商品、代采运费分项取对应平台份额。代采运费份额取系统结算记录，不根据客户运费与承运商金额自行推算。

毛利只使用同批商品金额与成本；发生日期视角的当期净成交，不与其他支付批成本直接相减形成毛利。

经营总览相关指标可打开支付订单、退款或毛利等明细抽屉；零售经营、代采经营及单店详情从主订单数入口打开支付主订单明细。明细表提供分页，订单号进入相应零售或代采订单页面，业务线使用“零售／代采”中文名称。

零售、代采经营切换发生日期时，毛利显示“—”并提示切换支付归属视角，支付人数／支付门店数也按页面显示“—”；支付订单数与其明细仍按本期支付订单圈定。支付趋势及来源构成继续使用支付数据，不将其描述为退款发生趋势。总览支付趋势可切换成交额合计、商品实付、运费实付。

### 5.3 统一门店排行与比较

经营总览展示 TOP10，门店经营比较展示完整列表，支持门店名称搜索、清空、分页及每页条数选择。统一门店表采用支付订单归属指标；总览切换发生日期后，排行仍使用支付订单归属数据。两处使用同一指标定义、门店范围和排序逻辑。

| 表头分组 | 字段 |
|---|---|
| 基础信息 | 排名、门店、事业线、品牌 |
| 零售经营 | 支付成交额、支付主订单数、商品交易毛利及毛利率 |
| 代采进货 | 商品支付金额、运费支付金额、支付主订单数 |
| 平台分配所得 | 零售商品所得、代采商品所得、代采运费所得、所得合计 |
| 对比与操作 | 当前排序指标较上期变化、详情 |

默认按零售支付成交额降序；可切换代采商品支付金额、平台分配所得合计排序。切换仅改变名次、排序列强调及该指标对比，不更换表头或门店集合。

同一筛选范围内仅有代采成交的门店，仍可在默认零售排序表中显示，零售交易金额为0。确认无交易与结果未形成使用不同显示。

宽表在表格内部横向滚动，固定门店及操作列。各业务指标并列比较，不生成综合总分。

## 6. 供应商端

### 6.1 页面结构

供应商数据中心按页面顺序使用横向模块切换：“经营总览、商品表现、订单退款、履约与售后、货款结算”。顶部展示日期选择及数据截止时间，各模块只查询当前供应商自身业务。

### 6.2 总览与商品表现

| 模块 | 内容 |
|---|---|
| 总览：交易与供货 | 支付交易规模、支付交易数量、支付订单数、实际供货数量、实际供货货款、退款金额 |
| 总览：结算摘要 | 应结货款、待结算货款、已结算货款 |
| 商品表现 | 商品／SKU、支付交易数量、履约完成供货数量、支付交易额、货款、退数量及退款金额；支持现有商品搜索和排序 |

交易规模及支付数量按支付成功时间统计；实际供货按系统现有履约完成节点统计，分别命名和展示。履约完成记录缺失时不以发货时间、支付时间替代。

商品表现按实际商品／SKU 归属汇总，支付数量、履约完成数量与退款数量分列。商品搜索支持商品／SKU，排序选项为支付交易额、支付数量、履约供货量、售后率；表格列为商品、支付数量、履约供货、支付交易额、货款、退数量／退款。商品货款与顾客支付金额分别取对应业务记录，不互相替代。

### 6.3 订单退款

展示关联订单、商品、退款类型、顾客退款金额、供应商货款调整，以及订单、售后、结算状态。

成功退款按退款完成时间纳入。顾客退款与供应商货款调整分别取系统记录；货款调整尚未形成显示“—”，不能直接以顾客退款金额代替。仅退款、退数量等售后结果按实际记录展示。

### 6.4 货款结算

分别展示应结货款、待结算货款、已结算货款、售后／退款冲销及对账差异数。金额均取供应商结算记录，不用消费者实付代替，不直接将三项相加为货款总额。

“结算单明细”进入已有供应商结算页面，可查看关联订单与结算结果。已结算与银行实际到账分别识别，不把结算完成自动表述为到账。

### 6.5 履约与售后

履约指标包括履约完成订单数、履约完成商品数、待发货数、平均发货时长（小时）、缺货取消数、配送异常数。

售后类型按仅退款、退货退款、补货等实际类型展示申请数、完成数及金额；售后原因展示原因原文、笔数及金额。售后申请、审核与退款完成分别识别，不将申请量作为成功退款量。

“客户订单”“售后管理”进入供应商已有页面，按当前供应商权限查看关联业务。

## 7. 页面状态与验收要求

### 7.1 页面状态

| 状态 | 展示行为 |
|---|---|
| 供应商加载中 | 展示加载提示 |
| 无符合记录 | 对应订单、列表或图表展示空态；保留当前页面已有筛选及清空能力 |
| 已确认结果为0 | 交易汇总按页面显示0；比率分母为0显示“—”。平台单店详情在无业务时使用“—”并标识无零售／代采成交 |
| 成本、佣金、货款结果未形成 | 显示“—”并提供对应指标解释，不当作0 |
| 供应商加载失败 | 显示错误提示及重试入口 |
| 无权限或对象无法识别 | 明确提示并允许返回，不展示其他门店或主体的默认数据 |

指标说明面向实际使用者，解释金额包含内容、统计时间及必要限制。页面不展示开发参数、内部调试方式、演示接口说明。

原型样例覆盖主要日期和有效筛选组合，以及跨期退款、跨期结算、部分退款、负毛利、无交易和结果未形成。样例间汇总、趋势、排行和明细一致，不通过忽略筛选填充数据。

### 7.2 验收清单

- 四端从各自实际业务入口进入，导航、主体身份及返回关系正确。
- 日期及筛选按页面适用范围生效；支付趋势、支付归属排行与发生日期指标明确区分。
- 订单按主订单去重，消费者及门店按各自身份去重；测试数据和特殊交易排除一致。
- 支付订单归属与发生日期分别取数，跨期退款、跨期结算可解释和对账。
- 店长总览主指标为平台零售支付成交额，进货摘要仅保留总额与订单数。
- 商城与直播固定展示；购买客户分类互斥，跨来源合计人数重新去重。
- 零售、进货最近订单均最多5笔且按支付时间倒序，进入历史业务列表；目标列表使用其自身筛选，返回保留报表筛选，不将入口写成已支持精确定位订单详情。
- 门店佣金与 BD 本人佣金取各自收款角色记录，金额与明细一致。
- 原 BD 无法查看已交接门店经营数据但可看本人历史佣金；新 BD 可看当前负责门店经营历史。
- PC 数据中心使用经营菜单；排行切换表头不变、指标与名次一致，仅代采成交门店仍可见。
- 平台毛利使用同批商品金额与实际成本调整，负值真实展示，未形成结果不当作0。
- 供应商按经营总览、商品表现、订单退款、履约与售后、货款结算五区展示；支付交易与履约供货分别统计，货款使用结算口径。
- 移动端无叠字、透底、无意义空白及整页横向滚动；PC 宽表在内部滚动。
