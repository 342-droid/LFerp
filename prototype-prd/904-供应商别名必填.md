# 【904】供应商别名必填

# 1. 后台业务 WEB 系统

## 1.1 概述

### 需求背景

供应商别名用于 C 端购物车、确认订单、订单详情的供应商标题。原先非必填，存量有空值；空时 C 端回退供应商名称。现改为必填。

口径确认：

1. **只在 PC 处理**，不做供应商 APP 自助维护。
2. **由平台运营**在供应商档案中维护别名（含存量补填）。
3. 已进件供应商一般不再改档，因此存量空别名不依赖商户回访，而依赖运营主动在 PC 补齐。
4. 不做登录「完善资料」门禁，不做静默批处理把空别名写成供应商名称。

### 需求目标

1. PC 新增、编辑保存时别名必填。
2. 存量空别名由运营在 PC 补填；未补前 C 端仍回退供应商名称，不拦经营。
3. 列表能识别空别名，便于运营处理。

## 1.2 历史数据处理方案

| 规则 | 说明 |
| --- | --- |
| 责任方 | 平台运营（PC 供应商档案） |
| 新增 | 别名必填，空白不可保存 |
| 编辑 | 别名必填；原为空时预填供应商名称，运营可改成对外简称后保存 |
| 存量空别名 | **不自动迁库**；列表显示「—」，可标「待补」；经营与登录不受影响 |
| C 端 | 有别名用别名，无别名用供应商名称，直至运营补填 |
| 不采用 | 供应商 APP 自助改别名；登录完善资料拦截；上线日静默批量写名称 |

### 运营补填建议节奏（非系统强制）

1. 发版后按列表「待补」或筛选空别名逐步补。
2. 优先补 C 端曝光高的供应商；其余可排期处理。
3. 若业务后续要求库内尽快无空，再单独做**经运营确认**的导入/批量，不作为默认发版动作。

## 1.3 管理范围

| 入口 | 说明 |
| --- | --- |
| PC · 供应商档案 | 新增 / 编辑维护别名；唯一写入入口 |
| C 端 | `别名 \|\| 供应商名称` |
| 供应商 APP / 门店 APP | 不提供别名维护 |

## 1.4 交互规则

1. 表单别名带必填星标；未填 toast「请输入供应商别名」。
2. 编辑时空别名预填供应商名称，提示可改成对外简称。
3. 列表空别名显示「—」并附「待补」，便于运营识别。
4. 字段说明：由平台运营维护；未填时 C 端回退显示供应商名称。

## 1.5 验收标准

| 场景 | 预期 |
| --- | --- |
| 新增不填别名 | 无法保存 |
| 编辑空别名 | 预填名称，可改；不可空保存 |
| 存量空别名未补 | 列表「— / 待补」；C 端显示供应商名称；其它业务正常 |
| 运营补填并保存 | 「待补」消失；C 端显示别名 |
| 无 APP / 登录门禁 | 供应商侧无别名自助页，登录流程不变 |
