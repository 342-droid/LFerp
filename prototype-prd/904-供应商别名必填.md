# 【904】供应商别名必填

# 1. 后台业务 WEB 系统

## 1.1 概述

### 需求背景

供应商别名用于用户 APP / 门店进货相关页面的供应商标题展示。原先非必填，存量有空值；空时回退供应商名称。现改为必填，并由平台运营在 PC 维护。

口径确认：

1. **只在 PC 处理**别名写入，不做供应商 APP 自助维护。
2. **由平台运营**在供应商档案中维护别名（含存量补填）。
3. 已进件供应商一般不再改档，存量空别名依赖运营在 PC 补齐。

### 需求目标

1. PC 新增、编辑保存时别名必填。
2. 存量空别名由运营在 PC 补填；未补前展示仍回退供应商名称，不拦经营。
3. 列表能识别空别名，便于运营处理。

## 1.2 历史数据处理方案

| 规则 | 说明 |
| --- | --- |
| 责任方 | 平台运营（PC 供应商档案） |
| 新增 | 别名必填，空白不可保存 |
| 编辑 | 别名必填；原为空时预填供应商名称，提示「请填写对外简称」后保存 |
| 存量空别名 | **不自动迁库**；列表空显示「-」；经营与登录不受影响 |
| 展示回退 | 有别名用别名，无别名用供应商名称，直至运营补填 |

## 1.3 PC 管理范围与交互

| 入口 | 说明 |
| --- | --- |
| PC · 供应商档案 | 新增 / 编辑维护别名；唯一写入入口 |

1. 表单别名带必填星标；未填 toast「请输入供应商别名」。
2. 编辑时空别名预填供应商名称，提示「请填写对外简称」。
3. 列表空别名显示「-」。

# 2. 门店 APP 端展示（别名透出）

## 2.1 展示规则

1. **取值顺序**：有别名展示别名；无别名展示供应商名称。
2. **历史订单与售后**：别名修改后，历史列表/详情按**最新别名**展示（不固化下单时快照文案）。
3. **分组与拆单**：仍按**供应商 ID** 分组/拆单，不得按别名合并，避免同名简称误并。

## 2.2 需覆盖的页面

| 页面 | 需要覆盖的展示位置 |
| --- | --- |
| 进货首页 / 分类商品列表 | 商品流供应商名称 |
| 进货购物车 | 供应商分组标题 |
| 确认订单 | 供应商分组标题；组内各履约包裹关联的供应商名称 |
| 商品详情 | 供应商信息区（若页内展示） |
| 我的进货订单列表 | 履约单卡片上的供应商名称（若展示） |
| 进货订单详情 | 供应商信息 / 商品分组 / 包裹标题中的供应商名称 |
| 售后列表、售后申请及详情 | 原订单/商品卡片关联的供应商名称（覆盖仅退款、退货退款、补货） |
| 退货信息 / 填写退货物流 | 退货地址区供应商名称（若展示） |
| 门店钱包账户明细及详情 | 佣金结算、佣金回退的交易方 |

# 3. 验收标准

| 场景 | 预期 |
| --- | --- |
| PC 新增不填别名 | 无法保存 |
| PC 编辑空别名 | 预填名称，提示「请填写对外简称」；不可空保存 |
| 存量空别名未补 | 列表显示「-」；各进货页显示供应商名称 |
| 运营补填别名后 | 列表显示别名；进货首页/购物车/确认单/订单/售后/钱包交易方显示别名 |
| 修改别名后再看历史订单 | 标题为最新别名 |
| 两供应商别名相同 | 购物车/确认单仍按供应商 ID 分成两组 |
| 无 APP 写入入口 | 供应商侧不能自助改别名 |
