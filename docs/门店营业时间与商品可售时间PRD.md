# 门店营业时间与商品可售时间

## 背景

门店何时开门、商品何时能卖，目前分散在平台默认、门店个性化、类目、快递 24 小时、单品自定义等多处。若规则不统一，会出现：

1. 把「店开着」当成全店可卖，营业时间内仍有商品已过自身窗口。
2. 把「店打烊」当成全店不可卖，快递 24 小时 / 自定义窗口仍有效的商品被误杀。
3. 购物车校验过后，确认页停留期间门店打烊，若不再校验会下出不该出的单。
4. 后台改了时间，运营无法判断当前生效的是哪一层配置。

## 目标

- 后台可分层配置门店营业时间、商品可售时间，并明确优先级。
- C 端按「该商品自己的可售时间」判定当前是否可卖：有的商品营业时间内也不可售，有的商品门店休息仍可售。
- 购物车点「立即下单」必须校验一次；确认订单提交必须再校验一次（防止停留期间门店打烊或窗口结束）。
- 浏览、搜索、详情、购物车、确认订单的露出、标识、拦截文案一致，可对照验收。

## 范围

**本期做**

- 平台：默认营业时间、是否允许跨日、商品类目可售时间、快递商品 24 小时可售
- 门店：本店独立营业时间 / 跟随平台；超过营业时间运营状态为「休息中」（与 C 端一致）
- 商品：商城 / 代采单品可售时间（跟随上层 或 自定义）
- C 端：可售判定、前端标识、加购与下单拦截
- 代采进货（门店 APP `restock.html?from=store-app`）：同步可售标识与购物车 / 确认订单两次校验；**不跟门店营业时间**

**本期不做**

- 不按星期拆不同营业时段（每天同一窗口）
- 不按仓库 / 供应商单独配营业时间
- 不把「可售时间」做成售后时效（退货期限、售后截止等另案）

## 术语

| 术语 | 说明 |
|------|------|
| 门店营业时间 | 该门店当天对外营业的时段。门店自定义优先，否则用平台默认 |
| 商品可售时间 | 该商品当天允许售卖的时段（不是售后时限） |
| 可售 | 当前时刻落在该商品自己的可售时间内 |
| 不可售 | 不在该商品可售时间内。前端标识文案为「商品不可售」 |
| 跟随门店 | 商品未配更具体窗口，可售时间等于门店营业时间；店休息则这类商品不可售 |
| 休息中 | 当前不在门店营业时间内。后台运营状态与 C 端门店状态均为「休息中」 |
| 跨日 | 结束时间早于开始时间，如 22:00 至次日 02:00 |
| 跟随 | 商品未自定义可售时间时，按优先级继承上一层时段 |

## 1. 判定总则（P0）

### 1.1 可售公式

**商品可售 = 当前处于该商品自己的可售时间**

门店营业时间**不是**全店总开关，只是「未配更具体窗口」时的继承来源。因此：

| 情况 | 结果 |
|------|------|
| 门店营业中，商品窗口更窄（自定义 / 类目未到或已过） | 该商品不可售 |
| 门店休息中，商品跟随门店 / 平台营业时间 | 该商品不可售 |
| 门店休息中，商品为自定义 / 类目 / 快递 24 小时，且自身窗口仍有效 | **该商品仍可售** |

快递 24 小时可售把快递商品的窗口放宽为全天，门店休息不拦截这类商品。

### 1.2 商品可售时间优先级（高 → 低）

取到第一层有效配置即停，不再往下看：

1. 商品自定义可售时间（SPU 已改过并保存）
2. 快递商品 24 小时可售（平台已开，且该商品履约为快递）→ 固定 00:00–23:59
3. 商品类目可售时间（平台按选品库类目配置，命中该类目）
4. 门店自定义营业时间
5. 平台默认营业时间
6. 兜底 08:00–22:00

未配置或配置不完整时，落到下一层；全部缺失用兜底。

### 1.3 门店营业时间优先级（高 → 低）

决定门店运营状态（营业中 / 休息中），并作为「跟随门店」商品的可售窗口。**不算**类目 / 商品自定义 / 快递 24 小时：

1. 该门店已保存本店独立营业时间
2. 平台默认营业时间
3. 兜底 08:00–22:00

### 1.4 时刻是否落在窗口内

以当天时分 `HH:mm` 比较（结束时刻不含，如 08:00–22:00 在 22:00 整为打烊 / 不可售）。

| 窗口类型 | 判定 |
|----------|------|
| 当日（开始 < 结束，且未开跨日） | 当前 ≥ 开始 **且** 当前 < 结束 |
| 跨日（已开「允许跨日」或开始 > 结束） | 当前 ≥ 开始 **或** 当前 < 结束 |
| 快递 24 小时可售（仅商品窗口） | 视为全天可售 |

开始与结束不能相同。未开跨日时，结束必须晚于开始。

**验收**

- 08:00–22:00、当前 21:59 → 跟随门店的商品可售；22:00 → 门店打烊，跟随门店的商品不可售
- 22:00–02:00 且允许跨日、当前 23:00 或 01:00 → 营业中；当前 10:00 → 打烊
- 门店营业中、商品自定义 09:00–11:00、当前 16:00 → 该商品不可售
- 门店打烊时，快递 24 小时或自定义窗口仍覆盖当前时刻的商品 → 仍可售、可加购、可下单

## 2. 后台配置

### 2.1 平台 · 营业时间配置（P0）

**位置**：门店配置 → 营业时间配置（修改 / 取消 / 保存）

| 字段 | 必填 | 说明 |
|------|------|------|
| 默认营业时间 | 是 | 全平台门店默认时段，默认 08:00 至 22:00 |
| 允许跨日营业 | 是 | 是 / 否（默认否）。开启后，默认营业时间与类目可售时间均可跨日 |
| 商品类目可售时间 | 否 | 按选品库类目加多条：类目 + 每天可售起止。类目不可重复 |
| 快递商品 24 小时可售 | 否 | 开关。开：履约为快递的商品，商品窗口视为 00:00–23:59；门店休息期间仍可售 |

保存校验：默认时段、每条类目时段均须满足 1.4；类目必须已选且不重复。失败不保存，提示对应字段。

超过平台默认营业时间：未配本店时间的门店打烊。超过类目可售时间：走该类目继承的商品不可售（仍先过优先级）。

### 2.2 门店 · 本店营业时间（P0）

**位置**：门店档案列表「营业时间」列；门店详情标题旁 / 基础信息「营业时间」。

| 展示 | 含义 |
|------|------|
| `08:00–22:00` + 标签「平台」 | 跟随平台默认，悬停「跟随平台默认营业时间」 |
| `09:00–21:00` + 标签「本店」 | 本店独立，悬停「本店独立营业时间」 |

点击编辑：起止时间 +「跟随平台」+「完成」。

| 操作 | 结果 |
|------|------|
| 完成且时段合法 | 写入本店独立时间，标签改为「本店」 |
| 跟随平台 | 清除本店时间，恢复跟随平台 |
| 未开跨日且结束不晚于开始 | 不保存，提示「未开启跨日营业时，结束时间需晚于开始时间」 |
| 开始 = 结束 | 不保存，提示「营业开始与结束时间不能相同」 |

**运营状态**（与 C 端一致，仅此两值）：

| 状态 | 判定 |
|------|------|
| 营业中 | 当前时刻在该店营业时间内 |
| 休息中 | 当前时刻不在该店营业时间内 |

列表可按运营状态筛选。超过营业时间自动变为「休息中」，不再使用「打烊」。

### 2.3 商品 · 可售时间（P0）

**位置**：商品列表 / 代采商品列表「可售时间」列（与门店营业时间一致，点编辑小图标才可改）；新增/编辑商品表单「可售时间」。

| 模式 | 说明 |
|------|------|
| 跟随 | 未改时间框。按 1.2 继承，表单下方提示来源 |
| 自定义 | 运营改过起止并保存。之后改类目 / 履约 / 门店 / 平台，不再自动覆盖 |

表单来源提示：

| 来源 | 提示 |
|------|------|
| 商品自定义 | 已采用商品自定义可售卖时间 |
| 快递 24 小时 | 24小时可售 |
| 类目 | 已采用商品类目可售卖时间 |
| 门店自定义 | 已采用门店自定义营业时间 |
| 平台默认 | 已采用平台默认营业时间 |

列表格内改时间即视为自定义。跟随态保存时仍按当时继承结果写入展示值，模式保持跟随。

### 2.4 C 端 · 门店名称旁的营业时间（P0）

**用户 APP 首页**：顶栏定位行 = 门店名称 + 箭头 + **右侧营业时间**（如 `08:00-22:00`）。时段取该店生效营业时间（本店自定义 > 平台默认），只读，点整行进切换地址。

**切换地址 / 自提点卡片**：门店名下方同时展示状态（营业中 / 休息中）和营业时间。

**我的 · 默认自提**：自提点旁展示营业时间。

**订单详情（自提）**：配送信息可展示营业时间。

首页只露时段、不在店名旁重复打「营业中 / 休息中」；状态以切换地址列表为准。

## 3. 前端标识（C 端）

统一文案：**商品不可售**。不另造「已打烊」「已过期」等商品标。

### 3.1 何时打标

该商品**自身可售窗口未到 / 已过**即打「商品不可售」，与门店当前是否营业无关。

店休息时：跟随门店的商品打标（或浏览下架）；自定义 / 类目 / 快递 24 小时且窗口仍有效的商品不打标、照常露出。

### 3.2 各页露出

| 页面 | 不可售商品 | 标识 |
|------|------------|------|
| 首页浏览、商城浏览、分类浏览 | 下架，不展示 | 无（卡片不出现） |
| 搜索结果 | 仍展示 | 卡片「商品不可售」，加购禁用 |
| 商品详情 | 仍展示 | 主图区「商品不可售」，加购 / 立即购买不可用 |
| 购物车有效区 | 可留在车内 | 不可勾选；点立即下单再拆失效（见 4） |
| 购物车 / 确认订单失效区 | 展示在「失效宝贝」 | 角标「失效」，原因「商品不可售」 |
| 直播间商品 | 仍展示 | 购买按钮不可用，文案「商品不可售」（已售罄仍用原「已售罄」） |

**验收**

- 店开着、商品过了自身可售时段：搜索 / 详情有标；首页同类目浏览看不到该品
- 店打烊：跟随门店的商品首页 / 分类不露出，搜索 / 详情打标；快递 24 小时等窗口仍有效的商品照常露出、可买
- 标识文案各页一致，均为「商品不可售」

## 4. 交互逻辑

### 4.1 加购 / 立即购买

当前不可售：不加入购物车，Toast「商品不可售」。已在车内的历史行不自动删除，进入 4.2。

### 4.2 购物车勾选

不可售行不可勾选，全选也不勾上它们。失效行进入「失效宝贝 N 件」，原因「商品不可售」。

### 4.3 立即下单 / 确认订单（P0）

必须做**两次独立校验**，都按提交当下的时刻重算，不沿用上一页的结论：

| 时机 | 动作 |
|------|------|
| 购物车点【立即下单】 | 校验本次勾选。全部不可售则拦截；部分不可售则拆失效后进确认页；全部可售则进确认页 |
| 确认订单点【确认订单】/ 提交 | **必须再校验一次**。用户可能在确认页停留到门店打烊，或商品窗口结束；此时把新不可售的剔除或整单拦截 |

**只校验本次已勾选（确认页为当页待支付商品）**，未勾选不参与拆单、不进本次失效专区。

点「应用」验收开关只回到「全部可售」列表，**不**当场拆单。部分 / 全部不可售要等用户点「立即下单」或「确认订单」才校验。

弹框约 2 秒后消失；「全部不可售」可点「确定」关闭。

#### 本次勾选全部不可售，且都跟随门店、当前店已休息

| 元素 | 文案 |
|------|------|
| 标题 | 商品不可售 |
| 正文 | 当前门店休息中，商品暂不可售 |
| 按钮 | 确定 |

购物车：留在购物车。确认订单：回购物车。

若勾选里仍有自定义 / 类目 / 快递 24 小时且窗口有效的商品，**不走整单休息文案**，按部分 / 全部可售继续。

#### 部分不可售（部分勾选商品过了自身可售时间，或跟随门店而店已休息）

| 元素 | 购物车「立即下单」 | 确认订单「确认订单」 |
|------|--------------------|----------------------|
| 标题 | 部分商品不可售 | 部分商品不可售 |
| 正文 | 部分商品库存不足或已不可售，已为你剔除不可售商品，**可继续下单** | 部分商品库存不足或已不可售，已为你剔除不可售商品，**可继续支付** |

拆单规则（只拆勾选项）：

1. 勾选里同时有自提和快递：自提可售，快递进失效。
2. 否则按勾选顺序隔件拆（一可售、一不可售）。
3. 不可售行取消勾选，进入失效专区。
4. 购物车：弹框结束后带失效商品进确认页；确认页：留在当页，可继续支付可售部分。

#### 全部不可售（本次勾选全部过了自身可售时间，且不是「全员跟随门店 + 店休息」）

| 元素 | 文案 |
|------|------|
| 标题 | 商品不可售 |
| 正文 | 商品库存不足或已不可售，需要重新挑选产品 |
| 按钮 | 确定 |

购物车：留在购物车。确认订单：回购物车。

未勾选任何可售商品且车内并非「全部不可售」：Toast「请选择商品」。

**验收**

- 店打烊、勾选全是跟随门店的商品：立即下单拦截，正文为休息中文案
- 店打烊、勾选含快递 24 小时且窗口有效：可继续下单该部分；跟随门店的进失效
- 营业中、勾 3 件仅 1 件在自身窗口内：弹「部分商品不可售」，购物车正文以「可继续下单」结尾并进确认页；确认页再点「确认订单」必须再校验，正文以「可继续支付」结尾
- 确认页停留至门店打烊后再提交：跟随门店的商品被再次剔除或整单拦截，不得沿用进页时的可售结论
- 勾选全不可售：不跳确认页（确认页则回购物车）
- 未勾选的不可售商品不进本次失效专区

## 5. 判断一览（给研发 / 测试）

对「当前门店 + 当前商品 + 当前时刻」按顺序判断：

```
1. 解析该商品可售窗口
   （自定义 > 快递24h > 类目 > 门店营业 > 平台默认 > 08:00–22:00）
2. 当前是否在该窗口内？
   - 是：可售（店休息也照卖）
   - 否：不可售（店开着也可能不可售）
       · 首页 / 分类下架
       · 搜索 / 详情打「商品不可售」
3. 购物车【立即下单】：只校验勾选，按 2 拆部分 / 全部不可售
4. 确认订单提交：按当下时刻再走一遍 2，不复用第 3 步结论
5. 仅当「勾选全部不可售 + 全部跟随门店 + 店已休息」
   → 文案「当前门店休息中，商品暂不可售」
```

类目命中：商品类目路径等于、包含或分段等于已配类目名即命中；多条类目按配置顺序取第一条。

履约：快递 / 快递到店 / 快递配送 视为快递；自提 / 门店自提视为自提。仅快递享受「24 小时可售」。

## 6. 代采进货端（门店 APP）

门店进货没有「本店是否开门」的限制。店休息时，跟随门店 / 平台营业时间的货仍可进货。

**可售公式（进货）**

- 商品自定义 / 类目 / 快递 24 小时：仍按自身窗口，过了就不可售
- 只跟随门店或平台营业时间的商品：进货端视为可售，不因店休息拦截
- 不出现「当前门店休息中，商品暂不可售」

**交互与用户 APP 一致**

| 页面 | 不可售商品 |
|------|------------|
| 进货首页浏览、分类浏览 | 下架不展示 |
| 搜索、商品详情 | 展示 +「商品不可售」，加购 / 我要进货不可用 |
| 进货购物车点【结算】 | 当场校验勾选；全部不可售拦截并进失效专区；部分不可售剔除后进确认页，确认页展示「失效宝贝」 |
| 确认订单点【提交订单】 | 再按当下时刻校验一次，新不可售进失效专区，不沿用购物车结论 |

验收开关在进货页、详情、确认订单均可切全部 / 部分 / 全部不可售。

## 其它约定

- 时间粒度到分钟；结束时刻不含。
- 跨日开关同时作用于平台默认营业时间和类目可售时间；门店本店时段同样受该开关约束。
- 商品自定义一经保存，不被类目 / 履约 / 门店 / 平台变更自动改写，除非运营再改回跟随（清空自定义）。
- 可售判定以后端当前时间为准；前端提示为辅。
- 「商品不可售」与库存不足可共用部分下单文案，标识本身只表达可售窗口，不表达无货。
- 门店运营状态枚举仅「营业中 / 休息中」，后台门店档案与 C 端切换地址一致，不再使用「打烊」「运营中」。
