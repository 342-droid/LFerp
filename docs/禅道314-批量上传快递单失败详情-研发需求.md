## 一、背景与目标

### 1.1 背景

运营在零售订单列表用 Excel / CSV **批量上传快递单号**。部分行导入失败后，现有失败详情只有：

| 行号 | 字段 | 错误信息 |
|------|------|----------|
| 1 | orderNo | 订单状态不允许上传 |

问题：

1. 只有原文件行号和技术字段名（如 `orderNo`），对不上业务单据。
2. 看不到这笔失败对应的**订单号、商品、物流公司、物流单号**。
3. 无法从失败详情精确定位该笔订单，只能回头翻导入文件或到列表里猜。

用户需求正文几乎只有两张图，文案为「参考」。

- **图 1（现状问题）**：失败结果只有「行号 / 字段 / 错误信息」。
- **图 2（参考目标）**：失败结果是一张可筛选的明细表，列含订单编号、物流名称、物流单号、失败原因；示例失败原因：「该订单下存在申请退款中的商品，请先处理退款申请！」。

标题在参考图之外，还明确要求展示 **商品名称**。

### 1.2 目标

批量上传快递单只要存在导入失败行，失败详情必须能**直接定位到那一单、那一件商品、那条物流**，列至少包含：

**订单号、商品名称、物流名称、物流单号、失败原因**

失败原因用业务中文，不用英文字段名。

| 失败行字段 | 见第三节 |

### 2.2 不做（本需求不扩）

- 不改导入模板列结构（仍为：订单号、商品名称、规格、物流单号）。
- 不改「何种订单状态允许上传」等业务校验本身，只改失败时**怎么把失败讲清楚**。
- 批量删除快递单的失败详情不在本需求内（标题仅覆盖上传）。
- 不改列表筛选、导出。

## 三、失败详情规格

### 3.1 列定义（必须）

按用户需求标题 5 列出结果文件。参考图少「商品名称」，本需求以标题为准补上。

| 列名（结果文件表头） | 取值 | 说明 |
|----------------------|------|------|
| 订单号 | 导入行上的订单号 | 参考图写作「订单编号」，结果文件统一用「订单号」，与导入模板一致 |
| 商品名称 | 导入行上的商品名称 | 标题明确要求；同单一商品一行 |
| 物流名称 | 该行对应的物流公司 | 模板无此列时：能识别则写识别结果（如按单号推断的「顺丰快递」）；识别不出则空，**不得用字段名凑数** |
| 物流单号 | 导入行上的物流单号 | 原样带出，便于对照导入文件 |
| 失败原因 | 本行失败的业务原因 | 中文整句，见 3.3 |

不要求再输出：行号、英文字段名（`orderNo` 等）、技术堆栈。

可选加列（不加也不挡验收）：规格。本需求不强制。

### 3.2 行规则

1. **一行导入失败 = 结果文件一行**。同一订单多商品失败，拆成多行，商品名称不同。
2. 导入成功、重复跳过（四者均一致已存在）**不进失败详情**。
3. 必填缺失、单号不合法、订单不存在、订单状态不允许上传、商品在退款中等，**都算失败**，都进详情。
4. 某字段空导致失败时，该列仍尽量带出已填内容；空列留空，不要写 `-` 或 `null`。
5. 部分成功：汇总里同时报成功数和失败数，失败详情只含失败行。

### 3.3 失败原因（示例，实现按实际校验对齐话术）

| 场景 | 失败原因（对运营可见） |
|------|------------------------|
| 订单当前状态不允许上传快递单 | 订单状态不允许上传 |
| 订单下有退款中商品 | 该订单下存在申请退款中的商品，请先处理退款申请！ |
| 订单号空 | 订单号不能为空 |
| 订单号在系统中不存在 | 未找到该订单 |
| 商品名称 / 规格空或不匹配 | 未匹配到该订单下的商品（商品名称 / 规格） |
| 物流单号空 | 物流单号不能为空 |
| 物流单号格式不合法 | 物流单号格式不正确 |
| 文件列缺失、整行无法解析 | 导入数据不完整 |

原则：写「为什么这单过不了」，不写「orderNo 校验失败」。

### 3.4 结果文件形态

对齐参考图 2：

- Excel 或 CSV 均可，表头可筛选。
- 文件名建议：`批量上传快递单_失败详情_yyyyMMddHHmmss.csv`（或 `.xlsx`）。
- 有失败才提供下载；全部成功只给成功提示，不强制出空文件。

交互建议（原型可先做轻量版）：

1. 关闭上传弹窗后 toast：`上传完成：成功 N，失败 M`（M>0 时不可只报成功）。
2. M>0 时同时触发失败文件下载，或弹窗内出现「下载失败详情」。
3. 不得只给「行号 + 字段 + 错误信息」那种技术表。

## 四、现有原型缺口（对照用，不写进禅道也可）

当前 `js/order-proxy-express.js` 批量上传结束后只 toast 计数（新增 / 合并 / 跳过重复 / 无效），**没有失败明细、不能下载、无效行没有原因和业务字段**。本需求补的就是这一块。

---

## 五、验收标准

1. 批量上传快递单存在失败行时，能拿到失败详情（下载或页内表）。
2. 详情列包含且仅需验收这 5 列：**订单号、商品名称、物流名称、物流单号、失败原因**。
3. 打开失败详情，不对照原文件行号，也能找到是哪一单、哪个商品、哪条物流。
4. 失败原因是中文业务句，不出现 `orderNo` 等英文字段名作为「字段」列。
5. 不再提供「行号 / 字段 / 错误信息」作为唯一失败结果。
6. 全部成功时，不出现失败详情或失败文件为空可接受。
7. 参考图中的退款中场景：失败原因能表达「请先处理退款申请」这类业务含义（话术可与现网校验文案对齐）。
