一、背景

系统主路径是先销后采：用户可以先付钱，货再采购到仓、到店。代采、商城、多场直播、同仓多家门店共用一份配送仓库存。零售快递到家经常供应商直发，仓里可以没有实物。

选品库不再单独做库存统计。运营在各渠道编辑商品 → 售卖规格配置里看现货、配可售、展开仓店明细。


二、术语

仓实物         仓储按配送仓维护的在库数量。入库加、核销扣。直发可以没有这项。
现货预占       已支付、货还在仓里、用户还没到手。扣剩余可售，也扣仓可用现货。
预售预占       已支付、货还没到仓（或直发待发）。不扣仓可用现货，也不进仓店表「剩余可售」列；下单时要扣还能卖。
总预占         现货预占 + 预售预占。只做统计，不拿去减仓实物。
仓可用现货     max(0, 仓实物 − 现货预占)。现货段从这里出。
仓可售         SKU 可售配置摊到该仓的上限。
剩余可售       编辑商品仓店表的列：max(0, 仓可售 − 现货预占)。直播本场配额从这里切。
还能卖         下单校验：max(0, 仓可售 − 现货预占 − 预售预占)。不够则整行拒单。
直发           供应商直接发给用户，不经过配送仓实物账。

仓店表把预售预占单独成列，所以剩余可售只减现货预占。用户再买时，系统还要减预售预占，得到还能卖。两个数都要保留。


三、账本维度

1. 唯一账本：SKU × 配送仓。
2. 门店只继承所属仓。同仓门店看到同一份现货，不按门店再拆一套账。
3. 代采 / 商城 / 直播场次在预占上记渠道，方便对账，加减仍落在同一仓。
4. 一单多行按行拆现货 / 预售；整单履约状态仍按订单截单规则。


四、可售怎么配（原型）

入口：代采商品列表 / 商城商品列表 → 编辑商品 → 售卖规格配置；直播排品编辑同一区块。

现货库存                 只读。各配送仓实物之和。
可售 · 按现货库存        填百分比。100% = 取现货；>100% 多卖的部分走预售预占。
可售 · 按具体数量        填全网上限，再按各仓实物占比分摊。
可售结果                 只读。按上面配置算出来的件数。
本场售卖配额             仅直播可改。不超过各仓剩余可售合计（含本场已占）。保存只作用于本场。
仓店库存                 只读。默认收起，一行看现货合计 · 可售合计 · N 个仓；展开看各仓现货 / 可售 / 总预占 / 现货预占 / 预售预占 / 剩余可售，以及共享门店。售卖范围选了门店时，表只留对应仓和店。改百分比时合计跟着变，展开状态保留。

预占加减过程不在抽屉里逐步播放。页面只展示算完的数。

仓可售（按现货库存）= round(仓实物 × 百分比 / 100)
仓可售（按具体数量）= 按各仓实物占比分摊全网固定上限
仓可用现货 = max(0, 仓实物 − 现货预占)
剩余可售   = max(0, 仓可售 − 现货预占)          ← 仓店表列、直播配额上限
还能卖     = max(0, 仓可售 − 现货预占 − 预售预占) ← 下单校验


五、预占何时增加（图 1 · 支付拆段）

唯一正向入口：支付成功。待支付、关未付、草稿都不占货。

一笔支付、一个商品行、数量 Q，落到一个配送仓（按收货门店找仓；直发不占仓可用现货）：

  还能卖 = 仓可售 − 现货预占 − 预售预占
  走现货 = min(Q, 仓可用现货, 还能卖)
  走预售 = Q − 走现货
  走现货 + 走预售 < Q → 整行拒单

走现货：现货预占 +该数（仓可用现货、剩余可售、还能卖都减）。
走预售：预售预占 +该数（还能卖减；仓可用现货、剩余可售不变）。

一笔单可以同时拆出两段，不必先勾现货 / 预售。百分比溢出的那一截只进预售段。
直发：仓可用现货按 0 算，Q 全部进预售预占（还能卖仍要够）。
直播：先扣本场剩余配额（配额本身不超过剩余可售），不够则拒单；扣下的数量再按上面拆段。


六、履约怎么走（图 2 · 履约判定）

不按商品类型写死「现货品 / 预售品」。看支付当时这个仓有没有可用现货。

零售 × 快递到家
  现货段：从该仓发、且仓有可用现货。核销看签收；仓发扣仓实物。
  预售段：供应商直发、仓无实物、或可售溢出。直发核销只清预占，不扣仓实物。

零售 × 门店自提
  现货段：所属仓有可用现货（含已到店）。核销看提货完成。
  预售段：先销后采、等到货。到货后按图 4 转化，再按现货段核销。

代采 × 平台配送 / 快递配送
  账在配送仓。平台配送核销看配送完成；快递配送核销看签收。

直播 × 快递 / 自提
  先占本场配额，再按仓拆段。核销与零售对应履约相同。

活动商品、积分兑换走同一套加减，不另开库存池。


七、生命周期（图 3 · 库存账怎么走）

待支付 → 支付成功（加预占）→ 截单（不改库存）→ 出库/待提（预占仍在）→ 核销（清预占；仓发扣实物）

入库可插在支付之后、核销之前（图 4）。取消（未到手）从支付后任意点原路退占。

待支付
  不占货。关单、超时无库存动作。

支付成功
  按第五节加预占。这是预占增加的唯一入口。

截单
  到点 / 支付后 / 订货汇总人工 / 提前发货补截，都不加减预占。

入库 / 仓收 / 店收（图 4 · 入库转化）
  仓实物 +N。
  转化 = min(N, 该仓预售预占)
  预售预占 −转化；现货预占 +转化。
  转化后货已在仓，但仍被未完成的单锁着，不会马上变成别人能下的仓可用现货。

取消 / 售中退款（未到手）
  按该行当时类型退回。
  现货预占退回：仓可用现货、剩余可售、还能卖加回。
  预售预占退回：还能卖加回。
  已截单走售后审核，库存仍按本条退，不靠释放截单。

发货 / 出库 / 到店待提
  用户还没到手，预占不消失。直发没有仓实物可扣。
  本期口径：仓发也等到核销再扣实物，出库只改履约状态，避免在途扣两次。

核销（签收 / 提货 / 配送完成）
  现货预占、预售预占按该行清掉。
  非直发且绑着仓的，仓实物 −Q。
  还能卖不加回（货已卖出）。

售后回库
  仅实物退回仓时仓实物 +回库数。不自动加回可售；可售仍跟 SKU 配置和当前实物走。


八、和订货、截单的关系

· 未转化的预售预占，才作为门店订货汇总的需求；现货预占不再进订货需求。
· 货已在店、不走订货单的商品，支付时优先走现货段。标签怎么维护另文，本文只认这个结果。
· 任何截单来源都不重复加预占。提前发货若支付时已占过，出库走「预占仍在」，核销再清。


九、原型页面

代采 / 商城 · 编辑商品
  售卖规格每个 SKU 一张卡：现货只读，可售下拉两项。
  仓店库存默认收起；点展开看表。售卖范围选了门店后，表只留对应仓。

直播 · 排品编辑
  现货、可售只读。本场配额可改，不超过剩余可售。同一套仓店表。保存不回写中央库。

已下线
  商品侧栏不再放库存统计。旧地址 MDM/mdm_product_stock.html 只留说明和跳转。


十、冻结口径

1. 预占只在支付成功增加。
2. 预占分现货 / 预售两类；仓可用现货只减现货预占。
3. 仓店表 / 直播配额用剩余可售（只减现货预占）；下单用还能卖（两类预占都减）。
4. 一笔支付可以同时拆出现货段和预售段。
5. 账本在配送仓，不按门店另建现货账。
6. 直发可以没有仓实物；核销只清预占。
7. 核销才扣仓实物（本期）；出库不扣第二次。
8. 截单不碰库存账。
9. 页面只展示结果；过程在底层。
