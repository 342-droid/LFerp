## 业务范围

| 在范围内 | 不在范围内 |
| --- | --- |
| 编辑商品：现货只读、本渠道可售 / 预占 / 剩余可售、仓店表现货 | 页面再拆两类预占 |
| 可售：按现货库存 / 按具体数量 | 选品库再做库存统计总表 |
| 先采后销 + 先销后采，同一套渠道预占 | 在页面播放预占加减过程 |
| 支付加本渠道预占；按履约节点释放；取消退占 | 改订单支付跳转、核销详情交互 |

## 一、背景与目标

代采、商城、多场直播共用配送仓现货。仓现货既有先采后销，也有先销后采。运营在各渠道编辑商品 → 售卖规格配置看现货、配可售、看本渠道预占。

可售和预占必须在同一维度，才能干净地算剩余可售。这个维度是放单渠道：代采 / 商城 / 直播 / 零售。各渠道各自独立，不摊到仓，不加总。

预占对外只叫预占库存。支付成功后本渠道 +Q，按履约节点本渠道 −Q。履约方式只决定何时释放，不再把预占记到门店、配送仓或直发账。

| 进销方式 | 货在哪 | 支付 | 入库 |
| --- | --- | --- | --- |
| 先采后销 | 仓里已有实物 | 本渠道预占 +Q | 仓实物 +N，预占不动 |
| 先销后采 | 仓里还没有，或可售超出实物 | 本渠道预占 +Q | 仓实物 +N，预占仍锁着，直到履约节点释放 |
| 直发 | 不经过仓实物账 | 本渠道预占 +Q | 不加仓实物 |

## 二、术语

| 术语 | 定义 |
| --- | --- |
| 放单渠道 | 下单占用可售的渠道：代采 / 商城 / 直播 / 零售。可售、预占都记在这里。 |
| 仓实物 / 现货 | 仓储按配送仓维护的在库数量。入库加。直发可以没有。 |
| 可售库存 | 本渠道该 SKU 的可卖上限。代采页=代采可售，商城页=商城可售。直播不配可售：页上只读，按现货算出，用来卡本场配额。没有中央可售账本。 |
| 预占库存 | 本渠道已支付、尚未按履约节点释放的数量。与可售同一维度。页面只展示这一个数。 |
| 剩余可售 | max(0, 本渠道可售 − 本渠道预占)。直播本场配额从这里切。 |
| 仓可用现货 | 仓实物。预占不锁仓。直发不碰仓实物。 |

## 三、账本维度

| 项 | 规则 |
| --- | --- |
| 现货 | SKU × 配送仓。仓储按仓维护，仓店表只展示这一列 |
| 可售库存 | SKU × 放单渠道。写在规格卡 |
| 预占库存 | SKU × 放单渠道。写在规格卡，与可售并列 |
| 剩余可售 | 同一渠道上的减法，不跨渠道、不摊到仓 |
| 门店现货 | 继承所属仓，不另建现货账，不另建预占账 |

不再按「门店预占 / 仓预占 / 直发预占」建账。履约节点只用来触发本渠道预占 −Q。

## 四、可售、预占与仓店表（原型）

| 字段 | 谁改 | 规则 |
| --- | --- | --- |
| 现货库存 | 只读 | 各配送仓实物之和 |
| 可售 · 按现货库存 | 代采 / 商城可改 | 填百分比。100% 取现货；大于 100% 多卖的部分仍记入本渠道预占 |
| 可售 · 按具体数量 | 代采 / 商城可改 | 本渠道该 SKU 的件数上限，不按仓分摊、不与其它渠道加总 |
| 预占库存 | 只读 | 本渠道该 SKU 已支付未释放的数量 |
| 剩余可售 | 只读 | 本渠道可售 − 本渠道预占 |
| 本场售卖配额 | 仅直播可改 | 不超过剩余可售（含本场已占）。保存不回写中央商品库 |
| 仓店现货 | 只读 | 默认收起。列：配送仓 / 门店 / 现货。不展示可售、不展示预占 |

| 公式 | 计算 |
| --- | --- |
| 本渠道可售（按现货） | round(各仓现货合计 × 百分比 / 100) |
| 本渠道可售（按数量） | 运营填写的本渠道件数上限 |
| 本渠道预占 | 该放单渠道已支付未释放之和 |
| 剩余可售 | max(0, 本渠道可售 − 本渠道预占) |
| 仓可用现货 | 仓实物。预占不扣仓 |

## 五、预占何时加减

唯一加预占入口：支付成功。待支付、关未付、草稿、截单都不占货。

支付数量 Q：本渠道剩余可售不够则整行拒单；够则本渠道预占 +Q。直播先扣本场配额。

| 履约 | 走仓储？ | 预占记在哪 | 何时本渠道预占 −Q |
| --- | --- | --- | --- |
| 零售 × 门店自提 | 货在店/仓 | 零售渠道 | 用户核销后（同时扣仓实物） |
| 零售 × 快递到家 | 不走仓储，供应商直发 | 零售渠道 | 供应商发货后 |
| 商城 × 快递 / 自提 | 快递不走仓储 | 商城渠道 | 快递：供应商发货后；自提：用户核销后 |
| 代采 × 平台配送 | 仓发到店 | 代采渠道 | 门店收货后 |
| 代采 × 快递配送 | 不走仓储，供应商发到店 | 代采渠道 | 门店收货后（收尾） |
| 直播 × 自提 | 同零售自提 | 直播渠道 | 用户核销后 |
| 直播 × 快递 | 不走仓储，供应商直发 | 直播渠道 | 供应商发货后 |

零售/直播快递供应商一发货就减，且不进仓储。代采配送、代采快递都以门店收货收尾。取消（未释放前）原路退本渠道预占。

## 全链路库存加减

| 节点 | 仓实物 | 本渠道预占 | 仓可用现货 | 剩余可售 |
| --- | --- | --- | --- | --- |
| 待支付 / 关未付 | — | — | — | — |
| 支付成功 | — | +Q | — | −Q |
| 支付不够 · 拒单 | — | — | — | — |
| 截单 | — | — | — | — |
| 入库 / 备货到仓 | +N | — | +N | 随可售配置 |
| 取消（尚未释放） | — | −Q | — | +Q |
| 零售自提 · 用户核销 | −Q | −Q | −Q | 不加回 |
| 零售/商城/直播快递 · 供应商发货 | —（不走仓储） | −Q | — | 不加回 |
| 代采配送 · 门店收货 | — | −Q | — | 不加回 |
| 代采快递 · 门店收货 | — | −Q | — | 不加回 |
| 售后回库 | +回库 | — | +回库 | 不自动加 |

图 A · 全链路库存加减

```mermaid
flowchart TD
  n0[待支付 各账不变] --> n1{支付成功}
  n1 -->|本渠道剩余可售够| add[本渠道预占加Q]
  n1 -->|不够| x[整行拒单 各账不变]
  add --> n2[截单 各账不变]
  n2 --> n3[入库 仓实物加N 预占不动]
  n2 --> n4[取消 本渠道预占减Q]
  add --> n5{履约释放本渠道预占}
  n5 -->|零售自提 用户核销| a[零售预占减Q 仓实物减Q]
  n5 -->|快递直发 供应商发货| b[该渠道预占减Q]
  n5 -->|代采配送或快递 门店收货| c[代采预占减Q]
```

## 六、冻结口径

| 议题 | 决策 |
| --- | --- |
| 可售 / 预占维度 | 同一维度：SKU × 放单渠道 |
| 预占展示 | 规格卡只展示预占库存，不按仓/店拆 |
| 预占何时加 | 只在支付成功，加到下单那个放单渠道 |
| 预占何时减 | 按履约节点从该渠道减 |
| 零售自提 | 记零售渠道；用户核销后 −Q，并扣仓实物 |
| 零售/商城/直播快递 | 不走仓储；记对应渠道；供应商发货后 −Q |
| 代采配送 / 代采快递 | 都记代采渠道；门店收货后 −Q |
| 截单 | 不碰库存账 |
| 仓店表 | 只展示现货 |
| 可售归属 | 本渠道该 SKU，各自独立 |
| 剩余可售 | 本渠道可售 − 本渠道预占 |

## 七、验收

| # | 验收项 |
| --- | --- |
| 1 | 代采 / 商城 / 直播编辑：规格卡有现货、可售、预占、剩余可售；都是本渠道该 SKU |
| 2 | 代采页预占 ≠ 商城页预占 ≠ 直播页预占 |
| 3 | 仓店表列为配送仓 / 门店 / 现货，没有预占列 |
| 4 | 可售在规格卡，不是仓字段、不是多渠道加总 |
| 5 | 待支付不加预占；支付成功本渠道预占 +Q；不够拒单 |
| 6 | 核销 / 发货 / 门店收货，从对应渠道预占 −Q |
| 7 | 截单不改预占；取消（未释放前）退该渠道预占 |
