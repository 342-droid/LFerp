版本：v1.0

用途：研发实现 / 对账口径；不在原型页面单独做库存台账
原型露出：代采 / 商城 / 直播「编辑商品 → 售卖规格配置」只展示仓/店现货、可售、预占结果，不展示本规则过程

一、在原图上改了什么

原图是单店、单池：下单扣可售或现货，预占 +1；到货后「总库存 > 预占」才长出现货；核销扣预占（预售同时扣总库存）。

我们这边不是单店池：

1. 库存池在配送仓。同仓多家门店、代采 / 商城 / 多场直播看同一仓数字，不按门店再拆一份额外现货。
2. 系统主路径是先销后采。仓里可能还没有货，订单先占可售。
3. 同一 SKU 可以同时卖现货和预售。可售允许按现货百分比溢出（100% = 取现货，>100% 多卖的部分走预售预占）。
4. 零售快递到家经常是供应商直发，仓里没有总库存，不能套「总库存 − 预占 = 现货」。
5. 预占从支付成功开始加，不从待支付下单开始加（待支付可关单，不占货）。
6. 截单只改履约承诺，不加、不减预占。


二、术语（和原图对照）

原图「总库存」     → 仓实物库存。仓储按配送仓维护，入库加上、出库核销扣掉。直发可以没有这一项。
原图「现货库存」   → 仓可用现货 = max(0, 仓实物 − 现货预占)。给现货单下单用。
原图「可售库存」   → SKU 配置出来的可卖上限（按现货×百分比，或按具体数量），再按仓现货占比摊到各仓。
原图「预占库存」   → 已支付、用户还没到手的量。我们拆成两类，不能混成一个数去减现货。
  · 现货预占     锁已经在仓里的货。扣还能卖，也扣仓可用现货。
  · 预售预占     锁未来到货 / 直发待发。扣还能卖，不扣仓可用现货。
原图「无现货」     → 仓实物 ≤ 现货预占，或直发根本没有仓实物。
还能卖             → 仓可售 − 现货预占 − 预售预占。直播本场配额从这里切。
总预占             → 现货预占 + 预售预占（统计用，不直接参与现货公式）。


三、维度

1. SKU × 配送仓 是唯一库存账本。门店只继承所属仓，不单独做一套现货账。
2. 预占按渠道记账（代采 / 商城 / 直播场次），方便对账，加减仍落在同一仓。
3. 一单多行：按行判断现货还是预售，互不影响；整单状态仍按订单截单规则走。


四、数量公式（按仓）

仓可售
  · 按现货库存：round(仓实物 × 百分比 / 100)
  · 按具体数量：按各仓实物占比分摊全网固定上限

仓可用现货 = max(0, 仓实物 − 现货预占)
还能卖     = max(0, 仓可售 − 现货预占 − 预售预占)

注意：还能卖可以大于仓可用现货（百分比 >100% 或固定数量大于实物）。多出来的只能走预售预占。
仓可用现货只减现货预占，不减预售预占——这是对原图「总库存 − 预占 = 现货」的改写：原图那个预占不含未来预占。


五、预占何时增加

触发：支付成功（待支付 → 待接单，或支付后截单直接待发货）。
不加预占：待支付、关闭未付、草稿。

一次支付、一个商品行、数量 Q，落在一个配送仓（按收货门店找仓；直发按发货仓或虚拟直发仓）：

  还能卖 = 仓可售 − 现货预占 − 预售预占
  走现货 = min(Q, 仓可用现货, 还能卖)
  走预售 = Q − 走现货

  走现货 > 0：现货预占 +走现货（仓可用现货、还能卖同步减少）。
  走预售 > 0：预售预占 +走预售（还能卖减少，仓可用现货不变）。

走现货 + 走预售 < Q 则整行拒单（可售不足）。

这就是原图「可同时现货 + 预售」在我们仓上的落法：一笔单可以拆成两段预占，不必用户先选预售。百分比溢出的那一截，只会进预售段。

直播：先扣本场剩余配额，配额不足拒单；扣下的数量再按上面拆现货 / 预售。配额和其他场、代采、商城共享同一仓还能卖。


六、履约怎么对应原图那棵树

原图：自提/配送分门店现货和好物预售；快递只写产地直发。

我们按渠道 × 履约，不按「门店现货 / 好物」商品类型写死。下单当时仓里有没有可用现货，决定走哪一段。

零售 × 快递到家
  · 仓里有可用现货且从该仓发：现货段（现货预占）。
  · 供应商直发、仓无实物、或可售溢出：预售段（预售预占）。直发核销不扣仓总库存。

零售 × 门店自提
  · 所属仓有可用现货（含已到店、不走订货单的货）：现货段。
  · 先销后采、等订货到仓/到店：预售段。到货后预售预占转现货预占，现货公式才出现货。

代采 × 平台配送 / 快递配送
  · 与自提相同，账在配送仓。平台配送核销看配送完成；快递配送核销看签收。

直播 × 快递 / 自提
  · 先占本场配额，再按仓拆现货 / 预售。和其他渠道共享该仓。

活动商品、积分兑换：同一套加减，不另开库存池。


七、生命周期（只改账，不改页面）

N0 待支付
  不占货。关单、超时无库存动作。

N1 支付成功
  按第五节加预占。这是预占增加的唯一正向入口。

N2 截单（到点 / 支付后 / 订货汇总人工 / 提前发货补截）
  不加减预占。只改订单截单状态。

N3 采购入库 / 仓收货 / 店收货
  仓实物 +入库数。
  转化 = min(入库数, 该仓预售预占)
  预售预占 −转化；现货预占 +转化（货到了但仍被未完成的单锁着）。
  转化后：仓可用现货 = max(0, 仓实物 − 现货预占)。
  对应原图「总库存 > 预占才长现货」：这里的预占只算现货预占。

N4 取消 / 售中退款（用户还没到手）
  按该行当时的预占类型原路退回。
  已转化成现货预占的，退现货预占，仓可用现货和还能卖加回。
  仍是预售预占的，退预售预占，还能卖加回。
  已截单的取消走售后审核，库存仍按本条退，不靠「释放截单」。

N5 发货 / 出库（快递已发出、配送已出仓、自提到店待提）
  预占不在这一步消失。货还在途或待提，仍算「用户未到手」。
  直发出库：没有仓实物可扣，只保持预售预占。
  仓发出库：仓实物可以在出库时先扣，或等到核销再扣，生产必须写死一种。
  本期口径：仓发与直发都等到核销再扣仓实物，避免在途把总库存减两次。出库节点只打履约状态。

N6 核销（签收 / 提货完成 / 配送完成）
  对应原图核销。
  现货预占 −Q；若该行还绑着仓实物，仓实物 −Q。
  预售预占 −Q（直发或尚未入库就核销的预售单）；直发不扣仓实物。
  总预占下降。还能卖不加回（货已卖出）。

N7 售后回库
  仅实物退回仓时：仓实物 +回库数。不自动加回可售占用；可售仍跟 SKU 配置和当前实物走。


八、和订货、截单的关系

· 预售预占 > 0 且商品要走订货单：门店订货汇总按未转化的预售预占看需求，不按现货预占。
· 不走订货单的商品：默认按现货路径（货已在店/在仓），支付时优先走现货预占。
· 人工截单、到点截单、支付后截单：都不重复加预占。
· 提前发货补截单：若支付时已加过预占，发货仍走 N5，核销走 N6。


九、冻结口径

1. 预占只在支付成功增加。
2. 预占分现货 / 预售两类；现货公式只减现货预占。
3. 一笔支付可以同时拆出现货段和预售段。
4. 账本在配送仓，不按门店另建现货账。
5. 直发可以没有仓实物；核销只清预占。
6. 核销才扣仓实物（本期）；出库不扣第二次。
7. 截单不碰库存账。
8. 本规则不在原型单独做页面。
