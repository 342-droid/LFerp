## 1. 需求描述

### 1.1 基础信息-仓库，出库页签下增加参数：分拣交互方式

分拣交互方式：下拉框，枚举：任务式，列表式，默认=列表式

原型页面：`SCM/warehouse.html`（仓库编辑-仓库参数-出库）

### 1.2 移动端分拣模块增加列表式交互

* 判断条件：当前登录仓库，仓库参数：分拣交互方式=列表式时，进入 APP-分拣模块，交互改为列表式

* 分拣交互方式=任务式时，仍走原任务式分拣（扫描商品 / 门店 / 线路领取，逐条扫描储位、商品后确认）

* APP-分拣-列表式交互原型：`SCM/app_obd_sorting_list.html`

### 1.3 逻辑说明

#### 1.3.1 选择分拣方式

进入列表式分拣后，先选择分拣方式，再进入对应任务列表：

* 按商品分拣：同一商品投到各门店储位，任务按商品聚合
* 按门店分拣：站在一个门店格，投完该店商品，任务按门店聚合
* 按线路分拣：按线路清场，任务按线路聚合；执行列表按门店分组

#### 1.3.2 分拣任务查询

* 顶部查询框：扫描 / 输入后即时筛选下方卡片

  * 按商品分拣：支持商品编码、商品条码、商品名称

    * 查询优先级1：商品编码
    * 查询优先级2：商品条码
    * 查询优先级3：商品名称，注意，名称是模糊匹配

  * 按门店分拣：支持门店编码、储位编码

    * 查询优先级1：门店编码
    * 查询优先级2：储位编码

  * 按线路分拣：支持线路编码、线路名称

    * 查询优先级1：线路编码
    * 查询优先级2：线路名称，注意，名称是模糊匹配

* 页签：未完成、已完成

  * 未完成：仅查询当前分拣方式下，仍存在可作业明细的聚合任务

    * 可作业明细：分拣单记录未完成；分拣人为空、=当前登录账号，或分拣单状态=分拣中且分拣人≠当前账号，均可展示
    * 他人分拣中的任务允许领取，点击卡片时二次确认

  * 已完成：仅查询当前分拣方式下，聚合范围内全部明细均已完成（含异常完成）的任务；仅展示当天已完成数据，历史数据请去电脑端查看
  * 已完成页签展示提示：「仅显示当天已完成数据，历史数据请去电脑端查看」
  * 已完成卡片不可再次领取

* 任务卡片状态标签

  * 未完成且分拣人为空：初始
  * 未完成且已有分拣人（当前账号或其他人）：分拣中
  * 已完成：已完成

* 按商品分拣-任务卡片

  * 标题：商品名称（有商品图片时展示缩略图，点击可查看大图；无图显示「暂无图片」）
  * 状态标签：分拣单聚合状态
  * 商品编码：分拣单表的商品编码
  * 商品条码：分拣单表的商品条码
  * 商品规格：分拣单表的商品规格
  * 待分数量 / 已分数量：当前页签下，该商品可展示明细的数量合计+单位
  * 门店数：当前页签下，该商品可展示明细涉及的门店数
  * 分拣人：当前页签下已领取明细的分拣人，多人用顿号拼接；无人则展示「-」

* 按门店分拣-任务卡片

  * 标题：门店编码-门店名称
  * 状态标签：分拣单聚合状态
  * 目的储位：储位编码-储位名称
  * 待分数量 / 已分数量：当前页签下，该门店可展示明细的数量合计，单位为件
  * 品项数：当前页签下，该门店可展示明细涉及的 SKU 数
  * 分拣人：当前页签下已领取明细的分拣人，多人用顿号拼接；无人则展示「-」

* 按线路分拣-任务卡片

  * 标题：线路编码-线路名称
  * 状态标签：分拣单聚合状态
  * 门店数：当前页签下，该线路可展示明细涉及的门店数
  * 品项数：当前页签下，该线路可展示明细涉及的 SKU 数
  * 待分数量 / 已分数量：当前页签下，该线路可展示明细的数量合计，单位为件
  * 分拣人：当前页签下已领取明细的分拣人，多人用顿号拼接；无人则展示「-」

* 空态

  * 未完成无数据：暂无待分拣任务
  * 已完成无数据：暂无已完成任务

#### 1.3.3 领取任务

* 在未完成页签点击任务卡片，领取该聚合维度下未完成的全部分拣明细

  * 分拣人为空的明细：更新分拣人=当前登录账号
  * 分拣人已是当前登录账号的明细：继续作业，不重复领取
  * 分拣单状态=分拣中，且分拣人≠当前账号：允许领取，弹出二次弹窗「当前分拣任务已被「XXX」领取，确认要领取并作业吗？」

    * 取消：关闭弹窗，不领取
    * 确认：将对应未完成明细的分拣人更新为当前登录账号，提示「领取成功」，进入分拣任务执行页

  * 领取成功后提示「领取成功」，进入分拣任务执行页
  * 无可领取明细时提示「没有可领取的分拣行」

* 领取后的后续单据状态处理，同任务式分拣：对应分拣单状态=分拣中；对应波次下出库单状态=开始分拣，开始分拣时间=当前时间

#### 1.3.4 分拣任务执行

* 页面标题：分拣任务执行

* 顶部汇总区

  * 按商品分拣：展示商品图片、商品名称、商品编码、商品条码、商品规格
  * 按门店分拣：展示门店编码-门店名称、目的储位（储位编码-储位名称）
  * 按线路分拣：展示线路编码-线路名称、门店数、品项数
  * 进度条：已分 合计已分拣量 / 应分 合计应分拣量

* 查询扫描框：用于查询定位下方明细，不作为完成分拣的强制校验

  * 按商品分拣，占位文案：门店编码/门店名称/储位编码

    * 查询优先级1：门店编码
    * 查询优先级2：门店名称，注意，名称是模糊匹配
    * 查询优先级3：储位编码
    * 未找到时提示「未找到匹配的门店或储位」

  * 按门店分拣、按线路分拣，占位文案：商品编码/条码/名称

    * 查询优先级1：商品编码
    * 查询优先级2：商品条码
    * 查询优先级3：商品名称，注意，名称是模糊匹配
    * 未找到时提示「未找到匹配的商品明细」

  * 定位规则

    * 精确匹配优先于模糊匹配
    * 同等匹配时，优先定位未完成明细
    * 定位后滚动到对应明细并高亮；未完成明细同时选中
    * 查询框为空时提示「请先扫描/输入」

* 明细卡片-按商品分拣

  * 标题：门店编码-门店名称
  * 状态标签：分拣中 / 已完成 / 异常
  * 目的储位：储位编码-储位名称
  * 应分拣数量：分拣单表的应分拣量+单位
  * 分拣数量：可编辑

    * 进入页面时自动填充，填充值=应分拣数量-已分拣数量
    * 已完成 / 异常明细仅展示已分拣数量，不可再编辑

  * 未完成明细展示「完成」按钮

* 明细卡片-按门店分拣

  * 标题：商品名称（有商品图片时展示缩略图，点击可查看大图）
  * 状态标签：分拣中 / 已完成 / 异常
  * 商品编码、商品条码、商品规格
  * 应分拣数量、分拣数量、完成按钮：规则同按商品分拣

* 明细卡片-按线路分拣

  * 先按门店分组，分组标题仅展示：门店编码-门店名称
  * 分组内商品卡片：

    * 标题：商品名称（有商品图片时展示缩略图，点击可查看大图）
    * 状态标签：分拣中 / 已完成 / 异常
    * 商品编码、商品条码、商品规格
    * 目的储位：储位编码-储位名称
    * 应分拣数量、分拣数量、完成按钮：规则同按商品分拣

* 点击「完成」

  * 分拣数量为空、非整数或小于 0：提示「请输入有效的分拣数量」
  * 分拣数量 > 应分拣数量：提示「分拣量大于应分数量」，拦截
  * 分拣数量 = 应分拣数量：提示「分拣确认成功」，提交该明细分拣结果
  * 分拣数量 < 应分拣数量：弹出二次确认弹窗「任务异常登记后将触发异常处理，请确认是否登记」

    * 点击取消按钮：关闭弹窗，什么也不做
    * 点击确认按钮：提示「登记成功」，按实际分拣数量提交该明细，并标记为异常，触发异常处理流程，详见分拣异常处理

* 提交单条明细后的后续逻辑，同任务式分拣确认（更新分拣量、是否分拣、出库单明细已分拣量、库存规则 W006、包裹 / 包裹明细）

* 当前领取范围内全部明细均完成后，进入分拣完成页

  * 展示「分拣完成」
  * 点击确定，返回对应分拣方式的任务列表

* 当前领取范围内仍有未完成明细时，停留在执行页，刷新进度与明细状态
