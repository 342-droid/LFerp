# 【925】商品剩余库存操作类型梳理

依据：`docs/库存管理规则-v1.0-20260903.txt` 的 v1.6 渠道库存口径及 `js/order-stock-runtime.js`。本页对应商城、代采商品列表的“剩余库存”及“商品库存操作”原型；弹窗流水为演示数据，不代表已接入真实订单库存流水。

## 展示口径

- 库存按 SKU × 放单渠道分别计算；商城与代采不共用预占。剩余库存 = max(0，本渠道可售 − 本渠道预占)。
- 表格“变动”指本渠道**剩余库存**的变化，不是仓现货变化，也不是预占库存的变化。
- 快递一件代发未维护库存时显示“—”。不能仅凭“快递”履约方式判定不维护库存。

## 操作类型与节点

| 业务节点 | 库存操作类型 | 本渠道剩余变化 | 说明 |
| --- | --- | --- | --- |
| 首次设置本渠道可售 | 初始可售 | +配置数量 | 建立可售基数；正式流水须关联 SKU、渠道、配置单据 |
| 支付成功 | 支付成功预占 | −支付商品数量 | 本渠道预占增加；不足时拒单，各账不变 |
| 已支付订单在预占释放前取消 | 取消退占 | +取消商品数量 | 原路释放本渠道预占；重复取消不得再次退占 |
| 预占释放前售中退款成功 | 售中退款退占 | +退款对应数量 | 仅释放尚在预占中的数量；仅退运费、差价不改变商品数量 |
| 到达履约释放节点 | 履约释放预占 | 0 | 商城自提核销、商城快递供应商发货、代采配送或快递门店收货。预占减少，已售数量不回补剩余 |
| 入库且本渠道可售按现货计算 | 入库联动可售 | 依配置计算，可为正 | 仓实物增加；按具体数量配置可售时，本渠道剩余不因此自动增加 |
| 运营更改本渠道可售 | 可售调整 | 正或负 | 应展示变更前后可售及原因；不能把仓盘点直接当作渠道可售调整 |

## 不生成本渠道剩余变动流水的节点

待支付、未支付关单、支付失败、库存不足拒单、截单均不增加预占，因此不存在“未付款退回库存”的操作类型。售后回库增加仓现货，不自动增加本渠道剩余；履约释放后退款也不能再次退同一笔预占。正式操作类型仍须与订单、售后和仓储真实流水对接校验。

## 原型验收点

1. 商城、代采库存弹窗中不出现“下单预占”或把支付成功称为“支付扣减”。
2. 支付预占、取消退占、售中退款退占、履约释放、入库联动、可售调整的示例余额与列表剩余一致。
3. 未付款关单不展示“退回库存”；履约释放行展示剩余变动 0，并说明已售数量不回补。
4. 操作时间倒序、分页与 5 / 10 / 20 条切换可用。
