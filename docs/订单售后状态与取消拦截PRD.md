# 订单售后标识与取消拦截

## 背景

订单履约中用户可发起售后，当前有三类问题：

1. 售后未完结时，客户端 / 代采端 / PC 后台仍可取消整单，售后与关单互相覆盖，退款、补货无法闭环。
2. 订单列表只展示商品名和订单状态，运营无法直接判断商品是否在退款或补发。
3. 订单完成后后台仅有「查看」，客诉补开售后只能走线下或让用户自行申请，与「平台退款」割裂。

## 目标

- 任意端口取消订单时，若存在未完结售后，一律拦截并提示，不关单、不退款。
- 零售 / 代采列表：商品名展示与详情一致的售后标识。
- 订单完成后后台可「发起售后」，与「平台退款」共用售后单能力。

## 范围

**本期做**

- 取消订单拦截：客户端订单详情、进货（代采）订单详情、PC 零售订单、PC 代采订单
- 零售 / 代采列表：商品售后标识
- 订单完成后后台「发起售后」

**本期不做**

- 不改变各端「取消订单」按钮的展示规则（仍按原订单状态控制是否出现）
- 不扩展 C 端待自提页的取消入口
- 不在零售 / 代采列表增加「售后状态」列，也不增加「售后状态」筛选项

## 术语

| 术语 | 说明 |
|------|------|
| 未完结售后 | 售后未到达已完成、已取消、已拒绝（C 端对应成功 / 关闭 / 失败） |
| 售后标识 | 贴在商品名称上：退款中、部分退款、全额退款、补发中、已补发 |
| 平台退款 | 履约中（待收货 / 待提货）后台代开售后的入口文案 |
| 发起售后 | 订单完成后后台代开售后的入口文案，能力与平台退款相同 |

## 1. 取消订单拦截

用户已发起且未完结的售后单，任意端口取消整单均拦截。

### 1.1 拦截条件（P0）

同时满足以下条件时拦截：不关闭订单、不触发退款。

| 项 | 规则 |
|----|------|
| 售后类型 | 仅退款、退货退款、补货、换货 |
| 未完结（C 端） | 售后阶段不是「成功 / 关闭 / 失败」 |
| 未完结（B 端） | 售后状态不是「已完成 / 已取消 / 已拒绝」 |
| 作用端口 | 客户端订单详情、进货（代采）订单详情、PC 零售订单、PC 代采订单 |
| 判定维度 | 整单：该订单下任意一笔符合条件的售后未完结即拦截 |

**流程**

1. 用户 / 运营点击「取消订单」
2. 该订单是否存在未完结售后？
   - 是：弹拦截提示，结束
   - 否：弹原「确认取消」→ 确认后关单

**异常**：无订单号或查不到售后记录时，不拦截，按原逻辑取消。

**验收**

- 订单存在处理中售后时，上述任一端口点「取消订单」均被拦截
- 售后均已完结时，取消订单走原确认流程
- 拦截后订单状态不变

### 1.2 拦截提示（P0，各端文案一致）

拦截时弹出提示框，不进入「确认取消」二次确认。

| 元素 | 文案 |
|------|------|
| 主标题 | 无法取消订单 |
| 提示文案 | 当前订单存在处理中售后，暂无法取消订单。 |
| 按钮 | 好的 |

**验收**

- 客户端 / 进货端：单按钮弹窗，点「好的」或遮罩关闭，订单仍在原状态
- PC 零售 / 代采：同样标题、正文、仅「好的」，不出现「确认取消」
- 售后完结后再点取消，出现原「确认取消订单」弹窗

C 端待自提本身无取消按钮，本期不新增入口。验收以有取消按钮的状态为准（待付款、截单前待发货；PC 按原取消可见规则）。

## 2. 订单列表 · 商品售后标识

零售 / 代采列表「商品信息」= 商品名称 + 售后标识，与订单详情「商品明细」商品名称上的标识一致。

### 2.1 标识规则（P0）

列表商品名右侧展示标识。只展示一行商品时，取该行商品标识；「等 N 种」时取列表主商品（第一件）的标识。

**标识枚举（不得增减）**

| 标识 | 含义 | 推导规则（与详情一致） |
|------|------|------------------------|
| 退款中 | 仅退款 / 退货退款进行中 | 售后状态为：待审批、退款中、待退货、待收货、退款异常 |
| 部分退款 | 退款已完成但未退完购买数 | 仅退款 / 退货退款状态=已完成，且退货数量 < 购买数量 |
| 全额退款 | 退款已完成且覆盖购买数 | 仅退款 / 退货退款状态=已完成，且退货数量 ≥ 购买数量 |
| 补发中 | 补货进行中 | 补货状态为：待审批、待收货 |
| 已补发 | 补货已完成 | 补货状态=已完成 |
| （不展示） | 无售后，或已拒绝且无其它结果 | — |

**同一商品多笔售后优先级**：退款进行中 → 退款已完成 → 补货进行中 → 补货已完成。

**推导**

1. 该商品是否有仅退款 / 退货退款进行中？→ 退款中
2. 否则是否有仅退款 / 退货退款已完成？退货数 < 购买数 → 部分退款；否则 → 全额退款
3. 否则是否有补货进行中？→ 补发中
4. 否则是否有补货已完成？→ 已补发
5. 否则不展示

**验收**

- 列表标识文案、颜色与订单详情商品明细一致
- 无售后的订单不展示标识
- 打开同一订单详情，商品名上的标识与列表一致

## 3. 订单完成后发起售后

已完成订单后台可开售后，能力与「平台退款」相同，均生成售后单。沿用现有订单后台操作权限，本期不新开权限点。

### 3.1 入口与可见性（P0）

PC 零售订单、代采订单操作列：

| 订单状态 | 操作文案 | 说明 |
|----------|----------|------|
| 零售自提：待收货、待提货 | 平台退款 | 保持原规则 |
| 零售快递 / 代采：待收货 | 平台退款 | 保持原规则 |
| 已完成 | 发起售后 | 本期新增 |
| 其它状态 | 不展示上述入口 | — |

两个入口打开同一侧栏抽屉（标题「发起售后」），可选仅退款 / 退货退款 / 补货，提交后生成售后单。

**验收**

- 已完成订单操作列出现「发起售后」，抽屉字段、校验、提交与「平台退款」一致
- 待收货（及零售自提待提货）仍为「平台退款」，不改名为「发起售后」
- 已关闭、待发货等状态不出现「发起售后」
- 抽屉校验失败（未选商品、未填原因 / 描述 / 凭证等）时不关单、不生成售后单，提示与现网平台退款一致

---

## 其它约定

- 取消拦截文案三端完全一致。
- 列表商品标识文案、颜色与订单详情共用同一套语义。
- 完结判定以售后单状态为准：已完成 / 已取消 / 已拒绝视为完结。
- 服务端取消订单接口须增加售后未完结校验，前端提示为辅。
- 无订单号或查不到售后时不拦截。
