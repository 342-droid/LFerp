## 1. 字段说明

每条指标固定列：

| 列 | 说明 |
|---|---|
| 指标 ID | 稳定英文标识，供原型 / 研发引用 |
| 中文名 | 界面展示名 |
| 所属专题 | 见信息架构专题 ID |
| 统计事件时间 | 必须落到具体事件，禁止笼统「日期」 |
| 粒度 | 主订单 / 子订单 / SKU / 履约明细 / 结算明细 / 资金流水等 |
| 定义或公式 | 已确认写清；否则填「待确认」并链到 Q 编号 |
| 适用角色 | 可见角色（摘要） |
| 状态 | `已确认` / `部分确认` / `沿用现网` / `暂缓` / `待确认` |

状态约定：

- **已确认**：本指标评审结论无未决子项，可进原型与验收。
- **部分确认**：已确认部分写入「定义或公式」；**暂缓**子项必须同格写明，**禁止**把整项标成已确认或暂缓。
- **沿用现网**：与门店经营参谋 / 佣金明细现网口径一致，以现网文档为准。
- **暂缓**：整项尚不具备可执行定义（或仅有禁止项）；待核对后再拍。
- **待确认**：有名称或方向，计算规则未拍板。

### 2.0 RBT 需求状态（报表筛选对齐 · 知页最新）

不以本地旧原型文案为准。知页《6-需求单管理PRD》V1.3：

- 主链路：`待审核 → 待接单 → 待确认签约 → 待签署 → 待付款 → 待复核 → 还款中 → 已完成`
- 旁路：`待重新确认`（待确认签约撤回接单后；不直接回待接单，须平台重新发布或作废）、`已作废`、`已驳回`
- 语义：`待付款`＝等贸易商付款；`还款中`＝门店按日还款（旧称「支付中 / 待还款」仅作历史迁移别名）
- 报表筛选、权限、对象归属随上述状态机对齐，**不自行改写流程**

## 2. 统一模型提醒

### 2.1 分析维度（分列维护）

公司及组织 · 事业线 · 业务线 · 交易渠道 · 门店及品牌 · 商品/品类/SKU · 供应商 · 贸易商 · 履约方式及节点 · 需求/合同/订单/结算/资金记录。

**组织／贸易商权限（Q-ORG / Q-TR，摘要）**

- 公司驾驶舱与经营报表**默认剔除测试门店** → Q-ORG-01。
- 门店组织归属变更：知页无改 `orgId` 流程；报表不实现重刷；BD 变更见历史关系 → Q-ORG-02／Q-ORG-03。
- BD 历史业绩按**历史管辖关系**归属 → Q-ORG-03。
- 贸易商业务结束后历史：**先支持查看，不做导出** → Q-TR-01 / Q-JV-12。
- 接单前／接单后菜单差异**冻结为权限配置** → Q-TR-02。
- 贸易商可见门店范围**跟知页 RBT 逻辑** → Q-TR-03。

**角色入口（Q-ROLE，摘要）**

- BD：默认含联营回收与明细下钻 → Q-ROLE-01。
- 产品分析：开放金额类敏感字段 → Q-ROLE-02。
- 供应商：默认可供货／待发／货款到账；**禁止**佣金与联营回收 → Q-ROLE-03。
- 财务看平台并可下钻单店；门店仅本店；非重复指标双定义 → Q-ROLE-04。
- **仅财务可导出**明细 → Q-ROLE-05。

### 2.2 时间维度（分列保留）

下单 · 支付 · 退款 · 发货 · 到店 · 签收/核销 · 结算 · 扣费 · 到账。

经营分析与资金分析可关联，但**各自使用事件时间**。

**页面日期筛选（一期，四端统一）**：仅 `今日｜昨日｜近7天｜近30天｜自定义`（`today`／`yesterday`／`7d`／`30d`／`custom`）。近7天、近30天均为**截至昨日**的完整自然日（不含今日）；自定义含首尾日；不再提供本周／本月。环比＝相对上一同等长度周期。钱包余额、待结佣金等当前时点指标不随日期筛选变化。

### 2.3 统计粒度与拆单

- 代采：履约方式 ＋ 供应商。
- 零售：履约方式 ＋ 商户主体；零售快递→供应商，自提→门店。
- 不同粒度通过关联追溯，不假设一一对应。

### 2.4 渠道／业务线（支付 GMV 覆盖）

**一期已确认** → Q-DATA-02：支付 GMV 仅覆盖冷丰已有业务——**平台零售（商城／直播）**与**代采进货**（代采商品支付金额单独列示，不计入消费者 GMV）；佣金／平台分配所得另列。其他渠道不在一期范围，不设入口、Tab、占位。

### 2.5 数据刷新（摘要）

- 钱包资金流水／可提现余额：现网为**实时同步** → Q-DATA-01。
- 成交／经营类专题（含直播）最小更新频率**统一近实时**（≤15 分钟，「差不多马上有」）→ Q-DATA-03 / Q-DATA-05。
- **结算资金 SETTLE**：**每日统一结算**（例外）→ Q-DATA-05。
- 「数据截至」**统一展示在页头**（筛选旁；结算可标批次日）→ Q-DATA-05。
- 未获取到时界面统一显示**「暂未获取」**（含直播）→ Q-DATA-03 / Q-DATA-04。

## 5. 联营采购、扣费及回收

门店端统一称「联营采购」，与自行付款的普通采购区分。金额必须分列。报表**只读追溯**已有 RBT / 商城 / 采购 / 结算规则，**不为报表另建交易规则或统一扣费比例**。
