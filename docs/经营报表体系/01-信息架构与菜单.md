## 1. 产品定位（摘要）

建设统一的公司经营驾驶舱和多角色经营报表体系，覆盖销售、直播、联营采购、资金回收、供货、库存、履约、结算、售后及预警。

- **公司层面**：整体经营 → 事业线 / 业务线 / 渠道 / 门店 / 供应商 / 贸易商 → 业务单据。
- **外部角色**：按身份及业务关系查看授权数据。
- **交互原则**：总览 → 专题 → 对象 → 业务明细；不为演示改写现有业务流程。

### 1.1 一期已确认范围（2026-11-20）

**业务范围**：一期仅覆盖冷丰已有业务——平台零售（商城／直播）、代采进货、佣金／平台分配所得（RBT 联营沿用 §6.6 及 03 既有结论）。POS、食亨及相关入口、Tab、渠道、账单、汇总公式、接口对接**均不在一期需求内**，各端不出现对应入口或占位。

**日期筛选**（四端统一）：

| 选项 | 统计区间 |
|---|---|
| 今日 | 当天自然日（截至当前，近实时） |
| 昨日 | 昨天完整自然日 |
| 近7天 | 截至昨日的连续 7 个完整自然日（不含今日） |
| 近30天 | 截至昨日的连续 30 个完整自然日（不含今日） |
| 自定义 | 起止自然日，含首尾日；不超过今天 |

不再提供本周、本月及其他快捷周期。环比脚注为相对上一同等长度周期。

**四端一期范围简述**（与现网原型代码对齐）：

### 1.2 实现缺口（非待拍板规则）

下列事项是**系统暂无字段或数据源**造成的实现缺口，不是待业务拍板的规则；业务规则已按各 Q 编号确认，待字段落库后按原规则实现：

| 缺口 | 影响 | 现状 |
|---|---|---|
| 发货／到店等**承诺时点**未落库（无预计发货、预计到店日期） | 供应商端「发货准时率」及准时率类指标无法计算 | 界面暂不展示（`store-app/js/store-app-biz-supplier-config.js` · `SHIP_ON_TIME.enabled=false`） |
| 03 · P3b 所列字段映射（需求金额、贸易商应收、实际付款、扣费流水、结款单／钱包状态码、测试店判定、BD 历史关系存档等） | 对应指标按已确认口径实现，需数据／研发补映射 | 见 03「P3b」 |
| 供应商货款「应结／待结算／已结算」是否包含关系 | 未确认互斥前不得直接相加三项 | 原型分开展示，沿用系统结算记录字段；正式字段映射见实现缺口 |
| 履约完成节点时间字段历史缺失 | 实际供货无法按履约完成补算 | 有记录按履约完成统计；历史无记录时显示未形成（—），**不用**发货／下单／结算时间补算 |
| 供应商应结货款汇总字段／形成时间 | 应结货款汇总可能缺字段 | 有系统字段则展示；无则标实现缺口，不编造金额 |

## 2. 角色与产品入口

| 角色 | 产品入口 | 主要内容 | 数据范围 |
|---|---|---|---|
| 公司管理层 | ERP 经营驾驶舱 | 公司经营、投入回收、资金、履约及风险 | 授权公司及组织范围 |
| 平台运营 | ERP 经营报表 | 销售、直播、门店、商品、顾客及异常分析 | 授权业务范围 |

| 门店 | 现有门店端经营中心（经营参谋） | 本店成交、佣金、扣费、结算及联营采购 | 本店 |
| 供应商 | 现有供应商端 | 自身订单、供货、库存、履约、应收及到账 | 自身供货相关业务 |
| 贸易商 | 丰银宝贸易商端 RBT 模块 | 授权门店经营概览、本人联营投入与回收 | 按需求可见性及有效业务关系授权 |

| 产品 | 内部分析入口 | 具体业务分析（指标待确认） | 按职责授权 |

权限须同时控制：**组织、业务对象、指标、明细、历史时间、导出**；不能仅隐藏页面入口。完整权限矩阵见后续交付物 2（本轮不展开细表）。

## 3. 四级导航模型

所有入口统一按四级展开：

| 层级 | 含义 | 示例 |
|---|---|---|
| L1 首页 / 总览 | 入口落地页，主题卡片或摘要 | 驾驶舱六大主题 |
| L2 专题 | 完整报表目录中的专题 | 销售经营、扣费与回收 |
| L3 对象 | 具体分析对象 | 某门店、某供应商、某直播场次 |
| L4 业务明细 | 单据 / 流水 / 规则追溯 | 子订单、结算单、资金流水 |

```text
入口首页(L1)
  └─ 专题报表(L2)
       └─ 对象分析(L3)
            └─ 业务明细(L4)
```

## 4. 公司驾驶舱（管理层）

驾驶舱是统一总览，**按主题进入专题**，不把所有指标堆在一页。

### 4.1 首页六大主题（L1）

| 主题模块 | 展示要点 | 默认进入专题 |
|---|---|---|
| 经营规模 | 支付 GMV、净成交额、订单、支付人数及变化 | 销售经营 |
| 收入与收益 | 按经营主体及财务确认口径（区别于 GMV） | 结算与资金 / 财务经营分析 |
| 联营投入与回收 | 实际投入、约定回收、实际回收、剩余金额 | 联营采购 · 扣费与回收 |
| 资金结算 | 应收、已结算、实际到账及差异 | 结算与资金 |
| 供货履约 | 待发货、缺货、发货与到店准时 | 库存与供货 · 仓配履约 |
| 售后及经营异常 | 质量、履约、成交下降、回收中断 | 售后 · 经营预警 |

筛选（驾驶舱全局）：组织、事业线、业务线、渠道、日期（各主题明确所用事件时间，见指标字典）。**默认剔除测试门店**（Q-ORG-01）。

### 4.2 平台运营 · ERP 经营报表（L1）

面向运营的专题导航首页，菜单对齐下方「完整报表目录」，默认强调：销售、直播、门店、商品、顾客、经营预警。

### 4.3 财务 · ERP 财务经营分析（L1）

财务视角首页，默认强调：联营投入与回收、扣费与回收、结算与资金；与经营 GMV 看板分栏，避免混读。

### 6.2 ERP 经营报表（平台运营）

与驾驶舱共用专题目录；首页排序侧重 SALES / LIVE / STORE / GOODS / CUST / ALERT。无「财务专属账务页」入口（归财务入口）。RBT 需求单详情仍见 [`RBT/rbt_demand.html`](../../RBT/rbt_demand.html)。

**一期平台 PC · 数据中心（现网原型，MDM 顶栏「数据中心」）**：

```text
平台数据中心
├─ 经营总览（零售＋代采汇总；统一门店排行 TOP10）
├─ 零售经营（商城／直播零售成交）
├─ 代采经营（门店进货；平台分配所得）
├─ 门店经营比较（与总览同表头／同排序规则）
└─ 单店经营详情
```

- 侧栏：进入数据中心后仅展示经营分析（经营总览／零售经营／代采经营／门店经营比较），**不**混入商家主体／商家列表／人员中心；刷新后仍保持。
- 门店排行：基础信息＋零售经营＋代采进货＋平台分配所得分组同表；排序仅切换零售支付成交额／代采商品支付金额／平台分配所得合计；无交易金额显示 0，结果未形成显示 —；零售与代采分列，不合成营业额。
- 指标范围：零售支付成交额／支付主订单数、代采商品支付金额、平台分配所得（零售、代采商品＋代采运费平台份额）；零售与代采**不相加**称为门店营业额。
- **无客户运营模块**（无顾客分析／复购流失页），无 POS。
- 日期筛选同 §1.1。
- 原型路径：`MDM/mdm_data_biz_overview.html`、`mdm_data_biz_retail.html`、`mdm_data_biz_proxy.html`、`mdm_data_biz_stores.html`、`mdm_data_biz_store_detail.html`。

### 6.4 门店端 · 经营中心（经营参谋）

沿用现有门店 APP 入口；目标菜单：

```text
经营参谋
├─ 总览（本店成交规模摘要）
├─ 佣金明细（下单日期 / 入账日期）
├─ 经营趋势 / 业务构成 / 商品 / 顾客（可并入总览区块）
├─ 扣费与结算（本店）
├─ 普通进货概况
└─ 联营采购（本店）— 与普通进货分开展示
```

一期店长端范围（与现网原型对齐）：经营总览；经营数据 Tab＝**平台零售（商城／直播）｜进货｜佣金**；运营数据（购买客户／购买频次／来源表现）；佣金明细；进货概况；RBT 付款账单（有业务才出）。**无 POS**（无 POS 结算区块、Tab、渠道筛选）。日期同 §1.1。

呈现原则：

- **成交规模、门店所得、资金余额、联营回收**分栏，不可混成一个「收入」数。
- **可提现余额**按当前资金状态展示，不随历史经营日期筛选变化。
- 渠道构成固定展示商城／直播成交额与占比（紧凑占比条），无业务线／全部渠道切换。
- 总览「代采进货」仅主指标进货支付总额、进货订单数，及「查看进货数据」入口；采购支出解释放指标说明。
- 经营数据「最近订单」最多 5 笔，「查看全部订单」进入历史客户订单页（`store-orders.html`）；「最近进货订单」最多 5 笔，「查看全部进货订单」进入历史进货订单列表（`restock-orders.html`）。汇总／趋势仍按全部符合条件订单。
- 现网原型：`store-app/h5/biz-center.html`、`biz-ops.html`、`biz-operate.html`、`biz-commission.html`、`biz-restock-report.html`。

### 6.5 供应商端

```text
经营 / 供货分析（供应商）
├─ 工作台 · 经营参谋
│    ├─ 经营总览（支付交易规模／实际供货／退款／货款结算摘要；各指标标注统计时间）
│    ├─ 商品表现（支付交易数量 vs 履约完成供货数量、货款、退数量／退款金额；SKU 不重复计）
│    ├─ 订单退款（顾客退款与货款调整分列；订单／售后／结算状态分列）
│    ├─ 履约与售后（履约完成订单／商品数；只读 → 订单／售后列表；准时率待承诺时点落库）
│    └─ 货款结算（应结／待结算／已结算分列，不相加 → 结算单明细）
│    （一期无独立门店分析：不含门店采购贡献／区域／沉默门店）
├─ 订单与供货计划
├─ 待发货 / 库存 / 缺货（库存专题一期不做）
├─ 发货履约
├─ 售后（自身相关，只读）
└─ 应收 · 结算 · 到账（自身货款；结算中心承接明细）
```

原则：供应商只看**自身供货与货款**；门店**佣金**、**联营回收**、其它供应商／平台全量、无关消费者 PII **禁止**开放（Q-ROLE-03）。**支付交易规模**按支付成功时间；**实际供货**按履约完成节点——二者分列，不混称「供货量」。货款 ≠ 消费者实付；**结算完成 ≠ 到账**。查询须按供应商主体隔离，后端必须校验。

原型路径：

| 能力 | 路径 |
| --- | --- |
| 数据中心 | `store-app/h5/biz-supplier-home.html` |
| 配置／缺口 | `store-app/js/store-app-biz-supplier-config.js` |
| 数据适配 | `store-app/js/store-app-biz-supplier-data.js` |

### 6.6 贸易商端 · RBT

> 贸易商端不属于一期四端范围（店长／BD／平台 PC／供应商），本节保留既有 RBT 规划；其时间窗（近 30 天／近 90 天／近 12 个月）为 RBT 模块自身规则，**不适用** §1.1 日期选项。

```text
贸易商 · 经营查看
├─ 首页基础工具 · 门店经营（多店）→ 单店经营页
│    ├─ 可见门店：仅本人已接单相关（不含待接单）
│    ├─ 门店经营概览（签署完成后出数；默认近 30 天，可切近 90 天 / 近 12 个月）
│    └─ 本笔联营回收（约定／实付／剩余／预计付完；未还款空态）
└─ 需求大厅：接单／签约／签署（不进需求详情，不挂经营块）
```

门店经营概览字段：平台内整体 GMV（营业额）、退款、净成交额、支付主订单数、客单价、最近成交日期、有成交天数及趋势。**不与佣金混读**（Q-JV-10）。

开业大礼包口径：提交需求时门店通常尚未营业；**各方完成签署（待复核及之后）**才可能有经营概览数据；签署前空态、不伪造成交。

本笔联营回收：核心回答「有没有能力付款、大概何时付完」；挂在已接单单店页；状态用**支付中**（不用「还款」）。贸易商端不展示佣金明细；页内经营数据**不写**「从到手佣金抽成付给贸易商」等资金链路说明。

原型路径（一期 H5，PC 运营端后置）：

| 能力 | 路径 |
| --- | --- |
| 贸易商 H5 模块 | `RBT/rbt_h5_trader.html` |
| 应用逻辑 | `RBT/rbt-h5-trader-app.js` |
| 经营／回收演示数据 | `RBT/rbt-trader-store-biz.js` |
| 贸易商端 PRD（登录／大厅） | `RBT/docs/8-贸易商端移动端PRD.md` |

约束：

- 不开放其他贸易商业务明细。
- 业务结束后，停止基于该笔业务**持续**查看门店经营数据；历史允许**先查看、不做导出**（Q-TR-01）；快照期限见 Q-JV-12 暂缓。接单前／后菜单差异冻结为权限配置（Q-TR-02）；可见门店跟 RBT（Q-TR-03）。
- 接单 / 撤回 / 签约 / 付款 / 复核 / 还款节点**沿用知页最新规则**，报表不新增业务状态。旧文案不可照搬：撤回接单 → **待重新确认**（非直接回待接单）；合同签完 → **待付款** → 贸易商付款后 **待复核**；复核通过 → **还款中**（非「支付中」）。
- **不开放**贸易商看门店佣金／提现／进货；不做预警处理状态机。

### 6.7 BD / 产品 / 财务入口（摘要）

| 入口 | 已确认范围 |
|---|---|
| BD | **BD APP 工作台 → 数据中心**：总览 → 门店业务分析（零售／代采）→ 门店详情；顶层「佣金数据」直接展示佣金分析（覆盖本人零售／代采及已交接门店历史佣金），「查看佣金明细」保留并携带筛选；经营提醒＋消息「门店预警」（一期仅提示需关注，无处理流程）；**不开放**门店佣金橙卡／提现；无客户运营、无 POS；历史业绩按历史关系（Q-ROLE-01 / Q-ORG-03）。展示名「零售佣金／代采佣金」，统计仍为本人应得 |
| 产品分析 | 开放金额类敏感字段（Q-ROLE-02）；SKU／品类细表暂缓 |
| 财务经营分析 | 看平台整体，可对应下钻单店；与门店端「仅本店」是范围差，不是重复指标（Q-ROLE-04） |
| 导出 | **仅财务**可导出明细（Q-ROLE-05） |

BD 数据中心原型（一期，与现网代码对齐；仅零售／代采，无 POS、无客户运营）：

```text
BD 工作台
  └─ 数据中心（biz-bd-home / biz-bd-center）
       ├─ 门店数据（业务分析／零售经营／平台进货）
       │    └─ 门店详情 biz-bd-store（单条标题栏：返回＋店名＋指标说明；零售／代采；「零售佣金／代采佣金」下钻 dim=pay）
       ├─ 佣金数据 → 直接进入佣金分析（完整业务范围；流水进明细；含历史佣金；不对交接店开放完整经营）
```

**BD 单店入口**：`biz-bd-store.html?storeId=S-CN&from=bd-app&role=bd`。误入店长壳页 `biz-center.html?role=bd&storeId=…` 会自动跳到上述单店页。门店 ID 统一为 `S-*`（旧 `STORE-*` 别名兼容）。无法解析门店时明确提示，不静默展示默认店。

## 7. 对象层（L3）与明细层（L4）示意

| 专题 | 典型对象（L3） | 典型明细（L4） |
|---|---|---|
| 销售经营 | 事业线、业务线、渠道 | 主订单 / 子订单 |

## 9. 设计约束

1. 事业线、渠道、商品分类、履约方式**分字段维护**，不可混成一个分类。
2. 直播引流与商城成交等跨维度关联**不得导致交易重复累计**。
3. 各报表必须标明所用**事件时间**（下单 / 支付 / 退款 / 发货 / 到店 / 签收核销 / 结算 / 扣费 / 到账）。
4. 统计粒度区分主订单、业务子订单、商品行、履约明细、包裹、结算明细、资金流水；拆单规则沿用知页（代采：履约方式＋供应商；零售：履约方式＋商户主体；零售快递→供应商，自提→门店）。
5. 不为完成演示场景改写现有流程。
