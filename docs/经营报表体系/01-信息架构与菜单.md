## 1. 产品定位（摘要）

建设统一的公司经营驾驶舱和多角色经营报表体系，覆盖销售、直播、联营采购、资金回收、供货、库存、履约、结算、售后及预警。

- **公司层面**：整体经营 → 事业线 / 业务线 / 渠道 / 门店 / 供应商 / 贸易商 → 业务单据。
- **外部角色**：按身份及业务关系查看授权数据。
- **交互原则**：总览 → 专题 → 对象 → 业务明细；不为演示改写现有业务流程。

## 2. 角色与产品入口

| 角色 | 产品入口 | 主要内容 | 数据范围 |
|---|---|---|---|
| 公司管理层 | ERP 经营驾驶舱 | 公司经营、投入回收、资金、履约及风险 | 授权公司及组织范围 |
| 平台运营 | ERP 经营报表 | 销售、直播、门店、商品、顾客及异常分析 | 授权业务范围 |
| 财务 | ERP 财务经营分析 | 投入、应扣、实扣、回收、应收、到账及对账 | 授权账务范围 |
| 门店 | 现有门店端经营中心（经营参谋） | 本店成交、佣金、扣费、结算及联营采购 | 本店 |
| 供应商 | 现有供应商端 | 自身订单、供货、库存、履约、应收及到账 | 自身供货相关业务 |
| 贸易商 | 丰银宝贸易商端 RBT 模块 | 授权门店经营概览、本人联营投入与回收 | 按需求可见性及有效业务关系授权 |
| BD | BD APP 工作台 · 经营参谋 | 关联门店多店总览、经营提醒、下钻单店经营参谋 | 授权负责门店 |
| 产品 | 内部分析入口 | 具体业务分析（指标待确认） | 按职责授权 |

权限须同时控制：**组织、业务对象、指标、明细、历史时间、导出**；不能仅隐藏页面入口。完整权限矩阵见后续交付物 2（本轮不展开细表）。

## 3. 四级导航模型

所有入口统一按四级展开：

| 层级 | 含义 | 示例 |
|---|---|---|
| L1 首页 / 总览 | 入口落地页，主题卡片或摘要 | 驾驶舱六大主题 |
| L2 专题 | 完整报表目录中的专题 | 销售经营、扣费与回收 |
| L3 对象 | 具体分析对象 | 某门店、某供应商、某直播场次 |
| L4 业务明细 | 单据 / 流水 / 规则追溯 | 子订单、结算单、资金流水 |

```text
入口首页(L1)
  └─ 专题报表(L2)
       └─ 对象分析(L3)
            └─ 业务明细(L4)
```

## 4. 公司驾驶舱（管理层）

驾驶舱是统一总览，**按主题进入专题**，不把所有指标堆在一页。

### 4.1 首页六大主题（L1）

| 主题模块 | 展示要点 | 默认进入专题 |
|---|---|---|
| 经营规模 | 支付 GMV、净成交额、订单、支付人数及变化 | 销售经营 |
| 收入与收益 | 按经营主体及财务确认口径（区别于 GMV） | 结算与资金 / 财务经营分析 |
| 联营投入与回收 | 实际投入、约定回收、实际回收、剩余金额 | 联营采购 · 扣费与回收 |
| 资金结算 | 应收、已结算、实际到账及差异 | 结算与资金 |
| 供货履约 | 待发货、缺货、发货与到店准时 | 库存与供货 · 仓配履约 |
| 售后及经营异常 | 质量、履约、成交下降、回收中断 | 售后 · 经营预警 |

筛选（驾驶舱全局）：组织、事业线、业务线、渠道、日期（各主题明确所用事件时间，见指标字典）。**默认剔除测试门店**（Q-ORG-01）。

### 4.2 平台运营 · ERP 经营报表（L1）

面向运营的专题导航首页，菜单对齐下方「完整报表目录」，默认强调：销售、直播、门店、商品、顾客、经营预警。

### 4.3 财务 · ERP 财务经营分析（L1）

财务视角首页，默认强调：联营投入与回收、扣费与回收、结算与资金；与经营 GMV 看板分栏，避免混读。

## 5. 完整报表目录（L2 专题）

| 专题 ID | 专题 | 主要报表（L2 内页） | 核心分析内容 |
|---|---|---|---|
| SALES | 销售经营 | 公司销售总览、事业线／业务线分析、渠道分析、销售趋势 | 成交规模、退款、净成交额、结构及变化 |
| STORE | 门店经营 | 门店总览、排行、单店分析、持续经营分析 | 门店表现、增长、活跃、收入及扣费 |
| GOODS | 商品经营 | 商品排行、品类分析、商品销售及退款分析 | 销量、金额、贡献及售后表现 |
| CUST | 顾客经营 | 支付顾客、新老客、复购及活跃分析 | 顾客规模、结构、留存和消费变化 |
| LIVE | 直播经营 | 直播日报、场次分析、拉新分析、成交与退款分析 | 拉新、成交贡献、会员与订单关联 |
| JV | 联营采购 | 联营业务总览、单笔业务台账、门店／贸易商投入分析 | 实际投入、约定回收及业务进度 |
| RECOUP | 扣费与回收 | 应扣实扣分析、实际回收、差异、回收预测 | 应扣、实扣、到账认定、剩余及预计周期 |
| SUP | 供应商经营 | 供应商供货、订单、商品、履约及结算分析 | 供货规模、库存、待发货、应收与到账 |
| INV | 库存与供货 | 库存概况、需求满足、缺货、待发货分析 | 今日及未来供货需求、可用库存和缺口 |
| FULFILL | 仓配履约 | 供应商发货、仓库发货、到店、自提及快递履约分析 | 各节点承诺与实际完成情况 |
| SETTLE | 结算与资金 | 应收、结算、到账、对账及资金流水分析 | 金额、时间、状态及差异追溯 |
| AS | 售后 | 售后总览、原因、责任、商品／供应商／履约分析 | 质量与履约问题、数量、金额及处理结果 |
| ALERT | 经营预警 | 门店经营、回收、库存、履约、结算及售后异常 | 异常发现、跟进及处理结果 |

> 新增分析指标的具体定义须逐项确认，不能仅凭名称生成计算规则。见 [03-待确认规则清单](03-待确认规则清单.md)。

## 6. 各入口菜单树

### 6.1 ERP 经营驾驶舱（管理层）

```text
经营驾驶舱
├─ 总览（六大主题卡片）
├─ 销售经营 → …（目录 SALES）
├─ 门店经营 → …
├─ 商品经营 → …
├─ 顾客经营 → …
├─ 直播经营 → …
├─ 联营采购 → …
├─ 扣费与回收 → …
├─ 供应商经营 → …
├─ 库存与供货 → …
├─ 仓配履约 → …
├─ 结算与资金 → …
├─ 售后 → …
└─ 经营预警 → …
```

### 6.2 ERP 经营报表（平台运营）

与驾驶舱共用专题目录；首页排序侧重 SALES / LIVE / STORE / GOODS / CUST / ALERT。无「财务专属账务页」入口（归财务入口）。

### 6.3 ERP 财务经营分析（财务）

```text
财务经营分析
├─ 总览（投入 / 应扣 / 实扣 / 回收 / 应收 / 到账摘要）
├─ 联营采购
├─ 扣费与回收
├─ 结算与资金
│    ├─ 应收
│    ├─ 结算
│    ├─ 到账
│    ├─ 对账
│    └─ 资金流水
└─ （只读关联）销售经营 / 门店经营 — 用于核对，不替代财务确认口径
```

### 6.4 门店端 · 经营中心（经营参谋）

沿用现有门店 APP 入口；目标菜单：

```text
经营参谋
├─ 总览（本店成交规模摘要）
├─ 佣金明细（下单日期 / 入账日期）
├─ 经营趋势 / 业务构成 / 商品 / 顾客（可并入总览区块）
├─ 扣费与结算（本店）
├─ 普通进货概况
└─ 联营采购（本店）— 与普通进货分开展示
```

呈现原则：

- **成交规模、门店所得、资金余额、联营回收**分栏，不可混成一个「收入」数。
- **可提现余额**按当前资金状态展示，不随历史经营日期筛选变化。
- 现网原型：`store-app/h5/biz-center.html`、`biz-commission.html`、`biz-restock-report.html`。

### 6.5 供应商端

```text
经营 / 供货分析（供应商）
├─ 订单与供货计划
├─ 待发货 / 库存 / 缺货
├─ 发货履约
├─ 售后（自身相关）
└─ 应收 · 结算 · 到账（自身货款）
```

原则：供应商只关心**自身货款是否到账**、**要发多少货**；消费者成交、门店**佣金**、**联营回收**等**禁止**对供应商开放（Q-ROLE-03）。消费者交易金额、供应商货款、实际到账分别展示；**结算完成 ≠ 到账**。

### 6.6 贸易商端 · RBT

```text
贸易商 · 经营查看
├─ 需求大厅 · 门店经营概览（接单前：可见需求对应门店）
│    └─ 默认近 30 天；支持近 90 天 / 近 12 个月；允许查看接单前历史
├─ 我的联营业务
│    ├─ 投入 / 扣费 / 回收（仅本人）
│    └─ 单笔业务台账
└─ （接单后）持续门店经营概览 — 依赖有效业务关系
```

门店经营概览字段（PRD 已列）：平台内整体 GMV、退款、净成交额、支付主订单数、客单价、最近成交日期、有成交天数及趋势。

约束：

- 不开放其他贸易商业务明细。
- 业务结束后，停止基于该笔业务**持续**查看门店经营数据；历史允许**先查看、不做导出**（Q-TR-01）；快照期限见 Q-JV-12 暂缓。接单前／后菜单差异冻结为权限配置（Q-TR-02）；可见门店跟 RBT（Q-TR-03）。
- 接单 / 撤回 / 签约 / 付款 / 复核 / 还款节点**沿用知页最新规则**，报表不新增业务状态。旧文案不可照搬：撤回接单 → **待重新确认**（非直接回待接单）；合同签完 → **待付款** → 贸易商付款后 **待复核**；复核通过 → **还款中**（非「支付中」）。

### 6.7 BD / 产品 / 财务入口（摘要）

| 入口 | 已确认范围 |
|---|---|
| BD | **BD APP 工作台 → 经营参谋**：多店总览 → 门店卡下钻；单店营业额／顾客／售后／自提销售／RBT；经营提醒＋消息「门店预警」（一期仅提示需关注，无处理流程）；**不开放**佣金橙卡／佣金明细／提现／进货；历史业绩按历史关系（Q-ROLE-01 / Q-ORG-03） |
| 产品分析 | 开放金额类敏感字段（Q-ROLE-02）；SKU／品类细表暂缓 |
| 财务经营分析 | 看平台整体，可对应下钻单店；与门店端「仅本店」是范围差，不是重复指标（Q-ROLE-04） |
| 导出 | **仅财务**可导出明细（Q-ROLE-05） |

BD 经营参谋原型：

```text
BD 工作台
  └─ 经营参谋
       ├─ 多店总览（biz-bd-home）
       │    ├─ 门店卡 → 单店经营参谋（biz-center?role=bd&storeId=）
       │    └─ 经营提醒（biz-bd-alerts，独立不回写）
       └─ 单店复用：营业额／顾客／售后／自提销售／RBT（无佣金、无进货）
```

## 8. 权限控制面（声明，非矩阵）

| 控制面 | 说明 |
|---|---|
| 组织 | 公司 / 事业部 / 区域等授权范围 |
| 业务对象 | 可见门店、供应商、贸易商、业务线 |
| 指标 | 同一页可隐藏未授权指标 |
| 明细 | 可看汇总不可看单、或可看单不可导出 |

## 9. 设计约束

1. 事业线、渠道、商品分类、履约方式**分字段维护**，不可混成一个分类。
2. 直播引流与商城成交等跨维度关联**不得导致交易重复累计**。
3. 各报表必须标明所用**事件时间**（下单 / 支付 / 退款 / 发货 / 到店 / 签收核销 / 结算 / 扣费 / 到账）。
4. 统计粒度区分主订单、业务子订单、商品行、履约明细、包裹、结算明细、资金流水；拆单规则沿用知页（代采：履约方式＋供应商；零售：履约方式＋商户主体；零售快递→供应商，自提→门店）。
5. 不为完成演示场景改写现有流程。
