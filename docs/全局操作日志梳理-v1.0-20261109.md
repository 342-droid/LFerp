# 全局操作日志梳理 v1.0

| 项 | 内容 |
|----|------|
| 日期 | 2026-11-09 |
| 依据 | 知业「ERP系统」知识库《操作日志》PRD（v1.0，2026-04-15）及售后单详情、取消售后单、取消订单、门店管理等文档；UAT 前端构建 2026-11-05；UAT 审计接口 `/system-core/v1/audit-log` 实际数据 |
| 原型 | `SCM/basic_settings_operation_log.html`（基础设置 → 操作日志） |

## 1. 结论

1. UAT 共有 **42 个**操作日志入口，归为 **7 种日志样式**。其中 29 个入口使用同一个通用日志抽屉，查询同一张审计表。
2. 审计表（`audit-log`）的记录范围远大于页面入口。商城商品、代采商品、订单、售后、钱包调账、权限、登录等 **14 类**业务已有记录，但没有任何查看入口。
3. 审计表同时记录了大量查询请求（列表、详情、轨迹等）。最近 4000 条中，查询类约占三成。直接做全局列表会被这些记录淹没。
4. 部分记录的请求参数含未脱敏的短信验证码、登录账号。通用抽屉「技术信息」会原样展示，需要处理。
5. 知识库 PRD 规划的风险等级、留存清理、统计看板、记录规则配置，UAT 均未实现。本次原型不纳入，只保留与 UAT 一致的部分。

## 2. 七种日志样式（UAT 实际组件）

| 编号 | 样式 | UAT 组件 | 形态 | 列表字段 | 详情 |
|---|---|---|---|---|---|
| A | 通用业务日志抽屉 | BusinessOperationLogDrawer | 70% 抽屉，标题「模块 · 操作日志 · 对象」 | 操作时间、操作内容、操作人、业务编号、结果、查看详情 | 760px 弹窗：结果标签 + 操作类型；操作时间、操作人、业务编号、操作结果；变更明细（共 N 项：变更项 / 变更前 / 变更后）；失败原因；折叠「技术信息」（后台动作标识、来源服务、请求方式、接口路径、客户端 IP、处理耗时、TraceID、请求参数） |
| B | 营销模板日志 | MarketingTemplateOperationLogPanel | 抽屉「操作日志 · 对象名」 | 操作时间、操作内容、操作人、方法、结果、查看详情 | 查询对象、客户端IP、来源服务、耗时；变更明细（共 N 个字段）；错误信息；请求参数 |
| C | 结算策略日志 | SettlementPolicyOperationLogPanel | 列表「更多 → 操作日志」抽屉 + 编辑/详情页卡片 | 同 B，另有操作类型、操作结果、时间筛选 | 资源对象，其余同 B |
| D | 门店详情日志页签 | StoreOperationLogTab | 门店详情「操作日志」页签 | 操作时间、操作内容、操作人、资源对象、方法、结果 | 同 C |
| E | 审核日志抽屉 | ReviewOperationLogDrawer | 50% 抽屉「操作日志 - 名称」，不分页 | 操作时间、操作内容、操作人、说明、结果 | 无 |
| F | 红包模版日志抽屉 | TemplateLogDrawer | 抽屉「操作日志 - 模版名」 | 同 E | 无 |
| G | 详情页时间线 | OrderDetailPage / DetailDrawer | 订单、售后、退款详情的可折叠卡片「操作日志」 | 时间、节点名、摘要、· 操作人；核销节点展开商品、条码、本次提货、累计进度、操作人 | 无 |

通用规则（A）：

- 筛选：操作类型、操作结果（成功 / 失败）、查询、重置。运费配置额外提供「模板名称 / ID」搜索。
- 分页：默认每页 20 条，布局为「共 X 条、上一页、页码、下一页」。
- 业务编号列：结算通用配置固定显示「平台」，直播配置显示「全局直播配置」并改称「配置对象」，运费配置改称「费用模板」。名称为空时只显示 ID。
- 操作类型未配置时显示「其他操作」，字段未配置时显示「其他配置项」。操作人为空时显示「用户 {ID}」或「系统操作」。
- 空列表显示「暂无操作记录」，无变更显示「无字段级变更」。

## 6. 原型设计：基础设置 → 操作日志

### 6.1 全局日志

- 数据：`GET /system-core/v1/audit-log/list`，不传 `resource` 即全量。实测已支持 `resource`、`action`、`success`、分页（单页上限 100 条）。
- 筛选：操作时间、业务模块、操作类型（随模块联动）、操作结果、操作人、业务编号 / 对象名称、「只看变更操作」（默认勾选）。
- 业务模块分两组：已有日志入口的 33 个模块，以及第 4 节的 14 类暂无入口业务。
- 列表：操作时间、业务模块、操作内容、操作人、业务编号、结果、查看详情。每页 20 / 50 / 100 条。
- 详情：沿用样式 A 的详情弹窗，基础信息额外展示「业务模块」「后台资源」。
- 订单、售后、退款时间线和红包审核日志不在审计表中，仍在各详情页查看。

### 6.2 入口清单

- 汇总卡片：7 种样式各自的入口数，点击可筛选。
- 列表：序号、一级菜单、页面、入口位置、日志样式、查询维度、记录的操作类型、预览。
- 预览：按 UAT 实际样式打开对应抽屉 / 页签 / 时间线（模拟数据）。
- 附表：第 4 节、第 5 节内容。

## 7. 需要后端配合

| 事项 | 说明 |
|---|---|
| 时间范围筛选 | 实测 `startTime` / `endTime` 未生效，全局查询需要支持按操作时间筛选 |
| 操作人筛选 | 需要支持按操作人姓名或用户 ID 查询 |
| 关键字筛选 | 需要支持按 `resourceId` / `resourceName` 模糊查询（目前仅运费配置有 `businessKeyword`） |
| 区分查询与变更 | 建议审计记录增加读写标识，或不再记录 list / detail / tree / trace 类请求 |
| 请求参数脱敏 | `requestParams` 中的 smsCode、loginAccount、手机号、密码、token 等写入前脱敏 |
| 对象名称 | 多数记录 `resourceName` 为空，列表只能显示长 ID，建议写入业务名称 |
| 供应商操作类型 | 供应商日志未配置操作类型字典，页面全部显示「其他操作」，需补字典 |

## 8. 验收要点

1. 「全局日志」默认隐藏查询类记录，取消「只看变更操作」后可见并带「查询」标记。
2. 选择业务模块后，操作类型只列该模块的动作。重置后恢复默认时间范围并勾选「只看变更操作」。
3. 失败记录的详情展示失败原因，变更明细为空时显示「无字段级变更」。
4. 技术信息默认折叠，请求参数中的验证码、手机号为脱敏值。
5. 「入口清单」42 个入口均可预览，样式与 UAT 对应组件一致。
