一、背景与目标

1.1 背景

快递截单页已经上线一套零售快递到家的策略配置（通用策略、直播/商城、类目优先、每日时刻窗口）。仓配另一套在「采购 → 门店订货汇总」：到点或人工截单，按门店生成门店订货单（MDH）。

生产和售后容易把「有没有 MDH / shipment_plan_id」当成「有没有截单」。仓配碰巧对；零售直发不进仓储、不走采购、不生成 MDH，那样猜会永远像没截单，取消和退款会错。

本期要做的不是重做快递截单页，而是：

  1. 把本页已有规则写全，作为零售直发「什么时候跨」的权威说明；
  2. 订货汇总截单后必须回写订单；
  3. 订单上建立统一截单事实源；对客增加「待接单」；
  4. 未截单提前发货由发货事件当场补截单，不走配置时刻。

1.2 目标

  • 快递截单页现行规则可验收（策略生命周期、窗口、匹配、截单后取消/退款）。
  • 订单上有唯一截单事实源；取消 / 退款 / 售后 / 核销只读它。
  • N2（快递到点）、N3（订货汇总截单）都回写订单：已截单 + 对客待发货。
  • 未截单提前发货（N5）：不走配置时刻，底层一次完成接单 + 发货，对客待收货。
  • 后台与 C 端主状态名称一致。

1.3 发布逻辑

配置页保持现网交互 → 订单域补统一状态与回写 → 对客露出待接单 → 售后/取消改读统一状态。

1.4 范围与优先级

优先级内容
P0快递截单现行规则写清并按此回写零售直发订单；订货汇总截单回写 CO；统一截单状态；待接单；提前发货补截单（底层）
本期不改交互快递截单页字段、抽屉、启停删；订货汇总截单按钮与自动配置弹窗
本期不做四种履约总配置台；C 端进度条；核销详情改版

四、业务底层逻辑（含原型确认口径）

本章为现行产品口径（快递截单页与订货汇总原型 + 订单回写）。
「补截单 / 接单 / 发货」一次落库属于底层实现，不在页面呈现过程。

4.1 统一截单边界（事实源）

订单必须自带截单状态，禁止各模块自己猜单据。

截单状态编码含义取消 / 退款
截单前PRE_CUTOFF还没对外承诺履约可普通取消
已截单CUTOFF_COMMITTED已对外承诺要履约不能普通取消；退款走售后审核

已截单不可释放。 一旦写成已截单，不能回退到截单前，没有「释放 / 反截」动作，也不做 N6 页面或接口。售后、关单走既有取消/退款规则，不靠把截单状态打回去。

取消、退款、售后、核销只读这个状态。 不许再用 ShipmentPlan、门店订货单、采购单、出库单判断「是否已截单」。 这些单据只当凭证，记在「截单来源 / 截单凭证」里。

零售快递直发过了本页时刻、没有 MDH，也必须是已截单。 仓配生成了 MDH，必须同时把订单写成已截单；有 MDH 只是凭证，不是判断条件。

4.2 策略只负责「怎么跨」

维度是 订单类型 × 履约方式，不是「零售 / 代采」二选一。

履约组合谁负责跨界跨界后典型凭证 / 单据
零售 × 直发（快递到家）快递截单启用策略的每日时刻预计接单时间 / 截单批次；不生成 MDH
零售 × 仓配（含自提）门店订货汇总截单生成 MDH，回写各 CO
代采 × 仓配 / 代采配送同上生成 MDH，回写各 CO
任意履约 · 未截单提前发货发货事件当场补截单运单号 / 出库单；不走配置时刻

履约可拆成供应商到仓、仓到店、店到人，允许跳过（零售直发不进仓、不到店）。跳过只影响后面单据，不改变已截单后的取消 / 售后规则。

4.3 对客主状态（B / C 必须同名）

不要把「截单」做成对客主状态。后台可留截单前 / 已截单作事实源。

待支付 → 待接单 → 待发货 → 待收货 / 待提货 → 交易成功 / 交易失败
主状态对应截单状态含义
待支付—未付款
待接单截单前已付，尚未对外承诺。可普通取消
待发货已截单已承诺、尚未发出。不能普通取消
待收货 / 待提货已截单货已发出或已到提货点

零售自提既有规则不变：门店待收货在用户侧仍展示「待发货」，门店收货入仓后转「待自提」。 直播、商城都属于零售订单，列表 / 筛选 / 导出 / 详情同一套，不单开规则。 一订单中任一商品截单，整单视为已接单（对客待发货），见 §4.4.5。不按商品行拆主状态。

4.4 快递截单：作用范围、匹配、窗口

本页只作用于全平台零售线、快递到家（供应商直发，不进仓储、不走采购）。 采购 / 门店订货截单不在本页，仍在「采购 → 门店订货汇总」。

4.4.1 一条策略包含什么

字段必填说明
策略名称是后台识别用
适用场景是直播、商城，至少选一个，可同时勾选
截单时间是每日时刻，精确到秒；默认示例 10:00:00
商品类目是全部类目，或指定选品库类目（指定时至少选 1 个）
备注否仅后台查看，不给用户看
状态系统写草稿 / 启用 / 停用
是否通用系统写仅一条：直播+商城+全部类目

4.4.2 一单会不会进本页截单池

必须同时满足：

  1. 零售订单（直播或商城场景）；
  2. 履约 = 快递到家（直发）；
  3. 已支付，对客 = 待接单，截单状态 = 截单前；
  4. 未填写快递单（供应商还没发）。

不进本页窗口：

  • 仓配 / 自提 / 代采（走订货汇总）；
  • 未支付、已关闭、已完成；
  • 已经是已截单（待发货或之后）；
  • 已填写快递单：按发货后规则，走 §4.8 / N5，不受本页时刻影响。

原型代码注释曾写「待发货未填快递单」。对客主状态改为「待接单」后，窗口里的单应认待接单 + 未填快递单。不要再截已经待发货的单。

4.4.3 截单窗口

启用中的策略，每天在配置的时刻 T 触发一次。

本次截单覆盖：上次该策略同一时刻 T  ～  本次 T 的前一秒
例：今天 10:00:00 截  昨天 10:00:00 至 今天 09:59:59  的订单
（按支付成功时间落入该闭开区间；若无支付时间则按下单时间，生产实现时写死一种并在联调确认）

只截命中本条策略且仍在 §4.4.2 池内的单。 到点后回写见 N2：已截单 + 对客待发货；不生成 MDH。

草稿、停用策略不触发。

4.4.4 直播 / 商城分开匹配，指定类目优先

订单行各自找策略，订单截单状态只有一份（见 §4.4.5）：

  1. 先按订单场景（直播或商城）过滤启用策略（策略勾了该场景才参与）。
  2. 该行类目若落在某条「指定类目」策略里 → 用该指定类目策略的时刻。
  3. 未单独配置的类目，走该场景的「全部类目」策略（通用策略覆盖直播+商城全部类目）。

页顶与抽屉原文：同一场景下指定类目优先于全部类目。

一单多商品、多条策略时刻不同时：以最先触发截单的那一行为准，整单接单，不按行各出一套对客状态。

4.4.5 任一商品截单，整单视为已接单（冻结）

截单状态、对客主状态都在订单头，不按商品行拆「待接单 / 待发货」。

规则：一订单中任一商品被截单，该订单即视为已接单。

结果：

  1. 订单截单状态写成已截单；
  2. 对客主状态从待接单变为待发货（已接单；若同时已发货则走 N5 到待收货）；
  3. 取消 / 退款按已截单，整单不再当截单前；
  4. 其余尚未到自己策略时刻的商品，不再单独等自己的截单时刻再改订单状态。履约可继续按行发货，但订单已经是已接单。

适用入口（同一条）：

  • 快递截单：任一商品行命中启用策略且落入窗口（N2）；
  • 门店订货汇总：任一商品行进入本次截单并进 MDH（N3）；
  • 提前发货：任一商品行先发出（N5），整单已接单且待收货。

例：一单有蔬菜（指定策略 08:00）和粮油（只走通用 10:00）。今天 08:00 蔬菜行被截 → 整单立刻已截单、对客待发货，取消隐藏。10:00 通用任务不得把该单再截一遍，也不得拆回「一半待接单」。

4.5 通用策略与策略生命周期

通用策略（系统默认一条）

  • 全部类目、直播 + 商城、状态永远启用。
  • 仅支持修改：名称、截单时间、备注。
  • 不支持改场景、改类目范围、停用、删除。
  • 列表名称旁打「通用」标。
  • 若不存在，系统补一条（名称默认「通用截单策略」，时刻默认 10:00:00）。

其它策略

动作结果
新增保存状态 = 草稿，须在列表手动启用才生效
修改启用中的策略并保存保存成功后状态变为 停用，须再手动启用（避免改时刻立刻按新规则空跑）
修改草稿 / 停用保持原状态
列表点启用 / 停用启用 ↔ 停用；通用策略无此按钮
删除仅草稿、停用可删；启用中不可删；通用不可删

4.6 策略重叠（保存时拦截）

同一场景下：

冲突提示口径（原型）

校验时机：新增 / 修改保存。启用不重新做重叠（保存时已拦）。

4.7 截单后对客规则（各策略统一）

抽屉「截单后」只读说明，各策略相同，运营不能改：

  1. 用户 APP「取消订单」隐藏；
  2. 「申请退款」截断免审直退，改为售后审核流。

产品语义：相当于把发货后的售后方式提前到截单时刻。 后台订单：待接单可取消；已截单的待发货按原规则不再普通取消。

4.8 已填快递单：不受本页时刻影响

供应商已经填写快递单的订单，按发货后规则，不进本页窗口。

若填写发生在截单前（待接单就发了）：走 N5——发货事件当场补截单，同时完成接单 + 发货，对客待收货。不走本页配置时刻。

4.9 门店订货汇总截单

入口：采购 → 门店订货汇总。

动作说明
截单并生成门店订货单人工：按门店合并当前汇总池，生成 MDH
自动截单配置按「订单渠道 × 履约方式」配定时器表达式与描述

跨界后：

  1. 生成 MDH（一张可含多 CO）；
  2. 必须回写本批每个 CO：截单状态 = 已截单，对客 = 待发货，凭证 = MDH 单号，来源 = 订货汇总截单；
  3. 后续采购单 / 出库单按原仓配链，不再当截单事实。

未截单却提前出库 / 发货：同样 N5，不走本页定时器。

4.10 正常路径 vs 提前发货

正常（走配置时刻）

付款 → 待接单（截单前）
    → N2 快递到点 或 N3 订货汇总截单
    → 已截单 + 待发货
    → 发货 N4
    → 待收货

配置时刻只处理到点仍未发的待接单。

例外：未截单提前发货（不走配置时刻）

仍是截单前，履约侧已发货（上传快递单、回传运单、仓配出库等现有动作）。

发货当口底层一次做完：

  1. 补截单 → 已截单（来源 = 提前发货补截单）；
  2. 同时完成【接单】+【发货】；
  3. 对客直接 待收货（自提按既有规则）。

不停留待接单，不经过待发货。之后取消 / 售后按已截单。 页面只看到待收货，不展示过程。

节点触发适用截单状态对客主状态附带走配置时刻页面呈现过程
N1 支付成功收款成功全部已付单保持截单前待支付 → 待接单—否只出待接单
N2 快递截单到点启用策略每日 T零售直发、待接单、未填运单；任一商品行命中策略且落入窗口→ 已截单（整单）待接单 → 待发货（已接单）来源=快递配置时刻；不生成 MDH；取消隐藏、退款改审核是（本页）配置页不改；订单只出待发货
N3 订货汇总截单自动定时或人工「截单并生成门店订货单」进汇总池且仍待接单；任一商品行进本批 MDH 即整单本批每个 CO → 已截单（整单）待接单 → 待发货（已接单）生成 MDH 并回写 CO是（汇总配置）或人工汇总页保持现有操作

N5 未截单提前发货现有发货动作，当时仍截单前任意履约→ 已截单待接单 → 待收货（一次接单+发货，跳过待发货）来源=提前发货补截单否不呈现过程
N6 截单释放——不发生—已截单无法释放，本节点不做—无入口、无接口

互斥

  • 已是已截单，N2 / N3 再跑到不得重复写成第二次截单事实。
  • N5 之后，配置任务不得再截，不得把待收货打回待发货。
  • N4 与 N5 对客都是待收货：N4 经过待发货；N5 从未进入待发货。
  • 任一商品截单即整单已接单；禁止同一订单部分行待接单、部分行待发货。
  • 已截单不可释放，不能打回待接单 / 截单前。
