# PC 与 App 双端一致性规范

| 项 | 内容 |
|----|------|
| **规则名称** | PC 与 App 双端一致性规范 |
| **规则制定人** | 征征 |
| **制定日期** | 2026-11-05 |
| **适用范围** | MDM / 运营后台（PC）与丰银宝 / 门店 App 等同业务能力 |
| **状态** | 生效 |

## 规则说明

写功能时 **前后端（PC / App）核心数据与状态字段必须匹配**；交互与信息密度按使用方侧重点分开设计，不要互相硬套页面结构。

### 谁在用、侧重点是什么

| 端 | 典型使用者 | 侧重点 | 设计要求 |
|----|------------|--------|----------|
| **PC** | 运营 / 财务 / 客服 / 平台侧 | 完整查询、批量、对账、策略与明细核对 | **沿用现有页面模型与交互**；按组织 / 角色视角裁剪列与操作，不另起一套状态语义 |
| **App** | 门店 / 供应商等一线商家 | 找单快、办结快、少踩坑 | **操作便利优先**：一二级筛选、时间区间快捷、主操作前置；字段精简但 **状态文案与枚举与 PC 一致** |

### 必须对齐（核心）

1. **状态枚举与中文文案**（订单状态、售后状态、清分状态、结算/结款状态、入账状态等）与 PC 同源，禁止 App 自造「已完成 / 售后中」等与 PC 列表不一致的叫法。
2. **关键业务键**：订单号、清分编号、结款单号、商品行、金额口径（采购款 / 应收 / 退款 / 净额等）命名与含义一致，可互相跳转核对。
3. **权限与归集口径**：谁能看见什么（如供应商只看本商家订单清分），PC 视角与 App 视角规则一致，只是展示密度不同。

### 允许不同（形态）

- PC：多条件筛选、表格列、抽屉 / 多 Tab 详情、批量。
- App：Tab + Chip、时间快捷区间、卡片列表、单页详情、二次确认；筛选项取 **商家高频** 子集，不必镜像 PC 全部筛选项。

## 例外

- 纯 C 端用户 App（`user-app/`）消费侧状态可按用户话术展示，但若与 B 端履约态对应，映射关系须可追溯。
- 演示环境缺数时，应用 **同一套枚举** 造数，不得为填满筛选而引入未在 PC 出现的状态名。

## 参考落地

- 供应商客户订单（App）：`store-app/h5/supplier-orders.html` ↔ PC 零售/代采订单供应商视角
- 供应商结算（App）：`store-app/h5/supplier-settle.html` ↔ PC `mdm_settle_index` 清分台账 / 供应商结算
