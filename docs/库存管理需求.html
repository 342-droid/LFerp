一、背景与目标

1.1 背景

系统主路径是先销后采：用户可以先付钱，货再采购到仓、到店。代采、商城、多场直播、同仓多家门店共用一份配送仓库存。零售快递到家经常供应商直发，仓里可以没有实物。

选品库不再单独做库存统计。运营在各渠道编辑商品 → 售卖规格配置里看现货、配可售、展开仓店明细。

1.2 目标

  • 运营能按 SKU 配可售，并按配送仓 / 门店核对现货、可售、预占。
  • 支付成功才占货；一笔单可同时占现货和预售，不必先选售卖类型。
  • 入库后预售预占转成现货预占；用户到手（核销）才扣仓实物。
  • 截单、出库状态变化不重复扣库存。

1.3 发布逻辑

编辑商品可售与仓店表先落地 → 支付按拆段加预占 → 入库转化、取消退占、核销清占接上订单流 → 截单继续只改履约承诺、不碰库存账。

1.4 范围与优先级

优先级内容
P0代采 / 商城 / 直播编辑商品露出现货、可售、仓店表；可售两项；仓店默认收起
P0支付拆段预占；入库转化；取消原路退；核销清占并按履约扣或不扣实物
本期不做选品库库存统计菜单；门店独立现货账；在页面播放预占过程

二、用户与角色

角色诉求
平台运营在代采 / 商城编辑商品配可售；在直播排品配本场配额；展开仓店表核对现货和预占
用户 / 门店进货人下单时系统自动判断走现货还是预售，不必自己勾类型；可售不够则下不了
仓配 / 采购货到仓或到店后，预售预占转成现货预占；未转化的预售预占才进订货需求
履约 / 售后截单不改库存；取消按预占类型退；核销才清占、仓发才扣实物
研发 / 测试公式、拆段、转化、核销可对照流程图验收

三、术语

术语定义
仓实物仓储按配送仓维护的在库数量。入库加、核销扣。直发可以没有这项。
现货预占已支付、货还在仓里、用户还没到手。扣「剩余可售」，也扣仓可用现货。
预售预占已支付、货还没到仓（或直发待发）。不扣仓可用现货，也不进仓店表「剩余可售」列；下单时要扣「还能卖」。
总预占现货预占 + 预售预占。只做统计，不拿去减仓实物。
仓可用现货max(0, 仓实物 − 现货预占)。现货段从这里出。
仓可售SKU 可售配置摊到该仓的上限。
剩余可售编辑商品仓店表的列：max(0, 仓可售 − 现货预占)。直播本场配额从这里切。
还能卖下单校验：max(0, 仓可售 − 现货预占 − 预售预占)。不够则整行拒单。
直发供应商直接发给用户，不经过配送仓实物账。
仓店表把预售预占单独成列，所以「剩余可售」只减现货预占。用户再买时，系统还要减预售预占，得到「还能卖」。两个数都要保留，不要合成一个。

四、账本维度

  • 唯一账本：SKU × 配送仓。
  • 门店只继承所属仓。同仓门店看到同一份现货，不按门店再拆一套账。
  • 代采 / 商城 / 直播场次在预占上记渠道，方便对账，加减仍落在同一仓。
  • 一单多行按行拆现货 / 预售；整单履约状态仍按订单截单规则。

五、可售怎么配（原型）

入口：代采商品列表 / 商城商品列表 → 编辑商品 → 售卖规格配置；直播排品编辑同一区块。

字段谁改规则
现货库存只读各配送仓实物之和，仓储维护。
可售库存 · 按现货库存运营（代采 / 商城）填百分比。100% 等于取现货；大于 100% 多卖的部分走预售预占。
可售库存 · 按具体数量运营（代采 / 商城）填全网上限，再按各仓实物占比分摊。
可售结果只读按上面配置算出来的件数。
本场售卖配额仅直播可改不能超过该 SKU 各仓「剩余可售」合计（含本场已占）。保存只作用于本场，不回写中央商品库。
仓店库存只读默认收起，一行看「现货合计 · 可售合计 · N 个仓」；点「展开」看各仓现货 / 可售 / 总预占 / 现货预占 / 预售预占 / 剩余可售，以及共享门店。售卖范围选了门店时，表只留对应仓和店。改百分比时合计跟着变，展开状态保留。
预占加减过程不在抽屉里逐步播放。页面只展示算完的数。
仓可售（按现货库存）= round(仓实物 × 百分比 / 100)
仓可售（按具体数量）= 按各仓实物占比分摊全网固定上限
仓可用现货 = max(0, 仓实物 − 现货预占)
剩余可售   = max(0, 仓可售 − 现货预占)          ← 仓店表列、直播配额上限
还能卖     = max(0, 仓可售 − 现货预占 − 预售预占) ← 下单校验

「还能卖」可以小于「剩余可售」（已被预售预占锁走）。「剩余可售」可以大于「仓可用现货」（百分比 >100% 或固定数量大于实物），多出来的只能走预售预占。

六、预占何时增加

唯一正向入口：支付成功（待支付 → 待接单；若命中支付后自动截单则直接待发货）。待支付、关未付、草稿都不占货。

一笔支付、一个商品行、数量 Q，落到一个配送仓（按收货门店找仓；直发不占仓可用现货）：

还能卖 = 仓可售 − 现货预占 − 预售预占
走现货 = min(Q, 仓可用现货, 还能卖)
走预售 = Q − 走现货
走现货 + 走预售 < Q → 整行拒单（可售不足）
  • 走现货：现货预占 +该数（仓可用现货、剩余可售、还能卖都减）。
  • 走预售：预售预占 +该数（还能卖减；仓可用现货、剩余可售不变）。

一笔单可以同时拆出两段，运营和用户都不必先勾「现货 / 预售」。百分比溢出的那一截只进预售段。

直播：先扣本场剩余配额（配额本身不超过剩余可售），不够则拒单；扣下的数量再按上面拆段。配额和代采、商城、其他场次抢同一仓「还能卖」。

入库可插在支付之后、核销之前，把预售预占转成现货预占。取消（未到手）从支付后任意点原路退占。

8.1 节点说明

节点库存动作
待支付不占货。关单、超时无库存动作。
支付成功按第六节加预占。这是预占增加的唯一入口。
截单到点 / 支付后 / 订货汇总人工 / 提前发货补截，都不加减预占。
入库 / 仓收 / 店收仓实物 +入库数。转化 = min(入库数, 该仓预售预占)：预售预占减少、现货预占增加（货到了但仍被未完成的单锁着）。之后仓可用现货 = 仓实物 − 现货预占。
取消 / 售中退款（未到手）按该行当时类型退回。现货预占退回则现货和剩余可售、还能卖加回；预售预占退回则还能卖加回。已截单走售后审核，库存仍按本条退，不靠释放截单。
发货 / 出库 / 到店待提用户还没到手，预占不消失。直发没有仓实物可扣。本期口径：仓发也等到核销再扣实物，出库只改履约状态，避免在途扣两次。
核销（签收 / 提货 / 配送完成）现货预占、预售预占按该行清掉。非直发且绑着仓的，仓实物 −Q。还能卖不加回（货已卖出）。
售后回库仅实物退回仓时仓实物 +回库数。不自动加回可售；可售仍跟 SKU 配置和当前实物走。

图 4 · 入库转化

→

转化后货已在仓，但仍被未完成的单锁着，所以进现货预占，不会马上变成别人能下的仓可用现货。

九、和订货、截单的关系

  • 未转化的预售预占，才作为门店订货汇总的需求；现货预占不再进订货需求。
  • 货已在店、不走订货单的商品，支付时优先走现货段。标签怎么维护另文，本文只认这个结果。
  • 任何截单来源都不重复加预占。提前发货若支付时已占过，出库走「预占仍在」，核销再清。

十、原型页面

10.1 代采 / 商城 · 编辑商品

路径：冷丰商品 → 代采商品列表 / 商城商品列表 → 编辑。

  • 售卖规格每个 SKU 一张卡：现货只读，可售下拉两项（按现货库存 / 按具体数量）。
  • 选「按现货库存」时出现百分比和只读结果；选「按具体数量」时出现件数输入。
  • 仓店库存默认收起，展示「现货合计 · 可售合计 · N 个仓」；点「展开」看表，点「收起」收回。改百分比时合计跟着变，展开状态保留。
  • 售卖范围选了门店后，表只留这些门店对应的仓。

10.2 直播 · 排品编辑

路径：直播 → 直播排品 → 编辑商品。

  • 现货、可售只读（跟中央库配置）。
  • 本场售卖配额可改，不能超过剩余可售（可售 − 现货预占，含本场已占）。
  • 同一套仓店库存收起 / 展开表。
  • 保存只作用于本场排品，不回写中央商品库。

10.3 已下线入口

商品侧栏不再放「库存统计」。旧地址 MDM/mdm_product_stock.html 只留说明和跳转。

十二、验收

  1. [ ] 代采 / 商城编辑：可售只有「按现货库存」「按具体数量」；100% 取现货，大于 100% 溢出走预售
