订单支付流水需求（本期）

版本v1.0日期2026-08-31状态待评审

页面字段名一律为支付流水（渠道支付成功流水号）。有值原样展示；未支付 / 失败 / 无渠道流水为「-」。一单多笔收款时，列表和用户端详情取成功收款那一条；收款明细按行展示。直播订单、商城订单都属于零售订单，列表 / 筛选 / 导出 / 详情同一套逻辑，不单开页面、不单开规则。

本期做

端页面改动
后台 零售订单、代采订单列表 「下单门店」右侧加列；展开筛选可模糊查；导出字段默认勾选。零售含直播、商城场景
后台 零售、代采订单详情 · 收款明细 加「支付流水」列（代采不删原支付方式列）
用户 APP 订单详情（自提、快递） 「付款时间」下加支付方式、支付流水；待支付、已取消与支付方式一同隐藏；商品总价 / 订单优惠 / 实付金额独立成卡，放在订单编号卡上方
门店 APP 进货订单详情 只在「支付方式」下加「支付流水」；待支付、已取消与支付方式一同隐藏。金额区和其它字段维持原样

本期不做

1. 用户 APP「配送方式」（送货上门、门店提货）：生产已有功能，本期不作为新需求。
2. 复制支付流水、混合支付拆成多条流水展示。
3. 其它同期需求（快递截单、库存统计等）。
