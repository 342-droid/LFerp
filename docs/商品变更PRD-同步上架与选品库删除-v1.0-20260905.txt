## 口径先说清（后文不再重复）

商品有两层状态，不要混：

| 层级 | 是什么 | 谁改 |
| --- | --- | --- |
| SPU | 这条商品在本渠道/本场是否上架售卖 | 「保存并上架」只改这一层 |
| SKU | 某个规格是否上架 | 「批量上架」和规格卡上的上架/下架改这一层 |

「保存」只落编辑内容，不改 SPU 状态。

三个编辑入口共用同一套按钮语义：商城商品、代采商品、直播排品（直播仅本场生效）。

---

## 1. 同步至其他 SKU

**出现条件**：当前已选 SKU ≥ 2。按钮只在**第一个**规格卡底栏，和上架/下架同一排、靠左。单 SKU 不出现。

**动作**：把第一个已选 SKU 的售卖规格，覆盖到其余已选 SKU。未选中的 SKU 不动。少于 2 个已选 SKU 时提示「请先选择多个 SKU」。

**会同步**

| 字段 | 商城 / 代采 | 直播排品 |
| --- | --- | --- |
| 规格图 | 是 | 是 |
| 售卖系数、售卖单位 | 是 | 是 |
| 限购配置 | 是 | 是 |
| 积分兑换方式及对应金额/积分 | 是 | 是 |
| 售价、划线价、起售量 | 是 | 是 |
| 可售配置（按现货百分比 / 按固定数量） | 是 | 否（直播没有这套配置） |

**不同步**（各 SKU 自己保留）：商品条形码、规格值、展示规格名称、库存实数（现货/可售/预占/剩余）、是否默认、SKU 上下架。直播另加：本场售卖配额、可售配置。

展示规格名称若运营没手改过，同步售卖单位后按「商品名 + 规格值 + 售卖单位」自动重算；手改过的不覆盖。

只改当前编辑态，点保存（或保存并上架）后才落库。

---

## 2. 批量上架

位置：选择 SKU 行右侧，和「重置规格」并排，本按钮在左。

**动作**：把**当前已选** SKU 全部标为上架。不改未选 SKU，不改 SPU 状态。

未选任何 SKU 时提示「请先选择 SKU」。成功提示「已批量上架 N 个 SKU」。

同样只改编辑态，需再保存才落库。

---

## 3. 保存并上架

位置：编辑底栏，在「保存」右侧。

**动作**：先走与「保存」相同的校验和落库；通过后**只把本条 SPU 置为上架**。

| 入口 | SPU 上架结果 |
| --- | --- |
| 商城 / 代采 | 商品状态 = 上架 |
| 直播排品 | 本场排品状态 = 上架（enabled），只影响本场 |

各 SKU 的上/下架保持规格卡里的现值，本按钮不会顺带批量上架 SKU。

「保存」与本按钮的唯一差别：保存不改 SPU 状态。

校验失败（缺商品名、类目、可售时间等）两种按钮都不落库、不上架。

---

## 4. 选品库删除 SPU

### 4.1 谁能被下游挂上

待售卖不能被商城 / 代采 / 直播新关联。须审核通过，商品状态变为**售卖中**后，才能加入下游。

已停售也不能再新关联。曾经在售卖中挂上的下游记录会保留。

### 4.2 谁能点删除

入口：列表「更多」里的「删除」。

| 选品库状态 | 删除 |
| --- | --- |
| 待售卖（含待审核、审核未通过） | 有 |
| 已停售 | 有 |
| 售卖中 | 无，须先停售 |

### 4.3 点删除时怎么判

按**当前选品库状态**分支，不要用「待售卖去查下游」：

| 当前状态 | 下游（商城 / 代采 / 直播） | 营销（积分商城 / 新人专区 / 秒杀） |
| --- | --- | --- |
| 待售卖 | 不查。按规则此时不会被下游挂上，直接进确认删除 | 不拦截。有引用则删除按钮略灰，确认文案提示营销侧商品将置灰 |
| 已停售 | 必须查。有任一渠道占用 → 不删，提示「下游已关联（渠道名），无法删除」 | 同上，不拦截，只置灰提示 |

售卖中 → 停售 → 再删：走「已停售」这一行。停售本身不拆下游关联。

### 4.4 删掉之后

选品库去掉该 SPU。中央商品库、下游已挂单据不在本次删除范围。

营销侧仍挂着该编码的行置灰，只留活动里的删除，不再当正常可售商品。

下游若当时已拦截，选品库 SPU 还在，下游记录不变。
