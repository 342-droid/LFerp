快递截单需求（含统一截单边界、待接单、未截单提前发货当场补截单）

版本v1.1日期2026-09-01状态待评审

快递截单配置页原型本期不改字段和交互。订单页露出以正式 PRD §6.5 / §6.6 为准：后台进度条「运输中」改为待接单并接待发货；用户 APP 无进度条，待接单不单开页签、不进「我的」，隐在全部。

直播、商城都属于零售订单，列表 / 筛选 / 导出 / 详情同一套，不单开规则。后台与 C 端主状态名称必须一致。对客用「待接单」，不要写「待商家接单」。

一、纠正什么

不能用「有没有门店订货单 / shipment_plan_id」判断有没有截单。零售快递直发不进仓储、不走采购、不生成门店订货单；那样猜会永远像没截单，取消和退款会错。门店订货单只是部分履约跨界后的凭证，不是截单事实。截单事实落在订单自己的统一边界上。

二、统一截单边界（取消 / 退款 / 售后只认这个）

状态含义取消 / 退款
PRE_CUTOFF（截单前）还没对外形成履约承诺可普通取消
CUTOFF_COMMITTED（已截单）已对外承诺要履约不能普通取消；退款走售后审核
CUTOFF_RELEASED（必要时）截单被释放 / 回退重新按截单前

跨过边界 = 平台已经对用户、供应商或仓配承诺「这单要履约」。取消、退款、售后、核销只读这个状态，不许再认识 ShipmentPlan、门店订货单、采购单、出库单。这些单据只当「怎么跨过来的」凭证。

三、策略只负责怎么跨

维度是订单类型 × 履约方式：零售仓配、零售直发、代采仓配、代采直发。每种只回答：什么时候跨、用什么凭证、生成什么单据。四种触发可以不同，最终都写入同一个订单截单状态。

履约可拆成供应商到仓、仓到店、店到人，允许跳过其中一段。跳过只影响后面单据，不改变已截单后的取消 / 售后规则。

四、对客主状态

不要把「截单」做成对客主状态。后台可留截单前 / 已截单作事实源，客服和用户看见的词是待接单 / 待发货。

待支付 → 待接单 → 待发货 → 待收货 / 待提货 → 交易成功 / 交易失败

主状态含义
待支付未付款
待接单已付款，仍在截单前。可普通取消
待发货已截单且尚未发出。不能普通取消；退款走售后审核
待收货 / 待提货货已发出或已到提货点。零售自提：门店待收货在用户侧仍展示「待发货」，入仓后转「待自提」（既有规则不变）

五、未截单提前发货

正常路径（走截单配置时间）：付款 → 待接单 → 到配置时刻自动截单 → 待发货 → 发货 → 待收货。

例外（不走截单配置时间）：订单仍在截单前却提前发货（上传快递单、回传运单、仓配出库等现有发货动作）。系统在发货当口当场补截单（写入 CUTOFF_COMMITTED），由发货事件触发，不是等到快递截单页或门店订货汇总的配置时刻。订单状态同时完成【接单】和【发货】，对客直接变为待收货，中间不停留待接单、不经过待发货。之后取消 / 退款 / 售后按已截单。此为底层逻辑，无需在页面呈现，不新做发货交互，不新做进度条。

六、和两套截单配置页的关系

快递截单页只配零售 × 直发（快递到家，供应商直发）：每天某个时刻，截上一窗待接单、未填快递单的已付单。到点后写入已截单，对客从待接单变为待发货。本页不生成门店订货单，但不能因此认为这些单没有截单。配置时刻前已提前发货的，走第五条：由发货事件当场补截单并一次完成接单 + 发货，不要等本页配置时刻。

采购 → 门店订货汇总截单配仓配类：跨界时生成门店订货单，同时必须写回同一套订单截单状态，对客同样从待接单变为待发货。

两页可继续分开。本页不要改成四种履约总配置台。本期不改本页字段、交互、文案。

八、开发验收

  1. 是否已截单只看订单统一截单状态。禁止用 shipment_plan_id != null 当事实。
  2. 零售快递直发过了策略时刻，即使没有门店订货单 / 采购单，也必须是已截单，对客为待发货。
  3. 仓配在门店订货汇总截单后，除生成订货单，必须同时把订单写成已截单，对客为待发货。
  4. 未截单提前发货：由发货事件当场补截单，不走配置时刻；同时完成接单 + 发货，对客为待收货。页面不另呈现。
  5. 取消、退款、售后、核销只读统一状态。
  6. B / C 主状态名称一致：待支付、待接单、待发货、待收货 / 待提货。
  7. 用户 APP 订单流有待接单状态（全部列表 + 详情标题），无独立页签、无「我的」入口、无进度条。
  8. 快递截单页范围本期仍是零售快递直发。

九、本期不做

1. 不改快递截单页原型。
2. 不在本页展开代采、仓配策略配置。
3. 不把「零售 / 代采定义」写进本页需求。
4. 不把「截单」做成对客主状态。
5. 用户 APP 不补进度条；不改取消 / 退款页、支付成功跳转等其它交互。
6. 门店核销详情不改。
7. 用户 APP「配送方式」是生产已有能力，不写进本期验收。
8. 订单支付流水是另一份需求，不塞进本文。
9. 未截单提前发货的补截单 / 接单 / 发货是底层一次完成，不在页面呈现过程。
