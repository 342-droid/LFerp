一、背景与目标

1.1 背景

v1.1 时，快递截单页只配零售 × 快递到家（每日时刻、直播/商城、类目优先）。仓配另一套在「采购 → 门店订货汇总」：到点或人工截单，按门店生成门店订货单（MDH）。

生产和售后容易把「有没有 MDH / shipment_plan_id」当成「有没有截单」。仓配碰巧对；零售直发不进仓储、不走采购、不生成 MDH，那样猜会永远像没截单，取消和退款会错。

v1.2 把配置入口收口：

  1. 菜单与页面从「快递截单」改为「订单截单」，统一配零售 / 代采；
  2. 履约随渠道：零售仅快递到家、门店自提；代采仅平台配送、快递配送；
  3. 截单方式除每日定时外，增加支付后自动截单；
  4. 门店订货汇总的自动截单并入本页，汇总页只留人工「截单并生成门店订货单」；
  5. 系统两条兜底：零售 × 快递到家（默认每日定时）；以及代采平台配送 / 代采快递配送 / 零售门店自提且标签为不走订货单时支付后自动截单。不做全部渠道×全部履约的通用兜底。

统一截单事实源、待接单、提前发货补截单等底层口径沿用 v1.1。

1.2 目标

  • 运营在一页配齐零售 / 代采的自动截单（到点或支付后）。
  • 订单上有唯一截单事实源；取消 / 退款 / 售后 / 核销只读它。
  • N1-pay（支付后截单）、N2（每日到点）、N3（订货汇总人工截单）都回写订单：已截单 + 对客待发货。
  • 未截单提前发货（N5）：不走配置时刻，底层一次完成接单 + 发货，对客待收货。
  • 后台与 C 端主状态名称一致。

1.3 发布逻辑

订单截单配置页先落地 → 订单域按新维度匹配并回写 → 订货汇总自动截单下线、只留人工 → 对客露出待接单（支付后截单的单跳过待接单）→ 售后/取消改读统一状态。

1.4 范围与优先级

优先级内容
P0订单截单页按渠道 + 履约 + 标签 + 类目配置；支付后自动截单；兜底仅零售快递到家；回写统一截单状态；待接单；提前发货补截单
P0订货汇总自动截单并入本页；人工截单后到点策略不再重复执行
本期不做选品库商品标签管理；C 端进度条；核销详情改版；全渠道通用兜底

二、用户与角色

角色诉求
平台运营在订单截单页配零售 / 代采策略；到点或支付后自动截；订货汇总只做人工截单
用户 / 门店进货人已付未截单看「待接单」可取消；截单后看「待发货」；发出后看「待收货」；支付后自动截单的单不停留待接单
履约 / 仓配直发按本页时刻或支付后备货发快递；仓配按 MDH 履约
售后 / 核销只看订单截单状态，不再猜订货单
研发 / 测试策略规则、匹配窗口、回写节点可对照验收

三、术语与概念

术语产品定义
截单平台对外承诺「这单要履约」。跨过即不能再当没承诺过
订单截单状态订单上的统一事实源。取值：截单前 / 已截单。已截单不可释放
对客主状态用户和后台订单列表看到的词：待支付、待接单、待发货、待收货 / 待提货
待接单已付款且仍在截单前。不要写成「待商家接单」
待发货已截单且尚未发出
订单截单策略本页一条配置：名称 + 订单渠道 +（零售）适用场景 + 履约方式 + 截单方式 +（定时则）每日时刻 + 商品标签范围 + 商品类目范围 + 状态
订单渠道零售、代采，可多选。渠道决定可选履约，也决定是否出现适用场景
适用场景仅零售：直播、商城，可多选。代采不区分场景。匹配时按订单实际场景分开算
履约方式零售：快递到家、门店自提。代采：平台配送、快递配送。可「全部」或「指定」
截单方式每日定时 / 支付后自动截单
支付后自动截单支付成功即写入已截单，对客直接待发货，不再停留待接单。只决定何时截，不决定是否进订货汇总
兜底策略系统默认一条：零售 × 快递到家 × 直播+商城 × 全部标签 × 全部类目。仅可改名称、截单方式、截单时间、备注；不可停用、删除
商品标签范围全部标签，或指定商品标签（可多选）。匹配字段，标签怎么维护不在本文
商品类目范围全部类目，或指定选品库类目（可多选）
截单窗口每日定时策略在时刻 T 触发时，截「上次该时刻 ～ 本次 T 的前一秒」内、命中该策略且仍待接单、未发货的订单
截单来源支付后自动截单 / 每日定时 / 订货汇总人工截单 / 提前发货补截单
门店订货单 MDH仓配人工截单后按门店合并的凭证。只证明「怎么跨」，不能当「是否已截单」
提前发货补截单仍在截单前却已发货：由发货事件当场写入已截单，不走任何配置时刻

截单状态 vs 对客主状态（二维）

  • 截单状态：有没有对外承诺。取消 / 售后只认这个。
  • 对客主状态：货到哪一步。用户看见的是这个。
  • 已截单 ≠ 已发货。已截单未发出 = 待发货；已发出 = 待收货。

两套配置入口

入口配什么不配什么
订单 → 订单截单零售 / 代采的自动截单（到点或支付后）人工生成 MDH
采购 → 门店订货汇总人工「截单并生成门店订货单」自动截单时刻（已并入订单截单）

四、业务底层逻辑（含原型确认口径）

本章为现行产品口径（订单截单页与订货汇总原型 + 订单回写）。
「补截单 / 接单 / 发货」一次落库属于底层实现，不在页面呈现过程。

4.1 统一截单边界（事实源）

订单必须自带截单状态，禁止各模块自己猜单据。

截单状态编码含义取消 / 退款
截单前PRE_CUTOFF还没对外承诺履约可普通取消
已截单CUTOFF_COMMITTED已对外承诺要履约不能普通取消；退款走售后审核

已截单不可释放。 一旦写成已截单，不能回退到截单前，没有「释放 / 反截」动作，也不做 N6 页面或接口。售后、关单走既有取消/退款规则，不靠把截单状态打回去。

取消、退款、售后、核销只读这个状态。

不许再用 ShipmentPlan、门店订货单、采购单、出库单判断「是否已截单」。

这些单据只当凭证，记在「截单来源 / 截单凭证」里。

零售快递到家过了本页时刻、没有 MDH，也必须是已截单。

仓配生成了 MDH，必须同时把订单写成已截单；有 MDH 只是凭证，不是判断条件。

4.2 策略负责「怎么跨」：渠道 × 履约

维度是 订单渠道 × 履约方式。渠道先定，履约再定；不是「零售 / 代采」二选一就结束。

订单渠道可选履约适用场景
零售快递到家、门店自提直播、商城（可多选，匹配时分开算）
代采平台配送、快递配送不区分
履约组合谁负责自动跨界跨界后典型凭证 / 单据
零售 × 快递到家订单截单（系统兜底 + 指定策略）预计接单时间 / 截单批次；不生成 MDH
零售 × 门店自提订单截单指定策略；无策略则只能人工或提前发货仓配类可生成 MDH
代采 × 平台配送订单截单指定策略；无策略则只能人工或提前发货生成 MDH，回写各 CO
代采 × 快递配送同上生成 MDH，回写各 CO
任意履约 · 订货汇总人工截单采购侧人工按钮生成 MDH，回写各 CO
任意履约 · 未截单提前发货发货事件当场补截单运单号 / 出库单；不走配置时刻

不做全渠道通用兜底。 代采、门店自提没有系统默认策略，必须单独配，或走订货汇总人工截单。

履约可拆成供应商到仓、仓到店、店到人，允许跳过（零售直发不进仓、不到店）。跳过只影响后面单据，不改变已截单后的取消 / 售后规则。

4.3 对客主状态（B / C 必须同名）

不要把「截单」做成对客主状态。后台可留截单前 / 已截单作事实源。

待支付 → 待接单 → 待发货 → 待收货 / 待提货 → 交易成功 / 交易失败

支付后自动截单：

待支付 → 待发货 → 待收货 / 待提货 → 交易成功 / 交易失败
（跳过待接单）
主状态对应截单状态含义
待支付—未付款
待接单截单前已付，尚未对外承诺。可普通取消
待发货已截单已承诺、尚未发出。不能普通取消
待收货 / 待提货已截单货已发出或已到提货点

零售自提既有规则不变：门店待收货在用户侧仍展示「待发货」，门店收货入仓后转「待自提」。

直播、商城都属于零售订单，列表 / 筛选 / 导出 / 详情同一套，不单开规则。

一订单中任一商品截单，整单视为已接单（对客待发货），见 §4.4.6。不按商品行拆主状态。

4.4 订单截单：作用范围、匹配、窗口

本页作用于全平台零售线与代采线。

人工生成 MDH 仍在「采购 → 门店订货汇总」，自动截单不在那边配。

4.4.1 一条策略包含什么

字段必填说明
策略名称是后台识别用
订单渠道是零售、代采，至少选一个，可同时勾选
适用场景勾了零售则必填直播、商城，至少选一个。只勾代采时不出现、不校验
履约方式是全部履约方式，或指定（选项随已选渠道变化；指定时至少 1 个）
截单方式是每日定时 / 支付后自动截单
截单时间每日定时必填每日时刻，精确到秒；默认示例 10:00:00。支付后自动截单不填
商品标签是全部标签，或指定商品标签（指定时至少选 1 个）
商品类目是全部类目，或指定选品库类目（指定时至少选 1 个）
备注否仅后台查看，不给用户看
状态系统写草稿 / 启用 / 停用
是否兜底系统写仅一条：零售 × 快递到家 × 直播+商城 × 全部标签 × 全部类目

4.4.2 一单会不会进本页自动截单

必须同时满足：

  1. 订单渠道命中策略（零售或代采）；
  2. 零售单还要命中适用场景（直播或商城）；代采单不看场景；
  3. 履约命中策略（全部履约，或指定履约包含该单履约）；
  4. 商品标签、类目按 §4.4.5 命中；
  5. 已支付；
  6. 截单状态仍是截单前（每日定时还要求对客 = 待接单）；
  7. 尚未发货（未填运单、未出库）。

不进本页自动任务：

  • 未支付、已关闭、已完成；
  • 已经是已截单（待发货或之后），含支付后已截、人工已截、提前发货已补截；
  • 已发货：按发货后规则，走 §4.8 / N5，不受本页时刻影响；
  • 草稿、停用策略。

对客主状态改为「待接单」后，每日定时窗口里的单应认待接单 + 未发货。不要再截已经待发货的单。

4.4.3 每日定时：截单窗口

启用中的「每日定时」策略，每天在配置的时刻 T 触发一次。

本次截单覆盖：上次该策略同一时刻 T  ～  本次 T 的前一秒
例：今天 10:00:00 截  昨天 10:00:00 至 今天 09:59:59  的订单
（按支付成功时间落入该闭开区间；若无支付时间则按下单时间，生产实现时写死一种并在联调确认）

只截命中本条策略且仍在 §4.4.2 池内的单。

到点后回写见 N2：已截单 + 对客待发货。零售快递到家不生成 MDH；仓配类是否生成 MDH 仍跟采购作业走，不改变订单已截单。

草稿、停用策略不触发。

订货汇总已人工截单的订单，到点策略不再重复执行。

4.4.4 支付后自动截单

启用中的「支付后自动截单」策略，不跑每日窗口。

支付成功当口：

  1. 订单行按 §4.4.5 匹配；任一商品行命中本策略 → 整单已截单（§4.4.6）；
  2. 对客主状态：待支付 → 待发货，跳过待接单；
  3. 来源 = 支付后自动截单；
  4. 之后取消 / 退款按已截单；
  5. 该单不再进入任何每日定时窗口。

仓配类仍可按原作业生成门店订货单，那是履约凭证，不是再截一次。

支付后自动截单只决定何时截单，不决定该单是否进入采购「门店订货汇总」。 两件事独立，进汇总规则不在本页、也不在本文（选品库商品标签另文）。

4.4.5 匹配优先级

订单行各自找策略，订单截单状态只有一份（见 §4.4.6）：

  1. 先按订单渠道过滤启用策略；零售再按场景（直播或商城）过滤。
  2. 履约：指定履约优先于「全部履约方式」。
  3. 标签：指定标签优先于「全部标签」，全部标签优先于「不限标签」。没有标签的商品只走「不限标签」。
  4. 类目：指定类目优先于「全部类目」。
  5. 零售快递到家、未单独配标签/类目的，走兜底策略「零售快递到家」。
  6. 代采平台配送、代采快递配送、零售门店自提中，商品标签为「不走订货单」的，走兜底策略「不走订货单」（默认支付后自动截单，可改每日定时）。未打该标签且未单独配置的，本页不自动截，可走订货汇总人工截单或 N5。

页顶与抽屉原文：同一履约下指定标签优先于全部标签，指定类目优先于全部类目。

一单多商品、多条策略时刻不同时：以最先触发截单的那一行为准，整单接单，不按行各出一套对客状态。

4.4.6 任一商品截单，整单视为已接单（冻结）

截单状态、对客主状态都在订单头，不按商品行拆「待接单 / 待发货」。

规则：一订单中任一商品被截单，该订单即视为已接单。

结果：

  1. 订单截单状态写成已截单；
  2. 对客主状态变为待发货（若同时已发货则走 N5 到待收货；支付后截单则从待支付直接到待发货）；
  3. 取消 / 退款按已截单，整单不再当截单前；
  4. 其余尚未到自己策略时刻的商品，不再单独等自己的截单时刻再改订单状态。履约可继续按行发货，但订单已经是已接单。

适用入口（同一条）：

  • 支付后自动截单：任一商品行命中该方式策略（N1-pay）；
  • 每日定时：任一商品行命中启用策略且落入窗口（N2）；
  • 门店订货汇总人工：任一商品行进入本次截单并进 MDH（N3）；
  • 提前发货：任一商品行先发出（N5），整单已接单且待收货。

例：一单有蔬菜（指定策略 08:00）和粮油（只走兜底 10:00）。今天 08:00 蔬菜行被截 → 整单立刻已截单、对客待发货，取消隐藏。10:00 兜底任务不得把该单再截一遍，也不得拆回「一半待接单」。

4.5 兜底策略与策略生命周期

兜底策略（系统默认两条，均不可停用 / 删除）

1）零售快递到家

  • 范围锁死：零售、直播 + 商城、指定履约 = 快递到家、不限标签、全部类目、状态永远启用。
  • 名称默认「零售快递到家」（历史「通用截单策略」「零售快递到家兜底」加载时改成此名）。
  • 仅支持修改：名称、截单方式、截单时间、备注。
  • 不支持改渠道、场景、履约、标签范围、类目范围、停用、删除。
  • 若不存在，系统补一条（时刻默认 10:00:00，方式默认每日定时）。

2）不走订货单

  • 范围锁死：零售 + 代采；零售场景直播 + 商城；指定履约 = 门店自提、平台配送、快递配送；指定标签 =「不走订货单」；全部类目；截单方式锁死支付后自动截单；状态永远启用。
  • 名称默认「不走订货单」（历史「不走订货单支付即截」加载时改成此名）。
  • 截单方式默认支付后自动截单，可改为每日定时。
  • 仅支持修改：名称、截单方式、截单时间、备注。
  • 不支持改渠道、场景、履约、标签、类目、停用、删除。
  • 若不存在，系统补一条。此类商品不进门店订货汇总，必须靠本策略在支付后截单。
  • 列表名称旁打橙色「兜底」标（不再叫「通用」）。
  • 不做「零售+代采 × 全部履约」的全渠道通用兜底。

4.6 策略重叠（保存时拦截）

先看渠道是否相交；仅零售相交时再看场景是否相交。渠道、场景都对上之后，履约、标签、类目三组同时冲突才拦截：

冲突提示口径（原型）
两条都是「全部标签 + 全部类目」（且履约也冲突）{渠道}（{场景}）{履约}已有「全部标签、全部类目」策略「{名称}」
两条指定标签出现同一个标签{渠道}（{场景}）{履约}标签「{标签}」已在策略「{名称}」中配置
两条指定类目出现同一个类目{渠道}（{场景}）{履约}类目「{类目}」已在策略「{名称}」中配置

指定与全部允许同时存在（靠 §4.4.5 优先级，不是互斥）：指定履约 vs 全部履约、指定标签 vs 全部标签、指定类目 vs 全部类目。

无渠道重叠，或零售无场景重叠，不算冲突。

兜底占掉「零售 × 快递到家 × 直播+商城 × 全部标签 × 全部类目」，因此不能再新增第二条同样范围。

校验时机：新增 / 修改保存。启用不重新做重叠（保存时已拦）。

4.7 截单后对客规则（各策略统一）

抽屉「截单后」只读说明，各策略相同，运营不能改：

  1. 用户 APP「取消订单」隐藏；
  2. 「申请退款」截断免审直退，改为售后审核流。

产品语义：相当于把发货后的售后方式提前到截单时刻。

后台订单：待接单可取消；已截单的待发货按原规则不再普通取消。

4.8 已发货：不受本页时刻影响

已经填写快递单 / 已经出库的订单，按发货后规则，不进本页每日窗口。

若发货发生在截单前（待接单就发了）：走 N5——发货事件当场补截单，同时完成接单 + 发货，对客待收货。不走本页配置时刻。

4.9 门店订货汇总截单

入口：采购 → 门店订货汇总。

动作说明
截单并生成门店订货单人工：按门店合并当前汇总池，生成 MDH
自动截单配置已下线到本页：按钮跳转「订单 → 订单截单」。本页不再配定时器

跨界后：

  1. 生成 MDH（一张可含多 CO）；
  2. 必须回写本批每个 CO：截单状态 = 已截单，对客 = 待发货，凭证 = MDH 单号，来源 = 订货汇总人工截单；
  3. 后续采购单 / 出库单按原仓配链，不再当截单事实；
  4. 已人工截单的订单，订单截单页的每日定时不再重复执行。

未截单却提前出库 / 发货：同样 N5，不走本页定时。

4.10 正常路径 vs 提前发货

正常 · 每日定时

付款 → 待接单（截单前）
    → N2 每日到点 或 N3 订货汇总人工截单
    → 已截单 + 待发货
    → 发货 N4
    → 待收货

配置时刻只处理到点仍未发的待接单。

正常 · 支付后自动截单

付款 → 已截单 + 待发货（跳过待接单）
    → 发货 N4
    → 待收货

例外：未截单提前发货（不走配置时刻）

仍是截单前，履约侧已发货（上传快递单、回传运单、仓配出库等现有动作）。

发货当口底层一次做完：

  1. 补截单 → 已截单（来源 = 提前发货补截单）；
  2. 同时完成【接单】+【发货】；
  3. 对客直接 待收货（自提按既有规则）。

不停留待接单，不经过待发货。之后取消 / 售后按已截单。

页面只看到待收货，不展示过程。

5.3 节点总表

节点触发适用截单状态对客主状态附带走配置时刻页面呈现过程
N1 支付成功（普通）收款成功未命中支付后策略保持截单前待支付 → 待接单—否只出待接单
N1-pay 支付后自动截单收款成功且命中该方式策略启用策略覆盖的渠道 / 履约 / 标签 / 类目；任一商品行命中→ 已截单（整单）待支付 → 待发货（跳过待接单）来源=支付后自动截单；不再进每日窗口否订单只出待发货
N2 每日定时到点启用策略每日 T待接单、未发货；任一商品行命中策略且落入窗口→ 已截单（整单）待接单 → 待发货（已接单）来源=每日定时；直发不生成 MDH是（本页）订单只出待发货
N3 订货汇总人工截单人工「截单并生成门店订货单」进汇总池且仍待接单；任一商品行进本批 MDH 即整单本批每个 CO → 已截单（整单）待接单 → 待发货（已接单）生成 MDH 并回写 CO；之后 N2 不再重复否（人工）汇总页保持该按钮
N4 已截单后发货现有发货动作已是已截单不改待发货 → 待收货物流/出库凭证否沿用现有入口
N5 未截单提前发货现有发货动作，当时仍截单前任意履约→ 已截单待接单 → 待收货（一次接单+发货，跳过待发货）来源=提前发货补截单否不呈现过程
N6 截单释放——不发生—已截单无法释放，本节点不做—无入口、无接口

互斥

  • 已是已截单，N1-pay / N2 / N3 再跑到不得重复写成第二次截单事实。
  • N1-pay 之后，每日定时不得再截。
  • 订货汇总已人工截单，每日定时不得再截。
  • N5 之后，配置任务不得再截，不得把待收货打回待发货。
  • N4 与 N5 对客都是待收货：N4 经过待发货；N5 从未进入待发货。
  • 任一商品截单即整单已接单；禁止同一订单部分行待接单、部分行待发货。
  • 已截单不可释放，不能打回待接单 / 截单前。

支付后灰字：支付成功即写入已截单，对客直接进入「待发货」，不再停留待接单。仓配类仍会生成门店订货单。

截单时间下灰字（随填写变化）：

每次截单覆盖「上次该时刻 ～ 本次前一秒」。例：今天 {T} 截昨天 {T} 至今天 {T-1s} 的订单。

指定标签 / 指定类目：出现已选列表，每行可删；+ 添加 打开多选弹窗（名称筛选，确定回写）。标签、类目选项来自既有主数据，无数据则空态提示。标签如何在选品库维护，不在本抽屉展开。

标签下灰字：同一履约下指定标签优先于「全部标签」。

类目下灰字：同一履约下指定类目优先于「全部类目」。未单独配置的走该履约的兜底策略。

6.2.3 截单后（只读，各策略相同）

  • 用户 APP「取消订单」隐藏
  • 「申请退款」截断免审直退，改为售后审核流

灰字：各策略统一，相当于把发货后的售后方式提前到截单时刻。已发货订单按发货后规则，不受本页时刻影响。
